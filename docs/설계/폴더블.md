## 3. 브레이크포인트

| 이름 | 조건 | 배치 | 해당 기기 |
|------|------|------|----------|
| phone | `<600px` | 지금 모바일 그대로 + **날짜 상세 바텀 시트**(5) | 폰, 폴드 커버, 아이폰 듀오 커버 |
| fold (신설) | `600px ≤ w < 1024px` | **레일 + 2단** (4) | 폴드 펼침 세로, 폴드8 펼침, 아이폰 듀오 펼침(가로, 세로) |
| pc | `≥1024px` | 지금 PC 그대로 | PC, 폴드 펼침 가로, 트라이폴드 |

- 600 은 Material의 compact/medium 경계와 같고, 커버 화면(최대 약 475)과 펼친 화면(최소 약 616)을 확실히 가른다
- 높이 보조 조건 `short` = `(max-height: 720px)`: fold 구간에서 D-day 타일을 빼고 월 숫자를 줄인다 (아이폰 듀오 가로 626, Safari 주소창 포함 시 약 550)
- Tailwind 4: `globals.css` `@theme` 에 `--breakpoint-fold: 600px` 추가 (`fold:` 변형). `short:` 는 `@custom-variant short (@media (max-height: 720px))`
- JS 판단은 `useIsDesktop` 을 `useLayout(): "phone" | "fold" | "pc"` 로 바꾼다 (matchMedia 두 개). 상세를 시트로 열지 칸에 넣을지 고르는 곳이 모두 이것을 본다

## 4. fold 구간 배치 (600~1023)

시안: `fold-proposal-duo-cal-light.png`, `-dark.png` (890×626), `fold-proposal-fold-cal-light.png`, `-dark.png` (984×1092)

### 4-1 공통 뼈대: 레일
- 왼쪽 레일 76px: 심볼, 코랄 + 버튼(48px, 지금 떠 있는 + 와 같은 동작), 달력 / 빈 시간 / 기념일 / 새 소식(배지) / 팀, 맨 아래 내 프로필
- 선택 항목은 아이콘 뒤에 `--tile` 알약 (52×32). 아이콘 20px, 글자 10.5px 700 (떠 있는 탭과 같은 크기)
- 떠 있는 탭과 + 버튼은 숨긴다 (P2, P4 해결). 본문 하단 여백도 탭 높이만큼 두지 않는다
- 상단 줄: 팀 이름 알약(팀 전환 시트 그대로) + 화면 제목 또는 월 표시. 새 소식 알약과 프로필은 레일로 옮겼으니 상단에서 뺀다
- PC 사이드바는 ≥1024 에서 그대로. 1024~1199 에서도 레일을 쓸지는 열린 질문 Q4 (P6)

### 4-2 달력
- 상단 줄: 팀 알약, 월 숫자 44px(`.82` 행간) + "월 2026", 오른쪽 오늘 / ◀ ▶
- 2단: 왼쪽 달력 타일(남는 폭 전부, 6주 그리드가 높이를 채움) | 오른쪽 칸 300px (폭 ≥ 960 이면 340px)
- 오른쪽 칸은 **개요**: 오늘 비는 시간 타일, 다가오는 일정 3~5건, 이번 주 빈 시간 2~3줄. 선택 날짜 내용은 칸에 두지 않고 날짜 팝오버(5장)로 보여 준다 (권장안 A, 5-1)
- `short` 가 아니고 높이가 남으면(폴드 세로) D-day 타일을 개요 맨 위에 둔다
- 날짜 칸 모양: 칸 높이 < 110px 이면 모바일처럼 막대 + 9px 제목, ≥ 110px(폴드 세로) 이면 PC 처럼 제목 칩. 칸 높이는 그리드가 정하므로 `@container` 쿼리로 고른다
- 시안: `fold-proposal-wide-day-light.png`, `-dark.png` (권장안 A). `fold-proposal-duo-cal-*.png`, `fold-proposal-fold-cal-*.png`, `fold-proposal-duo-detail-*.png` 는 대안 B(팝오버 없이 오른쪽 칸이 선택 날짜와 상세를 보여 줌)

### 4-3 빈 시간 찾기
- 2단 같은 폭: 왼쪽 조건 카드(위에 붙음), 오른쪽 결과 목록(칸 안에서 스크롤). 시안 `fold-proposal-duo-free-light.png` (P5)

### 4-4 일정 작성/수정
- 2단: 왼쪽 제목 + 메모, 오른쪽 종일 / 시작 / 종료 + 저장. 저장 버튼이 첫 화면에 보인다. 시안 `fold-proposal-duo-form-light.png` (P4)
- 날짜/시각 피커: PC 처럼 입력 아래 팝오버 (`PickerShell` 조건을 `pc` 에서 `fold | pc` 로)

### 4-5 기념일, 새 소식, 팀 설정, 내 정보
- 레일만 적용하고 본문은 가운데 640px 1단. 2단으로 나눌 내용이 없다

## 5. 날짜 탭 = 그날 상세 먼저 (모든 폭)

사용자 요청: 달력에서 **어떤 날짜든**(빈 날 포함, PC와 펼친 화면 포함) 누르면 바로 빠른 추가로 가지 않고 먼저 그날의 상세를 띄운다. 상세에는 그날 일정, 기념일, 비는 시간 힌트, "이 날 일정 추가" 가 있고, 추가를 누르면 **같은 자리에서** 빠른 추가 폼으로 바뀐다. 일정을 누르면 같은 자리에서 일정 상세로.

### 5-1 폭별 표면과 오른쪽 칸 처리
| 배치 | 날짜 탭 | 표면 | 오른쪽 칸 |
|------|--------|------|----------|
| phone (<600, 커버 포함) | 날짜 상세 | **바텀 시트** (반 높이, 끌어 올리면 전체) | 없음. 달력 아래 날짜 목록도 없앤다 |
| fold (600~1023) | 날짜 상세 | **날짜 칸 옆 팝오버** 340px (#46 빠른 추가 팝오버 자리 규칙과 모양 재사용) | 개요 (다가오는 일정, 이번 주 빈 시간) |
| pc (≥1024) | 날짜 상세 | 같은 팝오버 | 개요 |

**권장안 A: 오른쪽 칸은 개요로 바꾸고 날짜 내용은 팝오버에만 둔다.**
- 이유 1: 칸과 팝오버가 같은 날짜 목록을 동시에 보여 주면 중복이고, 어느 쪽을 봐야 하는지 흐려진다
- 이유 2: 탭하면 바로 그 자리에 뜨는 표면이 모든 폭에서 같아진다 (폰 시트 = 넓은 화면 팝오버, 내용과 순서 동일). 구현도 `DayPanel` 한 컴포넌트를 시트와 팝오버에 꽂으면 된다
- 이유 3: 칸이 날짜에 묶이지 않으면 "다가오는 일정" 처럼 달력에서 안 보이는 정보를 줄 수 있다
- 대안 B (팝오버 없이 칸만): 모달이 없어 가볍지만, 사용자가 원한 "누르면 그날 상세가 뜬다" 와 폰과의 일관성을 잃는다. B 를 고르면 시안 `fold-proposal-duo-cal-*.png` 그대로

### 5-2 상세 내용과 상태 (시트, 팝오버 공통 `DayPanel`)
| 상태 | 내용 | 시안 |
|------|------|------|
| 일정 있는 날 | 머리 "10일 화요일" + 오늘 배지 + 닫기, 기념일 줄(옅은 코랄 `--hl-tile`, 하트 선 아이콘, "오늘" 또는 "D-3"), 일정 행(멤버 색 + 제목 + 시간 + 등록자), 비는 시간 힌트 한 줄, 하단 주 버튼 "이 날 일정 추가"(`--btn`, 52px) | phone `fold-proposal-phone-sheet-light.png` `-dark.png`, 넓은 화면 `fold-proposal-wide-day-light.png` `-dark.png`, PC `fold-proposal-pc-day-light.png` |
| 빈 날 | 머리, 비는 시간 힌트, 가운데 빈 상태(코랄 원 + 달력 선 아이콘, "아직 일정이 없어요", "이 날 함께할 일을 바로 적어 보세요"), 같은 주 버튼 | `fold-proposal-phone-empty-light.png` `-dark.png`, `fold-proposal-wide-empty-light.png` |
| 빠른 추가 | 같은 표면이 바뀐다: 머리 "← 12일 목요일에 추가", 제목 입력(자동 포커스), 종일 토글, 시작 → 종료, "자세히" + "저장". 뒤로 화살표는 날짜 상세로. 필드와 저장 동작은 #46 `QuickAdd` 그대로 | `fold-proposal-phone-add-light.png` `-dark.png`, `fold-proposal-wide-add-light.png` |
| 일정 상세 | 일정 행을 누르면 같은 표면이 일정 상세(지금 상세와 같은 내용: 등록자, 제목, 시간, 수정/복제/삭제)로 바뀐다. 뒤로 화살표는 날짜 상세로 | 내용은 `fold-proposal-duo-detail-*.png` 와 같고 표면만 시트/팝오버 |

- 비는 시간 힌트: 팀 멤버가 2명 이상일 때만. 그날 하루 `free-slots`(09:00~23:00, 최소 1시간) 1회 호출, 300ms 지연 없이 열 때 시작, 오는 동안 한 줄 스켈레톤, 실패하면 줄을 숨긴다(오류 문구 없음). 오늘은 달력 위 타일이 이미 가진 값을 재사용
- 일정 칩(PC, 폴드 세로)을 누르면 팝오버가 일정 상세 상태로 바로 열린다 (뒤로 = 그날 상세). 지금처럼 오른쪽 칸에 상세를 띄우지 않는다
- + 버튼(떠 있는 + / 레일 + / PC "일정 추가")은 지금처럼 새 일정 폼으로 바로 간다 (날짜 상세를 거치지 않음)

### 5-3 바텀 시트 (phone)
| 항목 | 내용 |
|------|------|
| 높이 | 처음 화면의 약 56~60% (반), 손잡이를 위로 끌면 전체(위 여백 = safe-area + 12px), 아래로 끌거나 배경 탭하면 닫힘. 내용이 넘치면 시트 안 스크롤. 빠른 추가 상태에서 키보드가 올라오면 `visualViewport` 높이에 맞춰 주 버튼이 키보드 위에 남는다 |
| 모양 | 위 모서리 30px, `--tile`, 배경 `rgba(0,0,0,.35)`, 손잡이 40×5 `--faint`. 상태 전환은 내용만 120ms 교차 페이드, 시트 높이 변화 200ms (`prefers-reduced-motion` 이면 즉시) |
| 접근성 | `role=dialog` `aria-modal` + 제목 연결, 열면 제목에(빠른 추가는 입력에) 포커스, Tab 은 시트 안에서 돈다, Esc 닫기, 닫으면 누른 날짜 칸으로 포커스 복귀. 끌기 대신 손잡이 버튼(`aria-expanded`)으로도 전체/반 전환 |

### 5-4 팝오버 (fold, pc)
- 위치: #46 `QuickAddPopover` 규칙 그대로. 날짜 칸 오른쪽 8px, 자리가 없으면 왼쪽, 위아래는 화면 안으로 밀어 넣음. 폭 340px, 모서리 26px, `--line` 테두리 + `--pop-shadow`. 누른 날짜 칸에 `--pri` 2px 테두리
- 배경을 어둡게 하지 않는다(비모달처럼 보이되 포커스는 가둠). 바깥 클릭, Esc 로 닫고 날짜 칸으로 포커스 복귀. 다른 날짜 칸을 누르면 닫고 그 날짜로 다시 연다
- 상태 전환(날짜 → 빠른 추가, 날짜 → 일정 상세)은 팝오버 안에서. 높이가 바뀌면 위치를 다시 계산
- 폭이 바뀌어(접기) phone 이 되면 같은 상태를 바텀 시트로 옮긴다

### 5-5 뒤로가기와 주소 (#81 과의 관계)
- 지금: 선택 날짜는 `?date=`(오늘이면 생략), 보던 달은 `?month=` 를 `history.replaceState` 로 남긴다 (#81). 이 규칙은 그대로 둔다
- 시트나 팝오버를 열 때 **`history.pushState`** 로 `?date=YYYY-MM-DD&day=1` 한 칸을 쌓는다. 안에서 일정 상세로 가면 `&event=<id>`, 빠른 추가로 가면 `&add=1` 을 한 칸 더 쌓는다
- `popstate` 에서 주소의 `day`, `event`, `add` 로 표면 상태를 맞춘다. 안드로이드 뒤로 버튼과 iOS 뒤로 쓸기 = 빠른 추가/일정 상세 → 날짜 상세 → 닫힘 순서
- 닫기 버튼, 배경 탭, 아래로 끌기, 바깥 클릭, Esc 는 쌓은 칸 수만큼 `history.go(-n)` 으로 닫는다 (앞으로가기에 유령 상태가 남지 않게). 쌓은 칸이 없을 때(새로고침으로 `day=1` 주소에 바로 들어온 경우)는 `replaceState` 로 `day` 등을 뗀다
- 빠른 추가 저장 성공: 표면을 닫고(위와 같은 방식) 토스트 + 그 날짜 선택 (#46 동작 유지)
- 빠른 추가에 입력이 있는데 뒤로가기: 입력은 버리고 날짜 상세로 (확인 창 없음, 짧은 폼이라 "자세히" 로 넘긴 값만 유지)
- 새로고침이나 공유 주소의 `day=1` 은 모든 폭에서 상세를 다시 연다. `add=1` 은 새로고침 시 무시(빈 폼을 띄우지 않음)
- `pushState` 도 #57 과 같은 이유로 state 는 `null` 로 넘긴다 (AppShell + 버튼의 기준 날짜 동기화)

## 6. 힌지 (Viewport Segments)

- Chrome 138 부터 `@media (horizontal-viewport-segments: 2)` 와 `env(viewport-segment-left 1 0)` 등을 지원한다 ([Chrome 블로그](https://developer.chrome.com/blog/viewport-segments-api-shipped), [MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/horizontal-viewport-segments))
- **Safari 와 iOS Safari 는 미지원**이고 WebKit 입장도 없다 ([web-features](https://web-platform-dx.github.io/web-features-explorer/features/viewport-segments), [WebKit standards-positions #327](https://www.github.com/WebKit/standards-positions/issues/327)). 아이폰 듀오에서는 쓸 수 없다. 삼성 인터넷 지원 여부는 문서로 확인하지 못했다
- 폴드와 아이폰 듀오는 펼친 화면이 한 장이고 주름만 있다. 평평하게 펼치면 세그먼트가 1개로 잡힌다
- 결정: **힌지를 피하는 배치를 기본으로 만들지 않는다.** 펼친 화면은 거의 정사각형 한 장으로 본다. 반만 접은(책 자세) 경우만 후속 개선 후보로 남긴다: `horizontal-viewport-segments: 2` 이면 2단 경계를 `env(viewport-segment-right 0 0)` 에 맞춘다
