## 3. 브레이크포인트

| 이름 | 조건 | 배치 | 해당 기기 |
|------|------|------|----------|
| phone | `<600px` | 지금 모바일 그대로 + **날짜 바텀 시트**(5) | 폰, 폴드 커버, 아이폰 듀오 커버 |
| fold (신설) | `600px ≤ w < 1024px` | **레일 + 2단** (4) | 폴드 펼침 세로, 폴드8 펼침, 아이폰 듀오 펼침(가로, 세로) |
| pc | `≥1024px` | 지금 PC 그대로 | PC, 폴드 펼침 가로, 트라이폴드 |

- 600 은 Material의 compact/medium 경계와 같고, 커버 화면(최대 약 475)과 펼친 화면(최소 약 616)을 확실히 가른다
- 높이 보조 조건 `short` = `(max-height: 720px)`: fold 구간에서 D-day 타일을 빼고 월 숫자를 줄인다 (아이폰 듀오 가로 626, Safari 주소창 포함 시 약 550)
- Tailwind 4: `globals.css` `@theme` 에 `--breakpoint-fold: 600px` 추가 (`fold:` 변형). `short:` 는 `@custom-variant short (@media (max-height: 720px))`
- JS 판단은 `useIsDesktop` 을 `useLayout(): "phone" | "fold" | "pc"` 로 바꾼다 (matchMedia 두 개). 상세를 시트로 열지 칸에 넣을지 고르는 곳이 모두 이것을 본다

## 4. fold 구간 배치 (600~1023)

시안: `fold-proposal-duo-cal-light.png`, `-dark.png` (890×626), `fold-proposal-fold-cal-light.png`, `-dark.png` (984×1092)

### 4-1 공통 뼈대: 레일
- 왼쪽 레일 76px: 심볼, 코랄 + 버튼(48px, 지금 떠 있는 + 와 같은 동작), 달력 / 빈 시간 / 기념일 / 새 소식(배지) / 팀, 맨 아래 내 프로필
- 선택 항목은 아이콘 뒤에 `--tile` 알약 (52×32). 아이콘 20px, 글자 10.5px 700 (떠 있는 탭과 같은 크기)
- 떠 있는 탭과 + 버튼은 숨긴다 (P2, P4 해결). 본문 하단 여백도 탭 높이만큼 두지 않는다
- 상단 줄: 팀 이름 알약(팀 전환 시트 그대로) + 화면 제목 또는 월 표시. 새 소식 알약과 프로필은 레일로 옮겼으니 상단에서 뺀다
- PC 사이드바는 ≥1024 에서 그대로. 1024~1199 에서도 레일을 쓸지는 열린 질문 Q3 (P6)

### 4-2 달력
- 상단 줄: 팀 알약, 월 숫자 44px(`.82` 행간) + "월 2026", 오른쪽 오늘 / ◀ ▶
- 2단: 왼쪽 달력 타일(남는 폭 전부, 6주 그리드가 높이를 채움) | 오른쪽 칸 332px (폭 ≥ 960 이면 360px)
- 오른쪽 칸 위에서부터: 오늘 비는 시간 타일, D-day 타일(`short` 이면 숨김), **선택 날짜 칸**(5-2 와 같은 내용: 기념일 줄, 일정 목록, "이 날 일정 추가")
- 날짜 칸 모양: 칸 높이 < 110px 이면 모바일처럼 막대 + 9px 제목, ≥ 110px(폴드 세로) 이면 PC 처럼 제목 칩. 칸 높이는 그리드가 정하므로 `@container` 쿼리로 고른다
- 일정 행을 누르면 오른쪽 칸이 **일정 상세**로 바뀐다 (뒤로 화살표로 날짜 칸 복귀). 모달 없음 (P3). 시안 `fold-proposal-duo-detail-light.png`, `-dark.png`
- 빈 날짜 칸 재탭 빠른 추가: PC 처럼 칸 옆 팝오버 340px (`QuickAddPopover`). 890 폭에서도 들어간다

### 4-3 빈 시간 찾기
- 2단 같은 폭: 왼쪽 조건 카드(위에 붙음), 오른쪽 결과 목록(칸 안에서 스크롤). 시안 `fold-proposal-duo-free-light.png` (P5)

### 4-4 일정 작성/수정
- 2단: 왼쪽 제목 + 메모, 오른쪽 종일 / 시작 / 종료 + 저장. 저장 버튼이 첫 화면에 보인다. 시안 `fold-proposal-duo-form-light.png` (P4)
- 날짜/시각 피커: PC 처럼 입력 아래 팝오버 (`PickerShell` 조건을 `pc` 에서 `fold | pc` 로)

### 4-5 기념일, 새 소식, 팀 설정, 내 정보
- 레일만 적용하고 본문은 가운데 640px 1단. 2단으로 나눌 내용이 없다

## 5. 날짜 탭 = 그날 상세 (모든 폭)

사용자 요청: 달력에서 날짜를 누르면 그날의 일정, 기념일, "이 날 일정 추가" 를 보여 주고, 일정을 누르면 일정 상세로.

### 5-1 폭별 동작
| 배치 | 날짜 탭 | 일정 탭 | 이 날 일정 추가 |
|------|--------|--------|----------------|
| phone | **날짜 바텀 시트** 열기 | 시트 안에서 상세로 전환 (시트 유지, 뒤로 화살표) | 시트 안 버튼 → 빠른 추가 시트 (`QuickAddSheet`) |
| fold | 선택만 바꾸고 오른쪽 칸 갱신. 모달 없음 | 오른쪽 칸이 상세로 | 칸 안 버튼 → 빠른 추가 팝오버 |
| pc | 지금 그대로 (선택 + 빈 곳 클릭 팝오버, 우측 패널) | 지금 그대로 | 지금 그대로 |

- phone 에서 지금의 "선택된 날짜 재탭 = 빠른 추가 시트" 는 없어진다. 추가는 시트 안 버튼이나 + 버튼으로 (열린 질문 Q1)
- phone 의 달력 아래 날짜 목록은 없앤다. 달력 화면이 한 화면에 들어간다

### 5-2 바텀 시트 (phone)
시안: `fold-proposal-phone-sheet-light.png`, `-dark.png` (390×844)

| 항목 | 내용 |
|------|------|
| 내용 | 머리 "10일 화요일" + 오늘 배지 + 닫기, 기념일 줄(옅은 코랄 `--hl-tile`, 하트 선 아이콘, "D-day" 또는 "오늘"), 일정 행(지금 목록과 같은 모양), 하단 "이 날 일정 추가" 52px 알약(`--today-bg`). 빈 날은 기존 빈 상태 문구 |
| 높이 | 처음 열 때 화면의 56% (반), 손잡이를 위로 끌면 전체(위 여백 = safe-area + 12px), 아래로 끌거나 배경 탭하면 닫힘. 내용이 반 높이를 넘으면 시트 안 스크롤 |
| 모양 | 위 모서리 30px, `--tile`, 배경 `rgba(0,0,0,.35)`, 손잡이 40×5 `--faint`. 모션 200ms (`prefers-reduced-motion` 이면 즉시) |
| 접근성 | `role=dialog` `aria-modal` + 제목 연결, 열면 제목에 포커스, Tab 은 시트 안에서 돈다, Esc 닫기, 닫으면 누른 날짜 칸으로 포커스 복귀. 끌기 대신 쓸 수 있게 "전체 보기" 는 손잡이 버튼(`aria-expanded`)으로도 |
| 시트 안 이동 | 일정 행 → 같은 시트 안에서 상세로 바뀜(뒤로 화살표). 상세의 수정/복제는 지금처럼 페이지 이동 |

### 5-3 뒤로가기와 주소 (#81 과의 관계)
- 지금: 선택 날짜는 `?date=`(오늘이면 생략), 보던 달은 `?month=` 를 `history.replaceState` 로 남긴다 (#81). 이 규칙은 그대로 둔다
- 시트를 열 때 **`history.pushState`** 로 `?date=YYYY-MM-DD&day=1` 한 칸을 쌓는다. 상세로 들어가면 `&event=<id>` 를 한 칸 더 쌓는다
- `popstate` 에서 주소의 `day`, `event` 로 시트 상태를 맞춘다. 안드로이드 뒤로 버튼과 iOS 뒤로 쓸기 = 상세 → 날짜 시트 → 닫힘 순서
- 닫기 버튼, 배경 탭, 아래로 끌기, Esc 는 직접 상태를 바꾸지 않고 `history.back()` 을 부른다 (쌓은 칸을 지워 앞으로가기에 유령 상태가 남지 않게). 시트가 쌓은 칸이 아닐 때(새로고침으로 `day=1` 주소에 바로 들어온 경우)는 `replaceState` 로 `day` 를 뗀다
- 새로고침이나 공유 주소의 `day=1` 은 phone 에서만 시트를 연다. fold/pc 는 `day` 를 무시하고 선택 날짜만 쓴다 (오른쪽 칸이 이미 보여 준다)
- `pushState` 도 #57 과 같은 이유로 state 는 `null` 로 넘긴다 (AppShell + 버튼의 기준 날짜 동기화)
- 펼치거나 접어 phone ↔ fold 가 바뀌면: 시트가 열려 있었다면 fold 에서는 오른쪽 칸이 같은 날짜, 같은 상세를 보여 주고 시트는 렌더하지 않는다 (주소는 그대로). 다시 접으면 주소대로 시트가 열린다

## 6. 힌지 (Viewport Segments)

- Chrome 138 부터 `@media (horizontal-viewport-segments: 2)` 와 `env(viewport-segment-left 1 0)` 등을 지원한다 ([Chrome 블로그](https://developer.chrome.com/blog/viewport-segments-api-shipped), [MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/horizontal-viewport-segments))
- **Safari 와 iOS Safari 는 미지원**이고 WebKit 입장도 없다 ([web-features](https://web-platform-dx.github.io/web-features-explorer/features/viewport-segments), [WebKit standards-positions #327](https://www.github.com/WebKit/standards-positions/issues/327)). 아이폰 듀오에서는 쓸 수 없다. 삼성 인터넷 지원 여부는 문서로 확인하지 못했다
- 폴드와 아이폰 듀오는 펼친 화면이 한 장이고 주름만 있다. 평평하게 펼치면 세그먼트가 1개로 잡힌다
- 결정: **힌지를 피하는 배치를 기본으로 만들지 않는다.** 펼친 화면은 거의 정사각형 한 장으로 본다. 반만 접은(책 자세) 경우만 후속 개선 후보로 남긴다: `horizontal-viewport-segments: 2` 이면 2단 경계를 `env(viewport-segment-right 0 0)` 에 맞춘다

## 9. 열린 질문

| # | 질문 | 권장 |
|---|------|------|
| Q1 | phone 에서 "선택된 날짜 재탭 = 빠른 추가" 를 없애고 날짜 탭은 항상 날짜 시트로 갈까 | 예. 같은 탭이 두 동작을 갖는 것보다 시트 안 "이 날 일정 추가" 한 곳이 알기 쉽다. + 버튼은 그대로 |
| Q2 | fold 구간 내비게이션을 레일로 바꿀까, 떠 있는 탭을 유지할까 | 레일. 아이폰 듀오 가로는 높이 626 이라 탭 86px 가 크고, 폭은 남는다 |
| Q3 | 1024~1199(폴드 가로 1092)에서 PC 사이드바 대신 레일을 쓸까 | 예. 달력이 156px 넓어져 칩 제목 잘림(P6)이 줄어든다. 1200 이상은 사이드바 유지 |
| Q4 | 힌지(책 자세) 대응 | 이번 범위에서 제외. Safari 미지원이고 평평하게 펼친 상태가 대부분 |
| Q5 | 날짜 시트에 "오늘 비는 시간" 도 넣을까 | 넣지 않는다. 달력 위 타일에 이미 있고 시트는 그날 내용만 |
