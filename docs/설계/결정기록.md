# 설계 결정 기록

- 이슈: #2
- 설계 중 내린 판단. 번호는 다른 설계 문서에서 `D-NN` 으로 참조한다.

| # | 결정 | 이유 |
|---|------|------|
| D-01 | Prisma 7 문법 (`generator prisma-client` + `output`, datasource 에 url 없음, `prisma.config.ts` 에서 `env("DATABASE_URL")`) | 2026-11 현재 `pnpm add prisma` 가 7.x 를 설치한다. 런타임은 드라이버 어댑터(`@prisma/adapter-mariadb`) 필요. 백엔드가 6.x 를 고르면 `prisma-client-js` 와 `url = env(...)` 로 두 줄만 바꾸면 됨 |
| D-02 | 새 소식은 **EventLog 테이블**, 일정은 물리 삭제 | 소프트 삭제는 "누가 언제 수정했는지" 를 못 남기고 모든 일정 조회와 빈 시간 계산에 `deletedAt` 필터가 붙는다. 로그에 제목/시각 스냅샷을 두면 삭제된 일정도 그대로 보여줄 수 있다 |
| D-03 | 회원 탈퇴는 User 행 물리 삭제, `creatorId`/`actorId` 는 FK `SetNull` → null 이 "탈퇴한 멤버" | 기획 "탈퇴 시 즉시 삭제" 를 가장 단순하게 만족. 별도 deleted 플래그나 익명 사용자 행이 필요 없다 |
| D-04 | PERSONAL 팀은 `inviteCode = null`. 초대 코드 재발급은 GROUP_NOT_INVITABLE | "팀 타입은 초대 가능 여부에만 영향" 원칙 그대로. join 은 코드가 없으니 분기 없이 INVITE_NOT_FOUND 로 끝난다 |
| D-05 | PERSONAL 팀은 나가기 불가 (GROUP_PERSONAL_LEAVE). 탈퇴로만 삭제 | 나가면 개인 달력이 없는 계정이 생겨 `/` 분기가 깨진다. 타입 분기이지만 "표시와 초대 가능 여부" 범위로 본다 |
| D-06 | 현재 팀은 URL 경로 `/g/[groupId]/...` 에 둔다. 마지막 팀은 `wwm_group` 쿠키로 기억 | 딥링크와 새로고침이 그냥 되고, 서버 컴포넌트가 쿠키 없이 groupId 를 안다. 상태 라이브러리 없이 시작한다는 프론트 규칙과 맞음 |
| D-07 | 초대 코드는 OAuth `state` 안에 `next=/join/<code>` 로 운반 (웹 쿠키 아님) | 웹과 API 도메인이 달라 웹 쿠키가 API 콜백에 안 간다. state 는 카카오가 그대로 돌려주므로 추가 저장소가 없다 |
| D-08 | CSRF 는 API 도메인의 `wwm_oauth_state` 쿠키(nonce) 와 state.nonce 대조 | 콜백이 최상위 GET 이동이라 SameSite=Lax 쿠키가 전달된다. state 서명은 과함 |
| D-09 | 로그인 시작은 웹 `/auth/kakao` route handler 가 API 로 302 | `API_URL` 을 서버 환경변수로만 두고 `NEXT_PUBLIC_*` 를 만들지 않기 위해. "브라우저는 프록시로만" 규칙과도 일관 |
| D-10 | JWT 는 URL 쿼리 `token` 으로 웹 콜백에 전달 (해시 아님) | route handler 는 해시를 못 읽는다. 즉시 302 + `no-referrer` + `no-store` 로 노출을 줄인다 |
| D-11 | 리프레시 토큰 없음. 만료 30일, 만료 시 재로그인 | 카카오 로그인 한 번이 비용이 낮고, 무상태 JWT 로 로그아웃을 쿠키 삭제만으로 끝낼 수 있다 |
| D-12 | 빈 시간 계산에서 **종일 일정은 기본 제외**, 화면 토글(`includeAllDay`) 로 포함 | 생일/기념일 같은 종일 일정을 넣는 순간 비는 날이 사라져 첫 사용에서 기능이 무용해진다. 휴가/여행처럼 진짜 바쁜 종일 일정은 사용자가 토글로 포함 (2026-11-09 사용자 확정) |
| D-13 | 빈 시간 API 는 `GET` + 쿼리, 범위 31일, 결과 100개 상한, 과거는 현재 시각으로 잘라냄 | 부수효과가 없고 조건 변경마다 재호출하므로 GET 이 맞다. 상한은 최악 요청(31일 × 멤버 10명 × 팀 여러 개)에서도 응답 크기를 묶기 위해 |
| D-14 | 빈 시간 조회는 `select: { startsAt, endsAt }` 만, 응답은 구간만 | 다른 팀 일정 내용 비노출을 코드 수준에서 보장. 제목을 메모리에 올리지도 않는다 |
| D-15 | 일정 조회 범위 62일, 일정 길이 30일 상한 | 월 그리드 42일 + 여유. 길이 상한은 "2026년 전체" 같은 입력이 빈 시간 계산을 망치는 것을 막는다 |
| D-16 | 종일 일정은 `startsAt/endsAt` 을 KST 자정 UTC 값으로 저장하고 `allDay` 플래그 병행. 서버는 자정 여부를 검증하지 않음 | 빈 시간/겹침 쿼리가 종일을 특별 취급하지 않아도 된다. 자정 검증은 KST 고정 가정이 서버에 새는 것이라 뺐다 |
| D-17 | 기념일은 `@db.Date`, API 는 `YYYY-MM-DD`, D-day 는 클라이언트 | 시각이 없는 값에 UTC 를 씌우면 날짜가 밀린다. 100일 단위 표시도 순수 날짜 계산 |
| D-18 | 팀 이름 변경, 일정, 기념일 모두 **멤버 누구나** 수정/삭제. 역할 없음 | 기획 "팀원 누구나 수정/삭제" 와 "권한은 멤버십 하나" 원칙. 2~10명 모임에 관리자 개념은 과함 |
| D-19 | `POST /groups/join` 은 멱등 (이미 멤버면 200 + 같은 응답) | 링크를 두 번 눌러도 오류가 아니라 달력으로 가는 게 F1 완료 기준에 맞다 |
| D-20 | `GET /invites/:code` 는 비로그인 공개 | 로그인 전에 "누구 팀인지" 보여야 가입 전환이 오른다. 코드 자체가 비밀이고 팀 이름과 인원수만 노출 |
| D-21 | 멤버 색은 합류 시 팔레트에서 가장 적게 쓰인 색 자동 배정. 중복 색 금지는 하지 않음 | 첫 화면에서 색 고르기를 시키지 않기 위해. 9명째부터는 어차피 겹친다 |
| D-22 | 새 소식은 내 변경 제외, 최근 30일, 50건, 화면이 GET 뒤 seen POST | 기획 "다른 멤버가" 그대로. 보존 기간 정리 작업은 MVP 에 두지 않는다 (행 수가 작다) |
| D-23 | 팀 목록에 `unreadNewsCount` 를 팀마다 count 쿼리로 | 사용자당 팀 수가 한 자리라 조인 raw SQL 보다 Prisma count N번이 읽기 쉽다 |
| D-24 | 회원 탈퇴는 카카오 unlink(Admin Key) → 성공 후 DB 트랜잭션 | 액세스 토큰을 저장하지 않으므로 Admin Key 방식. unlink 가 먼저 실패하면 계정이 그대로라 재시도 가능. 반대 순서는 DB 는 지워졌는데 연결이 남는 상태를 만든다 |
| D-25 | 팀 전환 UI 는 상단 바 시트, 하단 탭은 달력/빈 시간/기념일/팀 4개, 새 소식은 종 아이콘 | 기획 "상단에서 내 팀 목록 전환" 그대로. 새 소식은 배지가 핵심이라 탭보다 아이콘이 맞다 |
| D-26 | 기념일 삭제만 확인 없이 되돌리기 토스트, 일정/팀 나가기/탈퇴는 확인 다이얼로그 | 기념일은 되돌리기가 값 재등록으로 완전하다. 나머지는 다른 사람에게 영향이 있거나 되돌릴 수 없다 |
| D-27 | PK 는 cuid 문자열 | URL 에 groupId/eventId 가 드러나므로 순번 추측을 막는다 |
| D-28 | `kakaoId` 는 BigInt | 카카오 회원번호가 2^31 을 넘는다. JSON 으로는 내려주지 않으므로 직렬화 문제 없음 |
