# 팀 공유 할 일 목록 설계

- 이슈: #276, 기획 `docs/기획/할일-목록.md`
- 결정: D-203 ~ D-207
- 작성: 2026-11-12

## 1. 데이터 (`schema.prisma`)

```prisma
/// (#276) 팀 공유 할 일 목록 (장보기, 여행 준비물). 날짜 없음
model TodoList {
  id         Int      @id @default(autoincrement())
  groupId    Int
  /// 주소(`/todos/<code>`)에서 번호 대신 쓰는 공개 코드 (common/public-code.ts, #311 과 같은 규칙)
  publicCode String   @unique @db.Char(8)
  name       String   @db.VarChar(30)
  creatorId  Int?
  /// 목록이나 항목을 마지막으로 바꾼 사람 (목록 화면 "민지, 3분 전")
  editorId   Int?
  createdAt  DateTime @default(now())
  /// 항목이 바뀌어도 올린다 (목록 정렬)
  updatedAt  DateTime @updatedAt

  group   Group      @relation(fields: [groupId], references: [id], onDelete: Cascade)
  creator User?      @relation("TodoListCreator", fields: [creatorId], references: [id], onDelete: SetNull)
  editor  User?      @relation("TodoListEditor", fields: [editorId], references: [id], onDelete: SetNull)
  items   TodoItem[]

  @@index([groupId, updatedAt])
}

model TodoItem {
  id        Int       @id @default(autoincrement())
  listId    Int
  text      String    @db.VarChar(100)
  done      Boolean   @default(false)
  doneAt    DateTime?
  doneById  Int?
  creatorId Int?
  createdAt DateTime  @default(now())
  updatedAt DateTime  @updatedAt

  list    TodoList @relation(fields: [listId], references: [id], onDelete: Cascade)
  doneBy  User?    @relation("TodoItemDoneBy", fields: [doneById], references: [id], onDelete: SetNull)
  creator User?    @relation("TodoItemCreator", fields: [creatorId], references: [id], onDelete: SetNull)

  @@index([listId, done, createdAt])
}
```

- 마이그레이션 `20261112180000_todo_lists`: 테이블 2개 생성만 (추가형, `docs/운영/배포.md` 정책). 백필 없음
- 항목에 `groupId` 를 두지 않는다. 단건(`/todo-items/:itemId`)은 `findFirst({ id, list: { groupId } })` 로 팀 안에서만 찾는다 (D-31)
- 팀 삭제(마지막 멤버 나감, 개인 팀은 탈퇴) → Cascade. 탈퇴 → `creatorId`, `editorId`, `doneById` SetNull = "탈퇴한 멤버" (D-03). 나가기 → 행은 남고 표시 이름은 나간 사람 규칙(닉네임, 회색)

## 2. API (api.md 2.11)

공통 봉투 D-33, 인증 열 "멤버" = 경로 `groupId` 멤버십 (아니면 403). 다른 팀 목록, 항목 번호는 404 NOT_FOUND (D-31).

| 메서드 | 경로 | 요청 | 응답 `data` |
|--------|------|------|------------|
| GET | `/groups/:groupId/todo-lists` | - | `{ items: TodoListSummary[] }` updatedAt 내림차순 |
| POST | `/groups/:groupId/todo-lists` | `{ name }` | 201 `TodoList` |
| GET | `/todo-lists/:code` | - | `{ list: TodoList, items: TodoItem[] }`. 틀린 코드, 없는 목록, 비멤버 모두 404 (D-197 과 같은 예외) |
| PATCH | `/groups/:groupId/todo-lists/:listId` | `{ name }` | `TodoList` |
| DELETE | `/groups/:groupId/todo-lists/:listId` | - | `{ ok: true }` 항목 Cascade |
| POST | `/groups/:groupId/todo-lists/:listId/items` | `{ text, done? }` (`done` 은 되돌리기용) | 201 `TodoItem` |
| DELETE | `/groups/:groupId/todo-lists/:listId/items?done=true` | - | `{ ok: true, count }` 완료 항목 지우기. `done=true` 가 아니면 400 |
| PATCH | `/groups/:groupId/todo-items/:itemId` | `{ text?, done? }` (빈 본문은 그대로) | `TodoItem` |
| DELETE | `/groups/:groupId/todo-items/:itemId` | - | `{ ok: true }` |

```ts
TodoListSummary = { id, publicCode, name, openCount, doneCount, editor: Member, updatedAt }
TodoList        = { id, publicCode, groupId, groupCode, name, creator: Member, editor: Member, createdAt, updatedAt }
TodoItem        = { id, listId, text, done, doneAt: string | null, doneBy: Member | null, creator: Member, createdAt, updatedAt }
```

- `Member` 는 api.md 1장 "표시 이름" 규칙. 탈퇴자 `{ userId: null, displayName: "탈퇴한 멤버" }`. `editor` 는 만들 때 만든 사람으로 채워 늘 값이 있고, 탈퇴하면 "탈퇴한 멤버", `doneBy` 는 `done=false` 면 null, 완료인데 탈퇴했으면 "탈퇴한 멤버"
- 글: 앞뒤 공백을 자르고 검증 (api.md 1장 "문자열 공백"). 이름 1~30자, 항목 1~100자. 아니면 400 VALIDATION_FAILED (`details[0].field = 'name' | 'text'`). `done` 은 boolean 만
- 상한 (D-205): 목록 20개/팀, 항목 300개/목록. 넘으면 400 `TODO_LIMIT_REACHED` ("목록은 20개까지 만들 수 있어요" / "항목은 300개까지 넣을 수 있어요"). 셈과 생성은 한 트랜잭션에서 팀(목록 만들기) 또는 목록(항목 추가) 행을 잠그고 해서 동시 요청에도 넘지 않는다
- 완료 (D-204): `done: true` → `doneAt = now`, `doneById = 나`. `false` → 둘 다 null. 지금 값과 같으면 쓰지 않는다(멱등, `updatedAt` 그대로, #62 원칙). 글도 같으면 쓰지 않는다
- 목록 `updatedAt`, `editorId`: 이름 바꾸기, 항목 추가, 수정(실제로 바뀐 경우), 삭제, 완료 지우기(1개 이상)에서 같은 트랜잭션으로 올린다
- 항목 순서: 미완료는 `createdAt` 오름차순(같으면 id), 그 아래 완료는 `doneAt` 내림차순. 서버가 정렬해 내리고 웹은 낙관적 반영 뒤 같은 순수 함수(`lib/todo.ts`)로 다시 정렬
- 요청 제한: 새 한도 없음. 기본 "사용자 300 / 1분" (api.md 1장 "요청 제한", D-143). 장보기 연속 입력도 1분 300회 미만
- 새 소식, 푸시: 기록하지 않는다 (기획 4장)
- 단건 조회를 번호 경로(`GET /groups/:groupId/todo-lists/:listId`) 대신 코드 경로로 둔 이유: 상세 주소가 `/todos/<code>` 이고 주소에 팀이 없어(D-196) 서버가 코드로 팀을 찾아야 한다. 같은 일을 하는 경로를 둘 두지 않는다 (D-203)

## 3. 화면 (화면흐름.md 7-1, 7-2)

| 화면 | 주소 | 내용 |
|------|------|------|
| 홈 구역 "할 일" (폰) | `/calendar` | 기념일 구역 아래. 제목줄 "할 일" + "전체보기 ›" (→ `/todos`). 가로 카드 148×84: 위 목록 이름 15/600 한 줄, 아래 "남은 N개" 13 `--mute` (0 이면 "다 했어요"). 누르면 상세. 목록 0개면 한 줄 안내 "같이 챙길 것을 적어 두세요." + "목록 만들기" (→ `/todos?new=1`). 불러오는 중 스켈레톤 3장, 실패는 한 줄 + 다시 시도 |
| 사이드바 (≥600) | - | 메뉴 줄 "할 일" (기념일과 새 소식 사이). 접힌 레일도 같은 자리에 아이콘 + 툴팁 "할 일" |
| 목록 화면 | `/todos` | 제목 "할 일" + 설명 한 줄, 제목줄 오른쪽 "목록 추가"(넓은 화면 버튼, 폰은 + FAB 가 목록 추가). 목록 카드(모서리 16, 흰 면): 이름 16/700, 아래 "남은 3개" 또는 "다 했어요" + "민지, 3분 전" 12 `--mute`. 본문 `main-lg`(≥696) 2열, `main-2xl`(≥1208) 3열 격자 (D-202). 빈 상태: 안내 + 제안 칩 셋 + "목록 추가". `?new=1` 이면 만들기 시트를 연 채로 |
| 목록 상세 | `/todos/<code>` | 머리줄 ‹(목록 화면) + 목록 이름 + `⋯`(이름 바꾸기, 완료 항목 지우기, 목록 삭제). 항목 줄 높이 44: 체크 원 버튼(누르는 칸 44, `aria-pressed`), 글, 오른쪽 추가한 사람 색 점. 줄을 누르면 글 수정(제자리 입력, 엔터 저장, Esc 취소, 빈 글은 삭제), 오른쪽 끝 × 로 삭제(되돌리기 5초). 완료 항목은 아래 "완료 N개" 접힘(누르면 펼침), 취소선 + `--mute` + "민지님이 완료, 11월 12일". 맨 아래 고정 입력줄 "항목 추가"(엔터로 연속 입력). 전체 폭 한 장 (D-100) |

- 폰 아래 독 4개는 그대로 (디자인규칙 4-1). `/todos` 에서는 어느 칩도 켜지 않는다. 폰 + 는 목록 화면에서 "목록 추가". 상세는 일정 작성 화면처럼 독과 + 를 숨기고(맨 아래 입력줄이 주 동작, 머리줄 ‹ 로 돌아간다)
- 다시 불러오기: 목록 화면, 상세, 홈 구역은 들어올 때와 `visibilitychange` 로 앞으로 올 때
- 저장 실패: 낙관적 반영을 되돌리고 토스트(`messageOf`). 404(다른 멤버가 지움)는 "이미 삭제된 항목이에요" + 다시 불러오기. 상세 목록 자체가 404 면 "이미 삭제된 목록이에요" + 목록 화면 링크. `TODO_LIMIT_REACHED` 는 서버 문구 그대로
- 스크린 리더: 체크 버튼 이름 "장보기, 우유, 완료 안 됨" / "... 완료됨"
- 아이콘 `IconTodo`: 둥근 사각 + 체크, 겹침 조각 = 왼쪽 위 작은 둥근 사각 (디자인규칙 3-2)
- 팀 전환: `/todos` 는 그대로 새 팀 목록, `/todos/<code>` 는 다른 팀 목록이라 `/todos` 로 (`afterTeamSwitch`). 상세 주소로 바로 들어오면 서버가 `GET /todo-lists/:code` 로 팀을 찾아 `TeamScope` 로 맞춘다 (D-198 과 같은 방식)
