# 인증 흐름

- 이슈: #2
- 카카오 OAuth 는 NestJS 가 직접 처리하고 자체 JWT 를 발급한다. 브라우저는 JWT 를 모르고, httpOnly 쿠키만 가진다.

## 1. 등장 요소

| 요소 | 값 |
|------|-----|
| 카카오 인가 | `https://kauth.kakao.com/oauth/authorize?client_id&redirect_uri&response_type=code&state&scope=profile_nickname,profile_image` |
| 토큰 교환 | `POST https://kauth.kakao.com/oauth/token` (grant_type=authorization_code, client_id, client_secret, redirect_uri, code) |
| 사용자 조회 | `GET https://kapi.kakao.com/v2/user/me` → `id`, `kakao_account.profile.nickname`, `kakao_account.profile.profile_image_url` 만 사용. 이메일 요청 안 함 |
| `KAKAO_REDIRECT_URI` | `${API_ORIGIN}/v1/auth/kakao/callback`. 개발자센터에 로컬/운영 둘 다 등록 (사용자가 직접) |
| JWT | HS256, `JWT_SECRET`. 클레임 `{ sub: userId, iat, exp }`. 만료 30일. 리프레시 없음 |
| 세션 쿠키 | 이름 `wwm_session`, 값 JWT. `HttpOnly; SameSite=Lax; Path=/; Max-Age=2592000`, 운영은 `Secure`. 웹 도메인에만 존재 |
| state 쿠키 | 이름 `wwm_oauth_state`, API 도메인. `HttpOnly; SameSite=Lax; Path=/v1/auth; Max-Age=600`, 운영은 `Secure` |
| 팀 기억 쿠키 | 이름 `wwm_group`, 값 마지막으로 본 groupId. JS 에서 읽고 씀 (민감정보 아님). `SameSite=Lax; Max-Age=1년` |

## 2. 로그인 시퀀스

```
브라우저                      웹 (Next)                         API (Nest)                      카카오
  │ 1 GET /auth/kakao?next=/join/ABC123                             │                              │
  │ ──────────────────────────► │ 302 ${API_URL}/v1/auth/kakao?next=/join/ABC123                  │
  │ 2 ◄──────────────────────── │                                   │                              │
  │ GET /v1/auth/kakao?next=... ──────────────────────────────────► │ nonce 생성                    │
  │                             │   state = base64url({ nonce, next })                             │
  │ 3 ◄── 302 kauth/authorize?state=...  Set-Cookie wwm_oauth_state=nonce                          │
  │ ────────────────────────────────────────────────────────────────────────────────────────────► │
  │ 4 ◄── 302 /v1/auth/kakao/callback?code&state ──────────────────────────────────────────────── │
  │ ───────────────────────────────────────────────────────────────► │ state.nonce == 쿠키 nonce 확인 │
  │                             │                                   │ 토큰 교환, /v2/user/me ───────► │
  │                             │                                   │ User upsert(kakaoId)           │
  │                             │                                   │   신규면 PERSONAL 팀 + 멤버십 생성│
  │                             │                                   │ JWT 발급, state 쿠키 삭제       │
  │ 5 ◄── 302 ${WEB_ORIGIN}/auth/callback?token=<JWT>&next=/join/ABC123                           │
  │ ──────────────────────────► │ token 형식 확인(JWT 3조각), next 검증                              │
  │ 6 ◄── 302 next  Set-Cookie wwm_session=<JWT>                     │                              │
  │ GET /join/ABC123 ─────────► │ (쿠키 있음) POST /api/groups/join ──► Bearer 로 변환 ─────────────► │
  │ ◄── 302 /g/<groupId>/calendar                                   │                              │
```

| 단계 | 규칙 |
|------|------|
| 1 | 웹의 `app/auth/kakao/route.ts` 는 302 만 한다. API 주소(`API_URL`)를 브라우저에 노출하지 않기 위한 한 겹 |
| 2 | `next` 는 `^/[A-Za-z0-9/_-]*$` 만 허용, 아니면 `/`. 초대 링크로 온 경우 `/join/<code>` 가 들어온다 (join 코드는 쿠키가 아니라 state 로 운반) |
| 3 | nonce 는 32바이트 랜덤 hex. state 는 서명하지 않는다 (nonce 쿠키 대조로 충분) |
| 4 | state 불일치, code 없음 → `302 ${WEB_ORIGIN}/login?error=OAUTH_STATE`. 카카오 호출 실패 → `?error=KAKAO_ERROR`. 쿠키는 어느 경우든 삭제 |
| 4 | User upsert: `kakaoId` 로 찾아 nickname/profileImageUrl 갱신. 없으면 생성하고 같은 트랜잭션에서 `Group(PERSONAL, name: "내 달력", inviteCode: null)` 과 `Membership(color: MEMBER_COLORS[0])` 생성 |
| 5 | token 이 URL 에 잠깐 노출된다. 웹 콜백은 저장 직후 302 로 URL 을 떠나고, 콜백 라우트 응답에 `Referrer-Policy: no-referrer`, `Cache-Control: no-store` 를 단다 |
| 6 | `next` 를 다시 같은 규칙으로 검증하고 302. 토큰은 JS 에 넘기지 않는다 |

## 3. 로그인 이후

| 상황 | 동작 |
|------|------|
| API 호출 | 웹 `app/api/[...path]/route.ts` 가 `wwm_session` 쿠키를 읽어 `Authorization: Bearer` 로 바꿔 `${API_URL}/v1/<path>` 에 전달. 메서드, 쿼리, JSON 본문, 응답 상태/본문 그대로 통과. 쿠키 없으면 API 를 부르지 않고 바로 `401 { error: { code: 'UNAUTHORIZED' } }` |
| API 가 401 | 프록시가 `wwm_session` 을 지우고 401 을 그대로 돌려준다. `lib/api.ts` 는 401 을 받으면 `/login?next=<현재 경로>` 로 이동 |
| 인증 필요 화면 진입 | `proxy.ts` 가 쿠키 **존재만** 확인 (서명 검증 안 함). 없으면 `/login?next=<요청 경로>`. 실제 유효성은 첫 API 호출의 401 로 드러난다 |
| 만료 | JWT 30일 = 쿠키 Max-Age 30일. 만료되면 위 401 경로로 자연스럽게 재로그인. 슬라이딩 연장 없음 |
| 로그아웃 | 웹 `POST /auth/logout` route handler 가 `wwm_session` 과 `wwm_group` 을 삭제하고 302 `/login`. API 호출 없음 (JWT 는 무상태) |
| 탈퇴 | `DELETE /api/me` 성공 응답을 받은 뒤 로그아웃과 동일하게 쿠키 삭제. 이미 발급된 JWT 는 `sub` 사용자가 없어 UNAUTHORIZED |
| API 측 검증 | `JwtAuthGuard` 가 서명/만료 확인 후 `User.findUnique(sub)`. 없으면 401. `@CurrentUser()` 로 주입 |

## 4. CORS 와 도메인

| 항목 | 값 |
|------|-----|
| 웹 → API | 서버 간 호출(프록시)이라 CORS 불필요. 브라우저가 API 를 직접 여는 것은 OAuth 리다이렉트(2단계) 뿐이고 이것은 최상위 이동이라 CORS 대상이 아님 |
| CORS 설정 | 그래도 `origin: WEB_ORIGIN, credentials: false` 로 고정 (`*` 금지) |
| 도메인 분리 | 웹(Vercel)과 API(Fly/Railway)가 다른 도메인이어도 동작한다. state 쿠키는 API 도메인, 세션 쿠키는 웹 도메인에만 있다 |
