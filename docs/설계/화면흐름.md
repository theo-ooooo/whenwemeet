**공통 뼈대 (`/g/[groupId]/*`)**

| 영역 | 내용 |
|------|------|
| 상단 바 | 왼쪽: 팀 이름 + ▼ (탭하면 팀 전환 시트: 내 팀 목록, 각 팀 옆 `unreadNewsCount` 점, 맨 아래 "새 팀 만들기" → 3, "초대 코드로 합류" → 2-1. PC 사이드바 "내 팀" 아래에도 같은 두 항목). 오른쪽: 새 소식 종 아이콘(배지 = 현재 팀 unreadNewsCount) → 8, 내 프로필 사진 → 10 |
| 하단 탭 | 달력(4) / 빈 시간(6) / 기념일(7) / 팀(9) |
| 팀 전환 | 선택한 groupId 로 같은 탭 경로 이동 + `wwm_group` 쿠키 갱신 |
| 403 응답 | 그 팀 멤버가 아니게 된 경우(나가기, 삭제됨). "이 팀에 더 이상 속해 있지 않아요" 토스트 후 `/` 로 |

## 2. 화면별 명세

각 화면의 **빈 상태 / 로딩 / 오류** 는 표의 마지막 세 행. 오류 문구는 API `error.message` 가 있으면 그것을 우선 보여주고, 아래는 네트워크 실패 등 message 가 없을 때의 기본값.

### 1 로그인 `/login`

| 항목 | 내용 |
|------|------|
| 구성 | 로고, 한 줄 소개("언제 볼까? 를 달력 하나로"), 카카오 로그인 버튼(#FEE500, 검정 글자, 카카오 심볼), 하단 "이용약관 · 개인정보처리방침" 링크 |
| 동작 | 버튼 → `/auth/kakao?next=<next>` (웹 route handler, 인증흐름.md 2) |
| `error` 쿼리 | `OAUTH_STATE` → "로그인 시간이 지났어요. 다시 시도해 주세요" / `KAKAO_ERROR` → "카카오 연결에 실패했어요. 잠시 후 다시 시도해 주세요" |
| 이미 로그인 | 쿠키 있으면 `next` 또는 `/` 로 바로 이동 |
| 빈 상태 | 없음 |
| 로딩 | 버튼 탭 후 비활성화 + "카카오로 이동 중…" |
| 오류 | 위 `error` 문구를 버튼 위에 표시 |

### 1-1 이메일 로그인 `/login/email` (#245, 이메일-로그인.md 6-3)

| 항목 | 내용 |
|------|------|
| 진입 | `/login`, `/join/[code]` 의 [이메일로 계속하기](테두리 보조 버튼, 소셜 버튼 아래). 앱 안: 네이티브 로그인 화면의 이메일 버튼(셸 UA `EmailLogin/1`) 또는 웹 선택 화면(토큰 없는 셸, 아래) |
| ① 이메일 | 제목 "이메일로 계속하기", 이메일 입력(타일 카드), [메일 받기] primary xl, 글자 버튼 "다른 방법으로 로그인" → `/login?next=` |
| ② 메일을 보냈어요 | 입력한 이메일 전체, 코드 6칸(숫자 키패드, 붙여넣기, 6자리 차면 바로 제출), [다시 보내기 (0:42)] 테두리 버튼, "다른 이메일로", 스팸함 안내. sessionStorage 로 새로고침해도 유지(15분) |
| 성공 | 기존 계정: 행에 저장된 next 로 전체 이동. 처음: 1-2 |
| 오류 | 이메일-로그인.md 6-6 표. 입력 아래 13px `--danger`. 틀린 코드는 칸 테두리 `--holiday` + 칸 비움 |
| 로딩 | 버튼 스피너, 코드 확인 중 "확인하는 중…" |

### 1-2 처음 가입 닉네임 `/login/email/nickname` (#245)

| 항목 | 내용 |
|------|------|
| 구성 | "어떻게 불러 드릴까요?", 닉네임 입력(n/20), [시작하기] — 앞뒤 공백 뺀 2~20자일 때만 |
| 성공 | 세션 쿠키 + next 로 이동 (초대면 `/join/<코드>?auto=1` 이 바로 합류) |
| 오류 | 가입 티켓 만료 → `/login/email?error=SIGNUP_TOKEN_INVALID` |

### 1-3 메일 링크 확인 `/auth/email?token=` (#245, D-113)

| 상태 | 화면 |
|------|------|
| VALID | "언제볼까 시작하기", 가린 이메일(`ki***@gmail.com`), [로그인 계속하기] form POST. 자동 제출 안 함 |
| EXPIRED, INVALID | "링크를 쓸 수 없어요" + [메일 다시 받기] |
| USED | "이미 사용한 링크예요" + [언제볼까 열기], "메일 다시 받기" |
| 스위치 꺼짐 | "지금은 이메일로 로그인할 수 없어요" + [로그인 화면으로] |
| 연결 실패 | "링크를 확인하지 못했어요" + [다시 시도] |

### 1-4 앱 안 `/login` 선택 화면 (#245, D-116)
이메일 버튼을 모르는 셸(UA 에 `EmailLogin/1` 없음)이고 스위치가 켜져 있으면 네이티브 화면을 자동으로 열지 않고 [카카오 또는 Apple로 계속하기](iOS) / [카카오로 계속하기](Android) primary xl → 네이티브 화면, 아래 [이메일로 계속하기]. 토큰이 있는 셸은 지금처럼 자동으로 네이티브 화면(맨 아래 이메일 버튼).

### 2 초대 수락 `/join/[code]`

| 항목 | 내용 |
|------|------|
| 진입 | 카톡으로 받은 링크(`/join/<code>?by=<표식>`, #196). 서버 컴포넌트가 `GET /invites/:code?by=` 로 미리보기(쿠키가 있으면 토큰도 같이) |
| 초대한 사람 | `inviter` 가 있으면 배지 "멤버 N명" 과 제목 사이에 "{이름}님이 초대했어요" (13/500 `--ink-2`). 이름은 20자 넘으면 말줄임. 없으면 이 줄을 그리지 않는다. 로그인으로 나갔다 돌아오는 `next` 에도 `by` 를 남긴다 |
| 이미 멤버 | `isMember` 면 제목 "{groupName}\n이미 함께하는 팀이에요", 설명 "달력에서 바로 이어서 볼 수 있어요", 버튼 [달력 열기] → `/g/<groupId>/calendar`. 자동 합류(`?auto=1`)도 하지 않는다. 자동으로 넘기지 않는 건 팀을 착각했을 때 알 수 있게 (#196) |
| 로그인 전 | "**{groupName}** 팀에 초대받았어요 (멤버 {memberCount}명)" + 카카오 로그인 버튼 → `/auth/kakao?next=/join/<code>?auto=1` |
| 로그인 후 | 같은 카드 + "합류하기" 버튼 → `POST /api/groups/join { code }` → 성공 시 `wwm_group` 갱신 후 `/g/<id>/calendar`. 이미 멤버여도 같은 경로 |
| 자동 합류 | 이 화면의 카카오 버튼으로 로그인하고 돌아온 직후(`/join/<code>?auto=1` + 세션 JWT `iat` 5분 이내)는 "합류하기" 를 누르지 않아도 바로 합류 후 그 팀 달력으로 (버튼은 "합류하는 중…"). 이미 멤버여도 합류가 멱등이라 그 팀 달력으로 간다. 쿠키를 쓰지 않아 카카오 인앱 브라우저에서도 동작하고, 합류를 시작하면 주소에서 `?auto=1` 을 뗀다. 로그인한 채 링크를 그냥 연 경우(`?auto=1` 이 붙어 있어도 세션이 오래됨)는 실수 합류를 막으려고 버튼 확인을 유지 (D-41). 자동 합류 실패 시 오류 문구 + "합류하기" 버튼 |
| 빈 상태 | 코드 없음(INVITE_NOT_FOUND): "초대 링크가 만료됐거나 잘못됐어요. 초대한 사람에게 새 링크를 받아 주세요" + 홈 버튼 |
| 로딩 | 카드 자리 스켈레톤 |
| 오류 | "초대 정보를 불러오지 못했어요. 새로고침해 주세요" |

### 2-1 초대 코드 입력 `/join` (#56)

| 항목 | 내용 |
|------|------|
| 진입 | 팀 전환 시트와 PC 사이드바의 "초대 코드로 합류", 3 팀 만들기 하단 "초대 코드를 받았나요? 코드로 합류하기". 로그인 필요 (proxy) |
| 구성 | 닫기(→ `/`), 제목 "초대 코드를 입력해 주세요", 설명 "팀원에게 받은 6자리 코드로 같은 달력에 합류해요", 6칸 입력, "합류하기", 하단 "새 팀 만들기" → 3 |
| 입력 | 칸 위에 겹친 input 하나. 소문자는 대문자로, 영문/숫자 외는 버림, 6자까지. 붙여넣기 지원(초대 링크 전체를 붙여넣으면 `/join/` 뒤 코드만). 6자가 차야 버튼 활성, Enter 로 제출 |
| 동작 | `POST /api/groups/join { code }` (`useJoinGroup`) → `wwm_group` 갱신 → `/g/<id>/calendar`. 이미 멤버여도 같은 경로 |
| 빈 상태 | 없음 |
| 로딩 | 버튼 스피너, 입력 비활성 |
| 오류 | INVITE_NOT_FOUND: 칸 테두리 빨강 + "코드가 맞지 않거나 만료됐어요. 초대한 사람에게 코드를 다시 확인해 주세요". 그 밖은 `error.message` 또는 "합류하지 못했어요. 다시 시도해 주세요". 코드를 고치면 문구를 지움 |

### 2-2 일정 카드 공유 받기 `/join/e/[token]` (#274, D-181 ~ D-186)

| 항목 | 내용 |
|------|------|
| 진입 | 카톡, 문자로 받은 일정 링크. 서버 컴포넌트가 `GET /event-shares/:token` (쿠키가 있으면 토큰도 같이). 토큰이 22자 base64url 이 아니면 API 를 부르지 않고 만료 화면 |
| 짜임 | 초대 화면(2)과 같다: 로고 32, 제목 28/36, 좌우 24, 하단 버튼. 위에서부터 칩 "{이름}님이 보낸 일정"(보낸 사람이 없으면 "공유받은 일정"), 제목(최대 2줄), 날짜와 시각 줄(15/600), 반복이면 "매주 반복 일정"(13 `--soft`), "{팀} 팀, 멤버 N명"(13/500 `--ink-2`), 안내 "합류하면 이 팀의 모든 일정을 함께 봐요" |
| 시각 형식 (KST) | `11월 15일 (토) 오후 7:00 ~ 9:00` (오전/오후가 바뀌면 끝에도), 종일 `11월 15일 (토) 종일`, 여러 날 `11월 15일 (토) ~ 17일 (월)`(달이 바뀌면 `~ 12월 2일 (수)`), 여러 날 시간 일정은 양끝 시각 (`lib/event-share.ts`) |
| 로그인 전 | 로그인 버튼(`JoinLoginActions`, next = `/join/e/<token>?auto=1`) + 모바일 브라우저면 `OpenInApp`(D-72, 경로 그대로) |
| 로그인, 비멤버 | [팀에 합류하고 일정 보기] → `POST /event-shares/:token/join` → `wwm_group` 갱신 → `/g/<id>/calendar?date=<그 회차 날짜>&day=1&event=<id>[&occurrence=]` (지난 날짜여도 그대로). 자동 합류(`?auto=1` + 세션 5분)는 초대와 같은 D-41 |
| 이미 멤버 | 화면 없이 서버에서 같은 달력 주소로 이동. 페이지를 여는 것만으로 합류하지 않는다 |
| 만료 | 없음, 만료, 끊김, 일정 삭제, 회차 취소(EVENT_SHARE_NOT_FOUND): "링크가 만료됐거나 끊겼어요" + "보낸 사람에게 새 링크를 받아 주세요" + [홈으로] |
| 오류 | "일정을 불러오지 못했어요" + API 문구(RATE_LIMITED 면 "잠시 후 다시 시도해 주세요") |
| 메타 | 제목 `{일정 제목} - {팀 이름}`, 설명은 시각 줄, 실패하면 "일정을 공유받았어요". 이미지 `/og/join/e/<token>` (kicker 시각, 큰 줄 일정 제목 2줄, "{팀} 팀 일정", 칩 "일정 보기", 성공 5분, 실패 1분 캐시). `Referrer-Policy: no-referrer`, robots noindex |

"이후 모두" 인데 단건 응답 `hasLaterExceptions` 가 참이면 확인 창 "이후 따로 바꾼 회차도 새 값으로 바뀌어요" → 바꾸기. 반복 필드(`repeat`, `repeatUntil`)는 새 일정/한 번짜리에서 켰을 때와 "이후 모두" 일 때만 보낸다. "이후 모두" 에서 시작, 종료를 불러온 값 그대로 두면 `startsAt`, `endsAt` 을 빼고 보내 서버가 그 회차의 규칙 자리에서 잇게 한다 (종료 날짜를 그대로 두면 `repeatUntil` 을 빼는 것과 같은 방식, QA3-M3) |
| 삭제 | 한 번짜리: 확인 다이얼로그 "이 일정을 삭제할까요? 팀원 모두에게서 사라져요" → `DELETE` → 달력으로. 반복 일정: 범위 시트 "반복 일정 삭제"(두 줄 위험 글자) → `DELETE ?occurrence=&scope=` → 달력으로. 달력 일정 상세의 삭제도 같은 시트 |
| 상세 표시 (#187) | 달력 일정 상세(EventDetail)는 시각 아래 "매주 목요일"(기준은 `repeatAnchor ?? seriesStartsAt`), 종료가 있으면 다음 줄 "12월 31일까지"(올해가 아니면 연도). 그 아래 알림이 있으면 종 아이콘 + "알림 1시간 전" (#188). 팀이면 "참여자" 칸(아바타 24 + 이름 세로 목록, 가입순, 나는 "(나)"; 모두면 "모두 (N명)" 아래 같은 목록; 참여자 없음이면 `--mute` "참여자 없음" + "수정에서 다시 고를 수 있어요"), 메모, "○○님이 추가", 등록/수정 시각 (#248). 개인 팀은 참여자 칸 없이 위 "○○가 등록" 그대로. 달력 주소는 `&event=<id>&occurrence=` |
| 알림 누름 (#188) | 셸이 `data.url` 을 웹뷰로 연다. 일정은 `/g/:id/calendar?date=&day=1&event=&occurrence=`(달력 일정 상세, 새 라우트 없음), 삭제는 `/g/:id/news`, 기념일은 `/g/:id/anniversaries`, 합류는 `/g/:id/calendar` (푸시-알림.md 6장). 일정이 없어졌으면 지금 규칙(`missingEventTarget`) |
| 종일 변환 | 종일 ON 시 startsAt=그날 KST 00:00, endsAt=다음 날 KST 00:00 을 UTC 로 보냄 (`lib/date.ts`) |
| 빈 상태 | 없음 |
| 로딩 | 수정 모드: 폼 자리에 스켈레톤. 저장 중 버튼 비활성 |
| 오류 | 저장 실패: 상단 배너 "저장하지 못했어요. 입력 내용은 그대로 있으니 다시 저장해 주세요". 404: "이미 삭제된 일정이에요" 토스트 후 달력으로 |

- 루트 레이아웃에 하나(`components/PushPrompt.tsx`). 계기: 일정 저장 성공 직후 또는 알림 줄에서 "없음" 이 아닌 값을 처음 고를 때, 둘 중 먼저 한 번

- 시트 제목 "알림", 본문 "약속 전에, 팀원이 일정을 바꿀 때 알려 드릴까요?", 보조 "내 정보 > 알림 에서 언제든 바꿀 수 있어요", 버튼 [나중에] [알림 받기]
- [알림 받기] → `wwm_push_prompt = accepted`, `pushRequest` → 허용이면 등록, 거부면 그냥 닫음. [나중에], 바깥, 닫기 → `later`
- 기기 등록: 로그인된 화면(팀 뼈대, 내 정보, 알림)이 그려질 때와 앱이 앞으로 올 때 `pushStatus` → 토큰이 있으면 `PUT /api/me/push-devices`(같은 토큰은 1시간에 한 번), 없는데 `wwm_push_token` 이 남아 있으면 `DELETE` 후 지움 (푸시-알림.md 2-3)
