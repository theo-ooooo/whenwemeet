# 화면 흐름

- 이슈: #2
- 모바일 우선(360px), 데스크톱은 가운데 480px. 모든 시각은 KST 로 표시.

## 1. 라우트와 뼈대

| 경로 | 화면 | 인증 | 비고 |
|------|------|------|------|
| `/` | 분기 | - | 쿠키 없으면 `/login`, 있으면 `/g/<wwm_group 쿠키 또는 PERSONAL 팀>/calendar` |
| `/login` | 1 로그인 | 공개 | 쿼리 `next`, `error` |
| `/join/[code]` | 2 초대 수락 | 공개 | 로그인 여부에 따라 두 모습 |
| `/groups/new` | 3 팀 만들기 | 필요 | |
| `/g/[groupId]/calendar` | 4 달력 | 필요 | 쿼리 `date=YYYY-MM-DD` (선택 날짜) |
| `/g/[groupId]/events/new`, `/g/[groupId]/events/[eventId]` | 5 일정 작성/수정 | 필요 | new 는 쿼리 `start`, `end` (ISO) 로 미리 채움 |
| `/g/[groupId]/free` | 6 빈 시간 찾기 | 필요 | |
| `/g/[groupId]/anniversaries` | 7 기념일 | 필요 | |
| `/g/[groupId]/news` | 8 새 소식 | 필요 | |
| `/g/[groupId]/settings` | 9 팀 설정 | 필요 | 초대 섹션 포함 |
| `/me` | 10 내 정보 | 필요 | |
| `/terms`, `/privacy` | 11 약관, 개인정보처리방침 | 공개 | |

**공통 뼈대 (`/g/[groupId]/*`)**

| 영역 | 내용 |
|------|------|
| 상단 바 | 왼쪽: 팀 이름 + ▼ (탭하면 팀 전환 시트: 내 팀 목록, 각 팀 옆 `unreadNewsCount` 점, 맨 아래 "새 팀 만들기" → 3). 오른쪽: 새 소식 종 아이콘(배지 = 현재 팀 unreadNewsCount) → 8, 내 프로필 사진 → 10 |
| 하단 탭 | 달력(4) / 빈 시간(6) / 기념일(7) / 팀(9) |
| 팀 전환 | 선택한 groupId 로 같은 탭 경로 이동 + `wwm_group` 쿠키 갱신 |
| 403 응답 | 그 팀 멤버가 아니게 된 경우(나가기, 삭제됨). "이 팀에 더 이상 속해 있지 않아요" 토스트 후 `/` 로 |

## 2. 화면별 명세

각 화면의 **빈 상태 / 로딩 / 오류** 는 표의 마지막 세 행. 오류 문구는 API `error.message` 가 있으면 그것을 우선 보여주고, 아래는 네트워크 실패 등 message 가 없을 때의 기본값.

### 1 로그인 `/login`

| 항목 | 내용 |
|------|------|
| 구성 | 로고, 한 줄 소개("언제 볼까? 를 달력 하나로"), 카카오 로그인 버튼(#FEE500, 검정 글자, 카카오 심볼), 하단 "이용약관 · 개인정보처리방침" 링크 |
| 동작 | 버튼 → `/auth/kakao?next=<next>` (웹 route handler, 인증흐름.md 2) |
| `error` 쿼리 | `OAUTH_STATE` → "로그인 시간이 지났어요. 다시 시도해 주세요" / `KAKAO_ERROR` → "카카오 연결에 실패했어요. 잠시 후 다시 시도해 주세요" |
| 이미 로그인 | 쿠키 있으면 `next` 또는 `/` 로 바로 이동 |
| 빈 상태 | 없음 |
| 로딩 | 버튼 탭 후 비활성화 + "카카오로 이동 중…" |
| 오류 | 위 `error` 문구를 버튼 위에 표시 |

### 2 초대 수락 `/join/[code]`

| 항목 | 내용 |
|------|------|
| 진입 | 카톡으로 받은 링크. 서버 컴포넌트가 `GET /invites/:code` 로 미리보기 |
| 로그인 전 | "**{groupName}** 팀에 초대받았어요 (멤버 {memberCount}명)" + 카카오 로그인 버튼 → `/auth/kakao?next=/join/<code>` |
| 로그인 후 | 같은 카드 + "합류하기" 버튼 → `POST /api/groups/join { code }` → 성공 시 `wwm_group` 갱신 후 `/g/<id>/calendar`. 이미 멤버여도 같은 경로 |
| 빈 상태 | 코드 없음(INVITE_NOT_FOUND): "초대 링크가 만료됐거나 잘못됐어요. 초대한 사람에게 새 링크를 받아 주세요" + 홈 버튼 |
| 로딩 | 카드 자리 스켈레톤 |
| 오류 | "초대 정보를 불러오지 못했어요. 새로고침해 주세요" |

### 3 팀 만들기 `/groups/new`

| 항목 | 내용 |
|------|------|
| 구성 | 팀 이름 입력(1~30자, 자동 포커스), "만들기" 버튼. 설명 한 줄 "커플, 가족, 친구 모임 어디든 좋아요" |
| 동작 | `POST /api/groups` → `wwm_group` 갱신 → `/g/<id>/settings?invite=1` (초대 섹션이 펼쳐진 채 열림). F1 의 3탭: 로그인 → 이름 입력 → 공유 |
| 빈 상태 | 없음 |
| 로딩 | 버튼 비활성 + 스피너 |
| 오류 | 입력 아래 "팀을 만들지 못했어요. 다시 시도해 주세요" |

### 4 달력 `/g/[groupId]/calendar`

| 항목 | 내용 |
|------|------|
| 상단 | 기념일 띠: 가장 가까운 기념일 1개를 "{name} D-3" 형태로. 탭 → 7 |
| 월 그리드 | 월 이동 ◀ ▶, 오늘 버튼. 날짜 칸에 멤버 색 점(최대 3개 + "+N"). 종일 일정은 점 대신 색 막대. 오늘 테두리, 선택 날짜 채움 |
| 일 목록 | 선택 날짜의 일정을 시작 시각 순으로. 각 행: 멤버 색 세로선 + 제목 + 시간(종일은 "종일") + 등록자 이름. 탭 → 5(수정) |
| FAB | + 버튼 → `/events/new?start=<선택일 KST 10:00>&end=<11:00>` |
| 데이터 | 월이 바뀔 때 `GET /api/groups/:id/events?from=<그리드 첫 날>&to=<그리드 마지막 다음 날>` (6주 그리드 = 42일), 기념일은 `GET .../anniversaries` 1회 |
| 빈 상태 | 일 목록: "이 날은 아직 일정이 없어요. + 를 눌러 첫 일정을 추가해 보세요" |
| 로딩 | 그리드 숫자는 즉시, 점/목록 자리는 스켈레톤 |
| 오류 | 목록 자리에 "일정을 불러오지 못했어요" + "다시 시도" 버튼 |

### 5 일정 작성/수정 `/g/[groupId]/events/new`, `/g/[groupId]/events/[eventId]`

| 항목 | 내용 |
|------|------|
| 구성 | 제목(필수, 50자), 종일 토글, 시작/종료 (날짜 + 시각 피커, 종일이면 날짜만), 메모(500자), 수정 모드엔 등록자 표시와 하단 "삭제" |
| 검증(클라) | 제목 공백 불가, 종료 > 시작, 30일 이하. 위반 시 필드 아래 문구, 저장 버튼 비활성 |
| 저장 | new → `POST`, 수정 → `PATCH` → 성공 시 `/calendar?date=<시작일>` |
| 삭제 | 확인 다이얼로그 "이 일정을 삭제할까요? 팀원 모두에게서 사라져요" → `DELETE` → 달력으로 |
| 종일 변환 | 종일 ON 시 startsAt=그날 KST 00:00, endsAt=다음 날 KST 00:00 을 UTC 로 보냄 (`lib/date.ts`) |
| 빈 상태 | 없음 |
| 로딩 | 수정 모드: 폼 자리에 스켈레톤. 저장 중 버튼 비활성 |
| 오류 | 저장 실패: 상단 배너 "저장하지 못했어요. 입력 내용은 그대로 있으니 다시 저장해 주세요". 404: "이미 삭제된 일정이에요" 토스트 후 달력으로 |

### 6 빈 시간 찾기 `/g/[groupId]/free`

| 항목 | 내용 |
|------|------|
| 조건 | 기간 칩: 이번 주 / 다음 주 / 직접(시작일, 종료일, 최대 31일). 시간대 `09:00`~`23:00` (30분 단위 선택). 최소 길이 칩: 1시간 / 2시간(기본) / 3시간 / 반나절(6시간). 토글 "종일 일정도 바쁜 시간으로" (기본 꺼짐, 켜면 `includeAllDay=true`) |
| 결과 | 날짜별 묶음으로 "{요일} {M/D}" 헤더 아래 "{HH:mm}~{HH:mm} ({N}시간)" 행. 탭 → `/events/new?start=&end=` (종료는 선택 구간 전체, 폼에서 줄이면 됨) |
| 안내 | 결과 위에 "{memberCount}명 모두 비는 시간이에요. 각자 다른 팀 일정도 반영됐어요" |
| 데이터 | 조건 바뀔 때마다 `GET /api/groups/:id/free-slots?...` (300ms 디바운스) |
| 빈 상태 | "이 조건에 모두 비는 시간이 없어요. 기간을 늘리거나 최소 길이를 줄여 보세요" |
| 로딩 | 결과 자리 스켈레톤 3줄, 조건 칩은 계속 조작 가능 |
| 오류 | "빈 시간을 계산하지 못했어요. 다시 시도해 주세요" + 재시도 버튼 |

### 7 기념일 `/g/[groupId]/anniversaries`

| 항목 | 내용 |
|------|------|
| 목록 | 각 행: 이름, 날짜, D-day 배지. 탭 → 수정 시트. 상단 "+ 기념일 추가" → 추가 시트 (이름 30자, 날짜) |
| D-day 표기 (클라) | `diff = KST 오늘 - date` (일). `diff == 0` → "D-day", `diff < 0` → "D{diff}" (예 D-12), `diff > 0` → "D+{diff}". 미래 기념일이 100일 단위(100, 200, …)가 되는 날이 30일 이내면 행 아래 작은 글씨 "{N}일 까지 {M}일" |
| 정렬 | 가까운 순: 다음으로 돌아오는 날짜 기준이 아니라 `date` 오름차순 (설계 단순화, 기획에 반복 개념 없음) |
| 삭제 | 수정 시트 하단 "삭제" → 확인 없이 삭제 + 5초 "되돌리기" 토스트 (되돌리기 = 같은 값으로 다시 POST) |
| 빈 상태 | "기념일을 등록하면 달력 위에 D-day 가 보여요. 첫 기념일을 추가해 보세요" |
| 로딩 | 목록 스켈레톤 |
| 오류 | "기념일을 불러오지 못했어요" + 재시도 |

### 8 새 소식 `/g/[groupId]/news`

| 항목 | 내용 |
|------|------|
| 목록 | `GET /api/groups/:id/news` 후 즉시 `POST .../news/seen`. 각 행: 행위자 색 점 + "{displayName}님이 '{title}' 일정을 추가/수정/삭제했어요" + 일정 시각 + 상대 시간("3시간 전"). `isNew` 행은 배경 강조. 탭 → 5 (eventId 있고 DELETED 아닐 때만) |
| 배지 | 상단 바 배지는 seen 호출 성공 후 0 으로 |
| 빈 상태 | "아직 새 소식이 없어요. 팀원이 일정을 바꾸면 여기에 모여요" |
| 로딩 | 목록 스켈레톤 |
| 오류 | "새 소식을 불러오지 못했어요" + 재시도 (seen 은 호출하지 않음) |

### 9 팀 설정 `/g/[groupId]/settings`

| 섹션 | 내용 |
|------|------|
| 팀 이름 | 인라인 편집 → `PATCH /groups/:id` |
| 초대 (TEAM 만 표시) | 6자리 코드 큰 글씨, "링크 복사" (navigator.clipboard 로 inviteUrl), "카카오톡으로 공유" (navigator.share 가 있으면 share, 없으면 복사), "코드 재발급" → 확인 "이전 링크는 더 이상 쓸 수 없어요" → `POST .../invite-code`. 쿼리 `invite=1` 이면 이 섹션이 펼쳐져 있고 포커스 |
| 멤버 | 색 점 + displayName + 프로필 사진. 나는 "(나)" 표시 |
| 내 표시 | 색 팔레트(MEMBER_COLORS 8개 + 현재 값) 와 표시 이름(20자, 비우면 닉네임) → `PATCH /groups/:id/me` |
| 나가기 (TEAM 만 표시) | 하단 빨간 "팀 나가기". memberCount > 1: "나가도 내가 만든 일정은 팀에 남아요" / memberCount == 1: "마지막 멤버예요. 나가면 팀과 모든 일정이 삭제돼요". 확인 → `DELETE /groups/:id/me` → `/` |
| PERSONAL 팀 | 초대, 나가기 섹션 대신 "개인 달력은 나만 볼 수 있어요. 여럿이 쓰려면 새 팀을 만들어 보세요" + "새 팀 만들기" 버튼 |
| 빈 상태 | 없음 (멤버는 최소 1명) |
| 로딩 | 섹션별 스켈레톤 |
| 오류 | 섹션별 "저장하지 못했어요. 다시 시도해 주세요" 토스트 |

### 10 내 정보 `/me`

| 항목 | 내용 |
|------|------|
| 구성 | 프로필 사진, 닉네임(카카오 값, 수정 불가 안내 "닉네임은 카카오에서 바꿀 수 있어요"), 내 팀 목록(수) |
| 로그아웃 | `POST /auth/logout` (웹) → `/login` |
| 탈퇴 | "회원 탈퇴" → 전체 화면 확인: "개인 달력과 그 일정은 삭제되고, 다른 팀에 남긴 일정은 '탈퇴한 멤버' 로 표시돼요. 카카오 연결도 끊어져요" + 입력란에 "탈퇴" 타이핑 → `DELETE /api/me` → 쿠키 삭제 → `/login` |
| 링크 | 이용약관, 개인정보처리방침 |
| 빈 상태 | 없음 |
| 로딩 | 프로필 스켈레톤 |
| 오류 | 탈퇴 실패(KAKAO_ERROR): "카카오 연결 해제에 실패했어요. 잠시 후 다시 시도해 주세요" (계정은 그대로) |

### 11 약관, 개인정보처리방침 `/terms`, `/privacy`

| 항목 | 내용 |
|------|------|
| 구성 | 정적 마크다운 렌더. 개인정보처리방침에 수집 항목(카카오 회원번호, 닉네임, 프로필 사진), 보유 기간(탈퇴 시 즉시 삭제), 처리 위탁(호스팅) 명시. 약관에 만 14세 이상 |
| 빈 상태 / 로딩 / 오류 | 없음 (정적) |

## 3. 기획 기능 → 화면 추적

| 기획 기능 | 화면 |
|-----------|------|
| 카카오 로그인 | 1 |

| 초대 링크 + 코드, 재발급 | 9 초대 섹션, 2 |
| 팀 전환 | 공통 상단 바 |
| 월 달력 + 일 목록 | 4 |
| 일정 CRUD | 4 → 5 |
| 기념일 D-day | 7, 4 상단 띠 |
| 빈 시간 찾기 | 6 → 5 |
| 새 소식 + 배지 | 8, 공통 상단 바 |
| 멤버 색/닉네임 | 9 내 표시 |
| 팀 나가기 / 삭제 | 9 |
| 회원 탈퇴 | 10 |
| 약관/개인정보처리방침 | 11, 1 과 10 에서 링크 |
