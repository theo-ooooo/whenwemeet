## 2. API (`api.md` 2.3)

- `PUT /groups/:groupId/events/:eventId/rsvp?occurrence=` `{ status }` → `{ data: RsvpSummary }`
- `PUT /groups/:groupId/events/:eventId/reaction?occurrence=` `{ reaction }` → `{ data: ReactionSummary }`
- 대상 회차는 `EventsService.resolveTarget` (단건 GET 과 같은 회차 규칙, 반복은 occurrence 필수)
- 쓰기 `EventResponsesRepository.saveRsvp/saveReaction` 한 트랜잭션: 멤버십 `FOR SHARE OF m` → (rsvp) 일정 행 `FOR SHARE` + 참여자 확인 → 지금 값과 같으면 끝 → upsert/delete → (rsvp) 새 소식 기록
- 목록, 단건, 생성, 수정 응답에 `rsvp`, `reactions` 집계. 목록은 창 안 회차 날짜 범위로 두 테이블을 한 번씩 읽는다. 단건은 `rsvpMembers`, `reactionMembers` 추가

## 3. 일정 변경과 정리 (D-225)

| 변경 | 응답, 반응 |
|------|-----------|
| 한 번짜리 PATCH (`updateWithLogTx`) | 시작 KST 날짜로 회차 날짜 이동. 참여자를 바꾸면 빠진 사람 응답 삭제 |
| "이 일정만" 수정 | 그대로 (회차 주소 = 원래 날짜) |
| "이 일정만" 삭제 | 그 회차 삭제 |
| "이후 모두" 첫 회차 | 시작 날짜, 주기, 기준 날짜가 바뀌면 전부 삭제. 아니면 종료일 뒤만 삭제. 참여자 정리 |
| "이후 모두" 그 뒤 회차 나눔 | 시작 날짜, 주기가 같으면 그 회차 이후를 새 원본으로 이동 + 새 참여자로 정리, 아니면 삭제 |
| "이후 모두" 삭제 | 그 회차 이후 삭제. 첫 회차면 Cascade |
| 색만 나눔 (`splitSeriesQuietTx`) | 이동 |
| 팀 나가기 (`removeWithGroupPrune`) | 그 팀 일정의 내 응답, 반응 삭제 |
| 탈퇴, 일정 삭제 | Cascade |

## 4. 새 소식, 알림

- EVENT_RSVP 2분 합치기 (D-227): `GroupActivitiesRepository.listRsvpActivitiesTx` 로 같은 사람의 2분 안 기록을 읽어 같은 (eventId, occurrence) 면 `replaceTx`, 취소면 `deleteTx`
- REMINDER 펼치기 (D-228): `PushDispatcher` 가 받는 사람을 구한 뒤 `PushRepository.withoutNotGoing(recipients, eventId, occurrence)`. 예약 행의 occurrence(반복만), 없으면 일정 시작 KST 날짜

## 5. 웹 (D-229)

- `lib/rsvp.ts`: 선택지, 집계 문구, 낙관적 갱신 함수
- `hooks/useEventResponses.ts`: `useSetRsvp`, `useSetReaction`
- `components/EventResponses.tsx`: 상세의 세그먼트, 집계 줄과 사람 시트, 반응 알약
- 상세는 목록 응답의 집계로 바로 그리고 단건 GET 으로 사람 목록과 내 stale 을 받는다. 바꾸면 단건과 일정 목록(다가오는 일정의 "응답")을 다시 받는다. 빈 시간은 다시 받지 않는다
- 403 NOT_PARTICIPANT: 되돌리고 토스트 "이 일정의 참여자가 아니라서 응답할 수 없어요", 상세와 목록 새로 받기
- 목(`API_MOCK=1`): 집계, 사람 목록, PUT 두 개, 새 소식 2분 합치기. 시드는 우리 가족 팀 "가족 저녁"
