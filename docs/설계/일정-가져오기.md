# 일정 가져오기 설계 (ICS 파일, #279)

- 기획: `docs/기획/일정-가져오기.md`. 결정기록 D-160 ~ D-167
- 코드: API `apps/api/src/imports/`, 웹 `apps/web/src/screens/ImportScreen.tsx`, `lib/import-copy.ts`

## 1. 한눈에

```
웹 파일 고르기 ─ multipart ─▶ POST /groups/:id/imports/preview ─▶ parseIcs → buildCandidates → (DB: 이미 넣은 해시) → finalizePlan ─▶ 미리보기
                 (같은 파일) ─▶ POST /groups/:id/imports         ─▶ 같은 계산 → EventImport 행 → 200개씩 커밋 → GroupActivity 1줄 + 푸시 1건
```

- 서버 상태 없음: 미리보기와 넣기에서 파일을 두 번 올린다. 파일은 multer 메모리에서 읽고 버린다 (디스크, DB 어디에도 없음)
- 일정은 `EventLog` 를 남기지 않고 넣는다. 새 소식과 팀원 변경 푸시는 가져오기 한 번에 하나씩 (D-166)

## 2. 스키마 (마이그레이션 `20261111140907_event_import`, 추가형)

| 변경 | 내용 |
|------|------|

| `EventImportItem` 새 테이블 | PK (importId, uidHash), **유일 (groupId, uidHash)**, eventId(SetNull, 일정을 지워도 행은 남는다) |

## 3. 파일 읽기와 계획 (`ics-parse.ts`, `ics-time.ts`, `import-plan.ts`)

### 3-1 읽기
- ical.js 2.2.1 (MPL-2.0, 의존성 없음)로 줄, 매개변수, 이스케이프, RRULE 를 읽는다 (D-160)
- 접힌 줄은 **바이트 단계**에서 먼저 잇는다. 75 옥텟마다 접으며 한글 중간을 자르는 파일이 있다. BOM 제거, CRLF/LF 모두
- 못 읽음(빈 파일, VCALENDAR 아님, 파싱 오류), 2MB 초과 → 400 VALIDATION_FAILED `field: 'file'`. VEVENT 3,000개 초과 → 400 IMPORT_TOO_LARGE

### 3-2 시각 (D-161)
| ICS | 우리 |
|-----|------|
| `VALUE=DATE` | 종일, KST 00:00 (D-16). DTEND 없으면 하루 |
| `Z` | 그대로 |
| `TZID=<IANA>` (접두사 붙은 이름, Windows 이름 몇 개 포함) | `Intl` 로 UTC. 봄에 없는 시각은 앞으로, 가을에 두 번 있는 시각은 앞의 것 |
| `TZID=<IANA 아님>` + 파일의 VTIMEZONE | ical.js `Timezone.utcOffset` |
| 모르는 TZID | KST 로 보고 경고 `UNKNOWN_TZID` |
| 떠 있는 시각 | KST |
| `DURATION` | 시작 + 초 |
| 끝 없음, 끝 <= 시작 | 시간 일정 1시간, 종일 하루 (D-164) |

### 3-3 필드
- 제목: 공백 정리, 비면 "제목 없음", UTF-16 50자 넘으면 49자 + "…" (경고 `TRUNCATED_TITLE`)
- 메모: "장소: {LOCATION}" 첫 줄 + DESCRIPTION, 500자 넘으면 자르고 "…", 비면 null
- `STATUS:CANCELLED` 건너뜀, `TRANSP:TRANSPARENT` 는 넣는다, VALARM/ATTENDEE/첨부 무시, 알림 NONE

### 3-4 반복 (D-162, D-163)
옮기는 조건 (서머타임 없는 시간대이거나 종일, 떠 있는 시각, UTC 일 때만. RDATE 가 있거나 RRULE 이 둘이면 펼침):

| 원본 | 우리 |
|------|------|
| WEEKLY, INTERVAL 1, BYDAY 없거나 시작 요일 하나 | WEEKLY |
| 위 + INTERVAL 2 | BIWEEKLY |
| MONTHLY, INTERVAL 1, BYMONTHDAY 없거나 시작 날짜, 그날이 28일 이하 (벽시계와 KST 모두) | MONTHLY |
| YEARLY, INTERVAL 1, BYMONTH/BYMONTHDAY 가 시작 월일, 2/29 아님 | YEARLY |
| `UNTIL` / `COUNT` | 그 안 마지막 회차의 KST 날짜를 `repeatUntil` |
| 그 밖 (DAILY, 요일 여럿, 2TU, BYSETPOS, INTERVAL 3+, 29~31일 매월, 2/29 매년, 서머타임 시간대) | 펼친다 |

- 옮긴 반복의 시작은 기간 창 안 첫 회차로 당긴다 (지난 회차가 달력에 보이지 않게)
- 일정 길이 > 30일 TOO_LONG, 옮길 반복의 길이 >= 주기도 TOO_LONG. HOURLY 이하 주기는 INVALID
- EXDATE → 그 회차 `EventException(cancelled)`. RECURRENCE-ID → 시각, 제목, 메모가 다르면 예외. 앞뒤 30일 밖이면 원본 회차를 취소하고 한 번짜리로 따로 (`UID#RECURRENCE-ID`). 취소된 바뀐 회차는 취소 예외
- 펼치기: 기간 창 시작 ~ 오늘부터 366일 전까지 시작하는 회차. 바뀐 회차는 그 회차를 대신하고 EXDATE 는 뺀다
- ical.js 는 BY 없는 매월/매년의 없는 날(2/29, 31일)을 다음 달 1일로 넘겨서, 시작 날짜를 BY 로 밝혀 RFC 대로 건너뛰게 한다
- 걸음 상한: 반복 하나 2만, 파일 10만. 넘으면 그 반복 INVALID. COUNT 없는 DAILY/WEEKLY 는 주기의 배수만큼 창 40일 앞까지 당겨 돌린다

### 3-5 기간, 중복, 상한 (D-163, D-165)
- 기간 창: `future` 오늘 KST 00:00, `year` 365일 전 00:00. **끝이 그 뒤인 일정**만 (오늘 진행 중인 여러 날 일정 포함). 나머지 TOO_OLD
- 중복 키 `uidHash = SHA-256(...)`: 한 번짜리, 옮긴 반복은 `UID`, 펼친 회차는 `UID@회차 시작 ISO`, 따로 넣은 바뀐 회차는 `UID#RECURRENCE-ID ISO`, UID 없으면 `~제목|시작|끝`
- 이미 그 팀에 있는 해시, 같은 파일 안 두 번째는 DUPLICATE. 다른 팀에는 다시 넣을 수 있다
- 남은 것을 시작 순으로 1,000개까지. 넘는 것은 OVER_LIMIT (같은 파일을 다시 올리면 다음 1,000개)

## 4. 넣기 (`imports.service.ts`, `imports.repository.ts`)
1. 멤버 확인, 계획 (미리보기와 같은 계산). 넣을 게 0이면 `importId: null` 로 끝 (행을 만들지 않음)
2. `EventImport` 행 생성
3. 200개씩 한 트랜잭션: 참여자 멤버 확인(FOR SHARE, D-133) → 일정 + 예외 + 참여자 → `EventImportItem` createMany → `created += n`. EventLog, 2분 묶음 푸시(`recordChangeTx`), 알림 예약 없음
4. 동시에 같은 파일을 넣어 (팀, 해시) 유일 제약(P2002)에 걸리면 이미 들어간 것을 DUPLICATE 로 빼고 한 번 더
5. 끝: `doneAt`, 넣은 게 있으면 `GroupActivity(EVENTS_IMPORTED, { count })` + TEAM 이면 `PushNotification(kind CHANGE, dedupeKey I:{importId}, 문구 미리 만듦)` 한 트랜잭션
6. 중간 실패: 넣은 묶음은 남는다. 넣은 만큼 5를 (doneAt 없이) 시도하고 500 `IMPORT_INCOMPLETE` "N개 중 M개 넣었어요. 같은 파일을 다시 올리면 나머지만 들어가요", `details: { created, total }`

- 참여자: `participants` 생략 시 TEAM 은 ALL(`allMembers`), PERSONAL 은 ME. ME 는 요청자 한 명 행
- 푸시: 받는 사람은 그 팀의 다른 멤버 중 "팀원 변경" 과 "이 팀 알림" 이 켜진 사람. 문구 제목 "{이름}님이 일정 N개를 가져왔어요", 부제 팀 이름, 누르면 그 팀 달력. 디스패처는 `eventLogId` 없는 CHANGE 의 미리 만든 문구를 그대로 쓴다

## 5. 웹
- 팀 설정(개인 달력 포함) 오른쪽 단에 "일정 가져오기" 줄 → `/g/[groupId]/import`. 앱 셸 안이지만 fold 이상 폭 480 가운데, 폰 독과 + 는 숨긴다 (일정 작성과 같다)
- 1단계: 설명 + [파일 고르기] + "어디서 파일을 받나요?" 접힘(구글, 애플, 네이버, TimeTree). 앱 웹뷰는 `accept` 를 비워(iOS 파일 앱이 .ics 를 흐리게 보이는 문제) 고른 뒤 이름(.ics)이나 `text/calendar` 로 거른다. 2MB 넘으면 올리기 전에 막는다
- 2단계 미리보기: "42개를 넣어요" 20/700, 반복 유지와 나눔, 첫~마지막 날짜, 건너뜀 이유별 줄, 경고, 예시 5개 / 넣을 팀(select), 참여자 [모두 | 나만] (TEAM 만), 기간 [오늘 이후 | 지난 1년부터]. 팀이나 기간을 바꾸면 다시 미리보기. [{팀}에 N개 넣기]
- 3단계 완료: "42개를 넣었어요" + 건너뜀 줄 + [다른 파일 넣기] [달력 보기]
- 오류는 같은 화면 한 줄. IMPORT_INCOMPLETE 는 문구를 보이고 미리보기를 다시 불러 남은 수를 보인다
- 새 소식: `EVENTS_IMPORTED` 줄은 달력 아이콘 + "민지님이 일정 42개를 가져왔어요", 누르면 달력. 옛 웹은 모르는 type 을 거른다 (D-155)
- 지원 페이지 `/support#timetree` "TimeTree 에서 옮기기", 개인정보처리방침 1장에 한 줄
