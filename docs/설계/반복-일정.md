# 반복 일정 설계

- 이슈: #187 (기획 `docs/기획/반복-일정.md`, 2026-11-10 승인)
- 상태: 설계 승인 대기
- 결정기록: D-63 ~ D-67, D-71 (반복 기준 날짜, #228)

## 1. 한눈에

```
Event (회차 규칙을 가진 원본 1행)
  repeat       WEEKLY | BIWEEKLY | MONTHLY | YEARLY | null(한 번짜리)
  repeatUntil  'YYYY-MM-DD' (KST, 그날 시작하는 회차 포함) | null(계속)
  repeatAnchor 'YYYY-MM-DD' (KST, 매월은 일, 매년은 월일의 기준) | null(첫 회차 날짜) (#228, D-71)
  └ EventException (회차 하나의 예외, 0..N)
       occurrence  원래 회차 날짜 (KST)
       cancelled   true 면 그 회차 없음
       title/startsAt/endsAt/allDay/memo  바꾼 값 (null 은 원본 값)
```

- 회차는 **저장하지 않고 서버가 조회 기간만 펼친다** (D-63). 펼치는 함수는 API 의 순수 함수 하나(`apps/api/src/events/recurrence.ts`)이고 일정 목록, 단건, 빈 시간 찾기, 이후 푸시(#188)가 같이 쓴다
- 회차의 주소는 `(eventId, occurrence)`. 한 번짜리 일정은 `occurrence = null`
- "이후 모두" 수정은 원본을 그 전날에서 끊고 새 원본을 만든다 (D-66)

## 2. 스키마 (GATE 3 대상)

```prisma
/// (#187) 반복 주기. 기준은 첫 회차 시작일 (기획 3-1)
enum EventRepeat {
  WEEKLY
  BIWEEKLY
  MONTHLY
  YEARLY
}

/// (#187) 반복 일정의 수정/삭제 범위. 새 소식 문구용
enum EventLogScope {
  THIS
  FOLLOWING
}

model Event {
  // ... 기존 필드 그대로
  /// (#187) null 이면 한 번짜리
  repeat      EventRepeat?
  /// (#187) 반복 종료일 (KST 날짜, 그날 시작하는 회차 포함). null 이면 계속
  repeatUntil DateTime?    @db.Date
  /// (#228) 반복 기준 날짜 (KST). MONTHLY 는 일, YEARLY 는 월일. null 이면 startsAt 의 KST 날짜 (D-71)
  repeatAnchor DateTime?   @db.Date

  exceptions EventException[]

  @@index([groupId, repeat])
}

/// (#187) 반복 일정 회차 하나의 예외. "이 일정만" 수정/삭제
model EventException {
  id         Int      @id @default(autoincrement())
  eventId    Int
  /// 원래 회차 날짜 (KST). 회차를 옮겨도 이 값은 그대로
  occurrence DateTime @db.Date
  /// true 면 그 회차는 없다 (아래 값 무시)
  cancelled  Boolean  @default(false)
  /// 바꾼 값. null 이면 원본 값
  title      String?  @db.VarChar(50)
  startsAt   DateTime?
  endsAt     DateTime?
  allDay     Boolean?
  memo       String?  @db.VarChar(500)
  updatedAt  DateTime @updatedAt

  event Event @relation(fields: [eventId], references: [id], onDelete: Cascade)

  @@unique([eventId, occurrence])
}

model EventLog {
  // ... 기존 필드 그대로
  /// (#187) 변경 시점의 반복 주기 (한 번짜리면 null)
  repeat     EventRepeat?
  /// (#187) 반복 일정에서 고른 범위. 한 번짜리, 새 반복 추가는 null
  scope      EventLogScope?
  /// (#187) 범위를 고른 회차 날짜 (KST)
  occurrence DateTime?      @db.Date
}
```

- 메모를 "지우는" 예외는 `memo = ''` 로 저장한다 (null 은 "원본 값") (D-65)
- 마이그레이션은 컬럼 추가와 테이블 생성뿐. 기존 행은 `repeat = null` 로 지금과 같다. 되돌리기 쉬움
- (#228) `repeatAnchor` 는 별도 마이그레이션 `event_repeat_anchor` (`ALTER TABLE Event ADD COLUMN repeatAnchor DATE NULL`). 기존 행은 null 이라 펼친 결과가 같다

## 3. 회차 펼치기 (`recurrence.ts`, 순수 함수)

```ts
expand(series: { startsAt, endsAt, allDay, repeat, repeatUntil, repeatAnchor? }, exceptions, from, to): Occurrence[]
Occurrence = { occurrence: 'YYYY-MM-DD', startsAt, endsAt, allDay, title?, memo?, exception: boolean }
```

1. **원래 회차 날짜** 를 KST 달력으로 구한다. 첫 회차 날짜 `d0` = startsAt 의 KST 날짜
   - WEEKLY: `d0 + 7k`, BIWEEKLY: `d0 + 14k`
   - 기준 날짜 `a` = `repeatAnchor ?? d0` (D-71). 주간은 쓰지 않는다
   - MONTHLY: `d0` 의 연/월 + k, 날짜는 `min(a.일, 그달 말일)` (D-64)
   - YEARLY: `d0` 의 연 + k, 월일은 `a` 의 월일, 2/29 는 평년 2/28 (기념일 D-59 와 같은 규칙)
   - 기준이 있으면 k = 0 이 `d0` 이어야 한다 (시작 날짜 = 그 달(해)의 보정된 기준 날짜). 예: 시작 2027-02-28, 기준 2026-10-31 → 2-28, 3-31, 4-30
   - k 는 0 부터. 반복은 루프가 아니라 **조회 기간에서 k 범위를 바로 계산** (기념일 D-60 방식). WEEKLY/BIWEEKLY 는 날짜 차이 ÷ 간격, MONTHLY/YEARLY 는 월/연 차이
2. 회차 시각 = 그 날짜 + 원본의 KST 벽시계 시각, 끝 = 시작 + 원본 길이 (ms). 한국은 서머타임이 없어 고정 +09:00
3. `repeatUntil` 이 있으면 원래 회차 날짜 `<= repeatUntil` 만
4. 예외 적용: `cancelled` 면 뺀다. 아니면 null 이 아닌 값으로 덮는다
5. **최종 시각** 이 `[from, to)` 와 겹치는 것만 남긴다

예외로 회차가 앞뒤로 옮겨질 수 있어 1단계는 `[from - 31일, to + 31일)` 의 원래 날짜를 본다 (일정 길이 상한 30일 + 여유). 예외 시각은 원래 날짜 ±30일 안으로만 저장하게 막는다 (5장 검증). 그래서 빠뜨리는 회차가 없다.

상한: 조회 기간은 지금도 62일 이하라 원본 하나에 회차는 최대 WEEKLY 18개 (124일 창). 팀 일정 수 × 18 이 응답 크기 상한.

## 4. API (`api.md` 2.3 변경)

```ts
EventInput = { title, startsAt, endsAt, allDay, memo?,
               repeat?: 'WEEKLY'|'BIWEEKLY'|'MONTHLY'|'YEARLY'|null,   // 생략/null = 한 번짜리
               repeatUntil?: 'YYYY-MM-DD'|null }                       // 생략/null = 계속
Event      = 기존 Event & { repeat, repeatUntil,
               occurrence: 'YYYY-MM-DD'|null,   // 회차 날짜. 한 번짜리는 null
               seriesStartsAt: ISO|null,        // 반복이면 첫 회차 시작 (상세의 "매주 목요일" 표시용)
               repeatAnchor: 'YYYY-MM-DD'|null } // 반복 기준 날짜 (#228, D-71). 응답에만, 입력으로는 받지 않는다
```

| 메서드 | 경로 | 바뀌는 점 |
|--------|------|----------|
| GET | `/groups/:gid/events?from&to` | 반복 원본은 기간 안 회차로 펼쳐 내려준다. 각 항목이 회차 하나. `startsAt` 오름차순, 같으면 `id`. 화면 키는 `${id}:${occurrence ?? ''}` |
| POST | `/groups/:gid/events` | `repeat`, `repeatUntil` 받음. 응답은 첫 회차 |
| GET | `/groups/:gid/events/:id?occurrence=YYYY-MM-DD` | 반복이면 `occurrence` 필수 (없으면 첫 회차). 없는 회차, 취소된 회차는 404 |
| PATCH | `/groups/:gid/events/:id?occurrence=&scope=this\|following` | 아래 표 |
| DELETE | `/groups/:gid/events/:id?occurrence=&scope=this\|following` | 아래 표 |

반복 일정에서 `occurrence`, `scope` 가 없으면 400 VALIDATION_FAILED (`field: 'scope'`). 한 번짜리 일정은 둘 다 무시하고 지금과 같다.

| 동작 | 처리 (트랜잭션 1개) | 로그 |
|------|------|------|
| PATCH this | `EventException` upsert (바뀐 필드만). `repeat`, `repeatUntil` 이 본문에 있으면 400 | UPDATED, scope THIS |
| PATCH following, 첫 회차 | 원본을 그대로 수정 + 원본의 예외 전부 삭제 (D-67) | UPDATED, scope FOLLOWING |
| PATCH following, 그 뒤 회차 | 원본 `repeatUntil = occurrence - 1일`, `occurrence` 이후 예외 삭제, 새 Event 생성 (원본 값 + 본문, 시작은 그 회차의 **규칙 자리**(예외 적용 전) 기준, `creatorId` 는 원본 등록자, 기준 날짜는 아래) | UPDATED, scope FOLLOWING, `eventId` = 새 원본 |
| DELETE this | `EventException` upsert `cancelled = true` | DELETED, scope THIS |
| DELETE following, 첫 회차 | 원본 삭제 (예외 cascade) | DELETED, scope FOLLOWING |
| DELETE following, 그 뒤 회차 | 원본 `repeatUntil = occurrence - 1일`, 이후 예외 삭제 | DELETED, scope FOLLOWING |

- 응답: PATCH 는 수정된 그 회차 (following 그 뒤 회차면 새 원본의 첫 회차). DELETE 는 `{ ok: true }`
- 같은 값이면 저장하지 않는 규칙(#62)은 THIS 에도 적용 (예외가 원본과 같은 값이 되면 예외 행을 지운다)
- PATCH following 에서 시작 시각을 바꾸면 새 원본의 첫 회차 시각이 된다. 날짜를 바꾸면 요일, 날짜 기준도 따라 바뀐다 (새 원본이므로)
- (#228, D-71) PATCH following 의 기준 값은 그 회차의 **규칙 자리**(원래 회차 날짜 + 원본 시각, 말일 보정 그대로, "이 일정만" 예외 적용 전) + 본문. "이 일정만" 은 지금처럼 그 회차의 현재 값(예외 반영) + 본문
- (#228, D-71) 날짜를 바꾸지 않은 "이후 모두" (본문에 `startsAt` 이 없거나 그 KST 날짜가 원래 회차 날짜) 는 규칙을 잇는다:
  - 그 뒤 회차: 새 원본이 규칙 자리에서 시작하고, 주기가 그대로인 매월/매년이면 `repeatAnchor = 원본.repeatAnchor ?? 원본 시작 KST 날짜`. 매월 31일을 2/28 회차에서 나눠도 3-31, 4-30 이 그대로, 매년 2/29 를 2027-02-28 에서 나눠도 2028-02-29
  - 첫 회차: 원본의 `repeatAnchor` 그대로
  - 날짜나 주기를 바꾸면 `repeatAnchor = null` (새 시작 날짜가 기준). 주간은 항상 null
  - 기준이 있으면 시작 날짜가 그 달(해)의 보정된 기준 날짜여야 한다. 아니면 EVENT_RANGE_INVALID "반복 기준 날짜와 시작 날짜가 맞지 않아요" (서버가 정하는 값이라 정상 흐름에선 나오지 않는 방어 검사)
  - 웹은 "이후 모두" 에서 시작, 종료를 불러온 값 그대로 두면 `startsAt`, `endsAt` 을 빼고 보낸다. 옮긴 회차("이 일정만")에서 제목만 고쳐도 원래 요일에서 잇는다
- `occurrence` 는 실제로 있는 회차여야 한다 (규칙상 날짜가 아니거나 `repeatUntil` 뒤, 또는 이미 취소면 404)

### 4-1 검증 (EVENT_RANGE_INVALID 계열)

| 조건 | 오류 | 문구 |
|------|------|------|
| 길이 ≥ 주기 (WEEKLY 7일, BIWEEKLY 14일, MONTHLY 28일, YEARLY 365일) | EVENT_RANGE_INVALID | 반복 간격보다 긴 일정은 반복할 수 없어요 |
| `repeatUntil` < 첫 회차 날짜 | EVENT_RANGE_INVALID | 종료 날짜는 시작 날짜 뒤여야 해요 |
| `repeatUntil` 만 있고 `repeat` 없음 | VALIDATION_FAILED | - |
| THIS 예외 시각이 원래 회차 날짜 ±30일 밖 | EVENT_RANGE_INVALID | 이 회차는 앞뒤 30일 안으로만 옮길 수 있어요 |
| `repeatAnchor` 가 있는데 시작 날짜가 그 달(해)의 보정된 기준 날짜가 아님 (#228) | EVENT_RANGE_INVALID | 반복 기준 날짜와 시작 날짜가 맞지 않아요 |
| 기존 규칙 (종료 > 시작, 30일 이하) | 그대로 | 그대로 |

### 4-2 빈 시간 찾기 (`api.md` 2.5)
3번 조회를 둘로 나눈다. **select 는 여전히 시각과 반복 필드만** (D-14 유지).
- 한 번짜리: 지금 쿼리 + `repeat: null`
- 반복: `groupId in allGroupIds, repeat != null, startsAt < to + 31일, (repeatUntil null 또는 repeatUntil >= from - 31일)` + 그 원본들의 `EventException` (시각, cancelled 만)
- 펼친 회차를 busy 에 합친 뒤 4번 병합부터 그대로. DB 조회 3번 → 4번

### 4-3 새 소식 (`api.md` 2.6)
`NewsItem` 에 `repeat`, `scope`, `occurrence` 추가. 문구는 웹이 조합 (기획 3-6):

| action | scope | 문구 |
|--------|-------|------|
| CREATED | null, repeat 있음 | "매주 반복 일정을 추가했어요" |
| UPDATED | THIS | "11월 18일 일정만 수정했어요" |
| UPDATED | FOLLOWING | "11월 18일부터 반복 일정을 수정했어요" |
| DELETED | THIS | "11월 18일 일정을 삭제했어요" |
| DELETED | FOLLOWING | "11월 18일부터 반복을 삭제했어요" |

로그의 `startsAt`, `endsAt` 스냅샷은 그 회차 값. 새 소식에서 누르면 `/events/:id?occurrence=` 로 (DELETED 는 이동 없음, 지금 규칙).

## 5. 웹

| 위치 | 변경 |
|------|------|
| `lib/api` 타입 | `Event` 에 `repeat`, `repeatUntil`, `occurrence`, `seriesStartsAt`. 목록 키 `${id}:${occurrence}` |
| 일정 작성 폼 | 시각 아래 "반복" 줄 (Segmented 대신 목록 시트: 반복 안 함/매주/격주/매월/매년). 반복을 고르면 "종료" 줄 (계속 / 날짜까지 + 날짜 피커). 클라 검증은 4-1 앞 두 줄 |
| 일정 상세/수정 `/events/[id]?occurrence=` | 반복 설명 한 줄 ("매주 목요일", "격주 목요일", "매월 31일", "매년 5월 5일", 종료 있으면 다음 줄 "12월 31일까지"). 설명 문자열은 `lib/recurrence-label.ts` 순수 함수 + 테스트 |
| 저장/삭제 | 반복이면 기존 Sheet 로 "이 일정만" / "이후 모두" / 취소. 삭제 시트는 danger 색. "이후 모두" 를 고르고 그 뒤에 예외가 있으면 확인 문구 "이후 따로 바꾼 회차도 새 값으로 바뀌어요" (서버가 예외 존재 여부를 `GET` 응답 `hasLaterExceptions` 로 준다) |
| "이 일정만" 수정 화면 | 반복 줄을 숨긴다 |
| 달력, 날짜 상세, 다가오는 일정 | 회차를 다른 일정과 똑같이 그린다 (아이콘 없음). 링크에 `occurrence` |
| 새 소식 | 4-3 문구 |
| 빈 시간 찾기 | 변경 없음 (서버가 반영) |

`hasLaterExceptions` 는 단건 GET 에만 둔다 (`Event` 응답 필드, 목록에서는 생략).
