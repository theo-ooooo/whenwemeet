# 약속 투표 설계

- 이슈: #189, 기획 `docs/기획/약속-투표.md`
- 결정: D-234 ~ D-241
- 작성: 2026-11-13

## 1. 데이터 (`schema.prisma`)

```prisma
enum PollStatus { OPEN CLOSED }

model Poll {
  id                 Int        @id @default(autoincrement())
  groupId            Int
  publicCode         String     @unique @db.Char(8)   // /polls/<code> (#311 과 같은 규칙)
  title              String     @db.VarChar(50)       // 정하면 일정 제목
  status             PollStatus @default(OPEN)
  deadline           DateTime?
  allMembers         Boolean    @default(true)        // 일정 참여자 D-130 과 같은 규칙
  creatorId          Int?                             // 탈퇴 SetNull
  eventId            Int?       @unique               // 정해서 생긴 일정. 일정 삭제 SetNull
  decidedOptionId    Int?                             // 정한 후보 (FK 없음)
  deadlineNotifiedAt DateTime?                        // 마감 알림 예약 표시 (한 번만)
  createdAt          DateTime   @default(now())
  closedAt           DateTime?
  @@index([groupId, status])
  @@index([status, deadline])
}
model PollOption      { id, pollId, startsAt, endsAt, allDay   @@unique([pollId, startsAt, endsAt]) }   // Cascade
model PollVote        { optionId, userId, createdAt             @@id([optionId, userId]) }              // 행 = "가능"
model PollParticipant { pollId, userId                          @@id([pollId, userId]) }                // allMembers = false 일 때만
```

- `User.notifyPoll Boolean @default(true)` (#369 에서 `NotificationPreference(kind POLL)` 행으로 옮김, D-249), `GroupActivityType` 에 `POLL_CREATED`, `POLL_CLOSED`, `PushKind` 에 `POLL`
- 마이그레이션 `20261113050347_polls`: 테이블 4개 생성, `User` 열 하나, enum 두 개 `MODIFY`(GroupActivity.type, PushNotification.kind). enum 변경은 테이블 ALTER 라 릴리스 전 운영 백업 (`docs/운영/배포.md`)
- 이슈 초안에 없던 것: `publicCode`(주소, D-237), `decidedOptionId`(정한 뒤 화면에 정한 시간을 보이려고. 일정은 나중에 바뀔 수 있다, D-240)
- 팀 삭제 Cascade. 탈퇴: 표, 대상 행 Cascade, `creatorId` SetNull = "탈퇴한 멤버". 나가기: 그 팀 투표의 내 표, 대상 행을 나가기 트랜잭션에서 지운다(기록 없음, D-240)

## 2. API (api.md 2.13)

| 메서드 | 경로 | 요청 | 응답 `data` |
|--------|------|------|------------|
| GET | `/groups/:groupId/polls` | `?status=open\|closed` (기본 open) | `PollSummary[]`. 진행 중: 고를 후보가 남은 것 먼저, 마감 가까운 순(없음은 뒤), 최근 연 순. 닫힌 것: 최근 30일, 최근 닫힌 순 |
| POST | `/groups/:groupId/polls` | `PollInput` | 201 `Poll` |
| GET | `/polls/:code` | - | `Poll`. 틀린 코드, 없는 투표, 비멤버 모두 404 |
| PUT | `/groups/:groupId/polls/:pollId/votes` | `{ optionIds: number[] }` (내 "가능" 전체, `[]` = 다 해제) | `Poll` |
| POST | `/groups/:groupId/polls/:pollId/confirm` | `{ optionId }` | 201 `{ poll: Poll, event: Event, warning: 'BUSY_NOW' \| null }` |
| DELETE | `/groups/:groupId/polls/:pollId` | - | `{ ok: true }` |

- 이슈 초안의 `GET /groups/:groupId/polls/:pollId` 는 두지 않고 공개 코드 조회로 대신한다 (주소에 팀이 없어 서버가 코드로 팀을 찾아야 한다. 할 일 목록 D-206 과 같은 이유, D-237)
- 검증: 개인 팀 400, 제목 1~50자(앞뒤 공백 자름), 후보 2~5개, 각 후보 `endsAt > startsAt`, 30일 이하, 시작이 지금 이후, 같은 구간 중복 없음, 종일 후보는 KST 00:00 경계, 마감은 지금 이후, 참여자는 일정과 같은 형식(생략 = `'ALL'`, 일정과 달리 기본이 "모두")이고 멤버 검사는 쓰기 트랜잭션 안(D-133). 진행 중 10개 상한(팀 행 `FOR UPDATE` 후 셈)
- 표: 닫힘 409 `POLL_CLOSED` "이미 정해진 투표예요", 마감 지남 409 `POLL_CLOSED` "투표가 끝났어요", 대상 아님 403 `NOT_PARTICIPANT` "이 투표의 대상이 아니에요", 남의 후보 400(field `optionIds`). 지난 후보는 새로 켜면 400 `POLL_OPTION_PAST`, 이미 켜 둔 표는 빠져도 지우지 않는다 (D-238)
- 정하기: 닫힘 409, 남의 후보 400, 지난 후보 400 `POLL_OPTION_PAST`. 마감 뒤에도 된다. 권한은 팀원 누구나 (D-234)
- 취소: 진행 중만. 닫혔으면 409 `POLL_CLOSED` (D-240)

## 3. 규칙

| 항목 | 규칙 |
|------|------|
| 마감 (D-235) | `expired = status OPEN AND deadline <= now` 를 읽을 때 계산한다(상태 값을 바꾸지 않음). 마감 뒤에는 표만 막고 정하기, 취소는 된다. 자동으로 정하지 않는다 (Q3) |
| 대상 | "모두" 면 지금 멤버 전원(나중에 들어온 사람 포함), 아니면 대상 행. 대상이 아닌 팀원은 결과만 본다 |
| 지난 후보 | `startsAt <= now`. 고를 수도 정할 수도 없고 화면에서 흐리게. 모든 후보가 지나면 목록에서 `allPast`("지난 투표") 로 맨 뒤 |
| 응답 수 | `voterCount` = 대상 중 한 후보라도 가능이라고 한 사람 수, `targetCount` = 대상 수 |

## 4. 정하기 (D-239)

한 트랜잭션:
1. `UPDATE Poll SET status = CLOSED, closedAt, decidedOptionId WHERE id AND status = OPEN`. 0행이면 롤백하고 409 (동시에 눌러도 하나만 성공)
2. 일정 + EventLog CREATED (`EventsRepository.createWithLogInTx`). 제목 = 투표 제목, 시각 = 후보, 참여자 = 투표 대상 설정(모두면 모두, 아니면 지금 대상 멤버), `reminder` NONE, 등록자 = 정한 사람. 팀원 변경 알림(CHANGE)은 만들지 않는다
3. `Poll.eventId`, GroupActivity `POLL_CLOSED`(payload 에 `eventLogId`), 정함 알림 예약

트랜잭션 전에 대상 멤버가 그 시간에 바쁜지 빈 시간 찾기와 같은 규칙(`FreeSlotsService.anyBusy`: 멤버들의 모든 팀, 참여자로 거름, 종일 일정 제외)으로 본다. 바쁘면 `warning: 'BUSY_NOW'` 만 싣고 그대로 정한다(사람의 판단이 우선). 종일 후보는 보지 않는다(빈 시간 결과에서 나오지 않는 직접 추가 후보라 거의 늘 겹친다).

## 5. 화면

| 화면 | 주소 | 내용 |
|------|------|------|
| 빈 시간 선택 모드 | `/free` | 결과 설명 줄 오른쪽 "투표로 정하기" 글자 버튼(팀이고 멤버 2명 이상, 결과가 있을 때). 누르면 결과 줄 왼쪽 체크 상자(22, 모서리 7), 2~5개. 6번째는 토스트. 아래 고정 줄 "후보 N개로 투표 만들기"(폰은 독 위, 넓은 화면은 결과 칸 아래 sticky). 다시 누르면 "그만 고르기" |
| 만들기 시트 | 시트 | 제목(정하면 일정 이름) → 후보(구간이 최소 길이보다 길면 구간 안 시작 시각 피커, 길이는 최소 길이, × 로 빼기) + "직접 추가"(날짜, 종일 토글, 시작~끝) → 마감 세그먼트(없음 / 내일 이맘때 30분 올림 / 직접 날짜, 시각) → 대상 줄(일정 참여자 시트 재사용, 기본 모두) → [투표 만들기]. 만들면 투표 화면으로 |
| 투표 화면 | `/polls/<code>` | 머리줄 ‹ + 제목 + ⋯(투표 취소, 진행 중만). 아래 "민지님이 연 투표, 11월 14일 (토) 오후 9:00까지". 상태 카드(응답 수 / 마감 / 대상 아님 / 정한 시간). 후보 카드: 날짜 12/600(+ "가장 많아요" `--acc-ink`, "지난 시간"), 시각 15/600, 가능한 사람 아바타 20 + 이름, 오른쪽 "가능" 알약 44(켜면 `--btn` 면 + 체크). 카드 왼쪽을 누르면 정할 후보로 고름(먹색 2px 테두리, `aria-pressed`), 표가 가장 많은 후보가 하나면 처음부터 골라져 있다. 맨 아래 전체 폭 "이 시간으로 정하기"(고르기 전 "정할 시간을 골라 주세요"), 정한 뒤 "일정 보기". 폰은 독과 + 를 숨긴다 |
| 정하는 중 (폰 홈) | `/calendar` | "다가오는 일정" 위. 진행 중 투표가 있을 때만(Q5). 가로 카드 148×108: 제목 15/600 두 줄, 응답 수 12 `--mute`, 마감 12/600 `--acc-ink`(지난 투표는 흐리게 "지난 투표") |
| 사이드바 (≥600) | - | "다가오는 일정" 묶음 위 한 줄: 투표 아이콘 18 + 가장 급한 투표 제목 + "외 N개" + 마감 또는 응답 수. 없으면 그리지 않는다 |
| 새 소식 | `/news` | "민지님이 '저녁 약속' 투표를 열었어요" → 투표 화면, "지훈님이 '저녁 약속' 시간을 정했어요" + 둘째 줄 정한 시간 → 그 일정. 투표 아이콘 |
| 알림 설정 | `/me/notifications` | "약속 투표" 토글(기본 켬) |

- 표는 낙관적으로 먼저 그리고 저장한다. 실패하면 되돌리고 토스트. 409 는 다시 불러오고 서버 문구(먼저 정해졌으면 "이미 정해졌어요")
- 정하기: 연 사람이 아니면 확인 창 "이 시간으로 정할까요?"(Q2). 성공하면 토스트("일정을 만들었어요", BUSY_NOW 면 "그 사이 이 시간에 일정이 생긴 사람이 있어요. 일정은 만들었어요") 후 일정 상세로
- 아이콘 `IconPoll`: 둥근 사각 둘이 겹치고 앞 사각에 체크, 겹침 조각은 겹친 자리 (디자인규칙 3-2)
- 팀 전환: `/polls/<code>` 는 팀 화면 목록 밖이라 달력으로 (`afterTeamSwitch`)
- 목 모드(`API_MOCK=1`): 같은 엔드포인트, 우리 가족 팀에 진행 중 투표 하나 시드

## 6. 알림 (D-241)

| 단계 | dedupeKey | 예약 | 받는 사람 (펼칠 때) | 문구 |
|------|-----------|------|------|------|
| 열림 | `PO:{pollId}` | 만들기 트랜잭션, 바로 | 대상 중 연 사람 제외. 투표가 진행 중일 때만 | `{이름}님이 '{제목}' 시간을 묻고 있어요` / `후보 N개, 마감 11월 14일 (토) 오후 9:00` → 투표 화면 |
| 마감 | `PD:{pollId}` | 틱이 마감 지난 투표를 집어 `deadlineNotifiedAt` 표시와 함께, 예약 시각 = 마감 | 연 사람 한 명. 아직 진행 중일 때만 | `'{제목}' 투표가 끝났어요` / `시간을 정해 주세요` → 투표 화면 |
| 정함 | `PC:{pollId}` | 정하기 트랜잭션, 바로 | 대상 중 정한 사람 제외, 정한 시각까지 들어와 있던 팀원(D-180) | `{이름}님이 '{제목}' 시간을 정했어요` / `11월 22일 (토) 오후 7:00` → 일정 |

- 종류 설정 `notifyPoll`(#369 부터 `NotificationPreference` POLL), 팀 설정 `notify` 를 따른다. 문구는 예약할 때 만든다(가져오기 D-166 과 같은 방식). 만료는 열림 = 24시간과 마감 중 이른 쪽(최소 10분), 그 밖 24시간
- 마감 처리는 기존 30초 틱(D-87) 안 `PollPlanner`. `status = OPEN AND deadline <= now AND deadlineNotifiedAt IS NULL` 한 번 조회, 투표마다 조건부 `UPDATE ... deadlineNotifiedAt` 1행일 때만 예약. 틱이 꺼져 있던 동안 지난 마감은 예약 시각이 마감이라 펼칠 때 10분 규칙(D-88)으로 SKIPPED
- 취소한 투표의 열림 알림은 투표가 없어 펼칠 때 SKIPPED

## 7. 테스트

- API 단위: `poll-rules.spec.ts`(후보 검사, 마감, 표 계획, 보기, 정렬), `polls.service.spec.ts`(권한, 409, 대상, BUSY_NOW, 종일, DTO), `poll-planner.spec.ts`, 푸시 문구, 펼치기 3단계, 새 소식 숨김, 안 읽은 수
