# 외부 캘린더로 내보내기 (ICS 구독)

- 이슈: #193 (로드맵 #205 P2). 읽기 전용 내보내기만. 가져오기는 #279(`일정-가져오기.md`)
- 결정: D-217 ~ D-221. API: api.md 2.12

## 1. 범위

| 포함 | 제외 |
|------|------|
| 팀 설정 "다른 캘린더 앱에서 보기": 연결 주소 만들기, 아이폰 캘린더에 추가, 주소 복사(구글은 붙여 넣기 안내), 메모, 기념일 토글, 주소 다시 만들기, 연결 끊기 | 외부에서 고친 내용 되받기(양방향) |
| 공개 피드 `GET /v1/ics/:token.ics` (RFC 5545) | 여러 팀을 한 주소로 (D-32, 팀마다 주소 하나) |
| 그 팀 일정 전부(반복 펼침, 예외 반영), 기념일(토글) | 일정 한 건 `.ics` 내보내기, CalDAV |

## 2. 데이터

`CalendarFeed` (schema.prisma, 마이그레이션 `20261113022150_calendar_feed`, 추가형 테이블 1개)

| 열 | 뜻 |
|----|----|
| `userId`, `groupId` | (사용자, 팀) 하나에 하나 (`@@unique`). 같은 팀 다른 멤버는 자기 주소를 따로. 탈퇴, 팀 삭제는 Cascade |
| `tokenSalt` | 16바이트 랜덤 base64url 22자. 재발급 = 교체 |
| `tokenHash` | sha256(토큰) hex, `@unique`. 공개 피드가 이 값으로 행을 찾는다 |
| `includeMemo` | 기본 false (Q2) |
| `includeAnniversaries` | 기본 true (Q3) |
| `lastFetchedAt` | 외부 캘린더가 마지막으로 가져간 시각. 1분에 한 번만 쓴다 |

토큰 = `base64url(HMAC-SHA256(HKDF(JWT_SECRET, "wwm-ics-feed"), "<userId>:<groupId>:<tokenSalt>"))` 43자(256비트). DB 에는 토큰이 없다. 설정 화면이 주소를 다시 보여 줄 때는 서버가 소금으로 다시 만든다(D-218).

팀 나가기(`removeWithGroupPrune`)는 같은 트랜잭션에서 그 사람의 그 팀 행을 지운다. 피드는 요청마다 멤버십을 다시 본다(정리 순서와 무관하게 막힘).

## 3. 피드

**창**: 오늘(KST) 기준 과거 60일 ~ 미래 400일(Q7). 일정 조회는 `[첫날 00:00, 마지막 날 다음 날 00:00)`, 반복은 `EventsService.listForFeed`(목록과 같은 `expand`, 62일 상한 없음).

**반복은 회차마다 VEVENT 하나**(RRULE 없음). 우리 매월 규칙은 없는 날이면 말일(D-64), 기준 날짜(D-71), "이 일정만" 예외가 있어 RRULE + EXDATE + RECURRENCE-ID 로는 클라이언트마다 다르게 보인다. "계속" 반복은 400일 끝에서 잘리고 창이 매일 앞으로 간다.

| 우리 | ICS |
|------|-----|
| 머리 | `PRODID:-//whenwemeet.day//whenwemeet calendar feed 1.0//KO`, `METHOD:PUBLISH`, `X-WR-CALNAME`/`NAME: 언제볼까 - {팀 이름}`, `X-WR-TIMEZONE:Asia/Seoul`, `REFRESH-INTERVAL;VALUE=DURATION:PT1H`, `X-PUBLISHED-TTL:PT1H` |
| UID | 한 번짜리 `e{id}@whenwemeet.day`, 회차 `e{id}-{YYYYMMDD 원래 날짜}@whenwemeet.day` ("이 일정만" 으로 옮겨도 같다). 기념일 `a{id}-{YYYYMMDD}@whenwemeet.day` |
| 시간 일정 | `DTSTART`/`DTEND` UTC(`...Z`). VTIMEZONE 없음 |
| 종일 | `DTSTART;VALUE=DATE` = 시작 KST 날짜, `DTEND;VALUE=DATE` = (끝 순간 바로 앞의 KST 날짜) + 1일(배타). 여러 날 같은 규칙 |
| 제목 | `SUMMARY` (예외 제목 반영) |
| 설명 | 첫 줄 `참여: 민지, 지훈`(모두면 `참여: 모두`, 참여자 없음이면 줄 없음, 개인 팀은 줄 없음). 메모는 `includeMemo` 일 때만, 빈 줄 하나 띄우고 |
| 상세 | `URL:{WEB_ORIGIN}/events/<일정 코드>?team=<팀 코드>[&occurrence=]` (D-198) |
| 개정 | `DTSTAMP` = `LAST-MODIFIED` = 일정 `updatedAt`(요청 시각이 아니라 본문이 같으면 같은 값), `SEQUENCE` = 2020-01-01 부터 센 `updatedAt` 초 |
| 기념일 | 하루에 우선순위 첫 항목 하나(`anniversaryItemsOn`, D-92)를 종일 VEVENT 로. 제목 "이름 300일", "이름 1주년", 원래 날짜와 매년은 이름만. `TRANSP:TRANSPARENT` |
| 멤버 생일 (#305, D-227) | "기념일 포함" 이면 이 팀에 보이는 멤버 생일을 창 안의 해마다 종일 VEVENT "민지 생일" 로(2월 29일은 평년 2월 28일). UID `b{userId}-{YYYYMMDD}@whenwemeet.day`, 개정은 `User.updatedAt`, `TRANSP:TRANSPARENT` |
| 알림 | `VALARM` 없음 (푸시가 있다) |

**텍스트**: CRLF, 75 옥텟 접기(코드 포인트 단위라 한글, 이모지를 가르지 않음), `\` `;` `,` 줄바꿈 이스케이프, 탭 밖 제어 문자 제거 (`calendar-feed/ics.ts`).

**응답**: `200 text/calendar; charset=utf-8`, `ETag` = 본문 sha256, `If-None-Match` 가 같으면 304, `Cache-Control: private, max-age=900`, `X-Robots-Tag: noindex`, `Referrer-Policy: no-referrer`. 실패는 본문 없는 상태 코드(404, 429 + `Retry-After`, 500).

## 4. 화면

**용어(제품 결정)**: 화면 문구에 "구독" 을 쓰지 않는다(유료 구독으로 읽힘). 주소는 "연결 주소". 코드, API, 이 문서의 기술 용어(ics, feed, token)는 그대로.

팀 설정 오른쪽 단(이 팀에서 내 표시 → 이 팀 알림 → **다른 캘린더 앱에서 보기** → 일정 가져오기 → 나가기). 폰은 같은 순서 1단. 개인 달력에도 같은 칸("내 일정" 문구). 컴포넌트 `components/CalendarFeedSection.tsx`, 문구와 판정 `lib/calendar-feed.ts`(`FEED_COPY`), 훅 `hooks/useCalendarFeed.ts`.

| 상태 | 모양 |
|------|------|
| 꺼짐 | "구글 캘린더, 아이폰 캘린더에 이 팀 일정이 보여요. 보기만 되고, 고치는 건 언제볼까에서 해요." + (팀만) "팀원 누구나 자기 연결 주소를 만들 수 있어요"(Q6) + 보조 버튼 [연결 주소 만들기] |
| 고지 시트 | 만들 때마다. 제목 "연결 주소를 만들까요?", 세 줄(주소를 아는 누구나 제목, 시간, 참여자 이름을 볼 수 있음, 보내지 말 것 / 메모는 나가지 않음 / 보이기까지 몇 시간, 보기만 되고 고치는 건 언제볼까에서) + 주 버튼 [만들기] |
| 켜짐 | 한 줄 고지 → [아이폰 캘린더에 추가](webcal, 애플 기기만) [주소 복사](https, 토스트 "연결 주소를 복사했어요") + 안내 "구글 캘린더 > 다른 캘린더 + > URL로 추가에 붙여 넣으세요"(폰이면 "구글 캘린더는 컴퓨터에서만 추가할 수 있어요") → 토글 "메모 포함"(켤 때 확인 "메모도 보이게 할까요?"), "기념일 포함" → "마지막으로 가져간 시간: 3시간 전" / "아직 가져가지 않았어요", "다른 캘린더 앱에는 몇 시간 뒤에 반영될 수 있어요" → 글자 버튼 "주소 다시 만들기"(먹색 확인 "지금 주소는 바로 끊겨요"), "연결 끊기"(`--danger`, 빨강 확인) |

- 아이폰 버튼은 iPhone, iPad, Mac(앱 셸은 UA 의 `(ios)`)에서만. Android, 윈도우는 webcal 을 받을 앱이 없을 수 있다. 서버 렌더는 숨긴 채 시작
- 구글은 바로가기 버튼 대신 붙여 넣기 안내(앱에서는 URL 추가가 안 되고 컴퓨터 웹에서만 된다). API 의 `googleAddUrl` 은 남겨 둔다
- 앱 셸: `webcal://` 은 `decideNavigation` → `external` 로 OS 에 넘어간다. 네이티브 변경 없음
- 코랄 주 버튼은 시트의 [만들기] 하나(디자인규칙 1-3). 칸 안 버튼은 보조
- 실패: 지금 팀 설정과 같은 토스트("저장하지 못했어요. 다시 시도해 주세요"), 토글은 되돌림

## 5. 남은 확인 (출시 전)

- 실기기 구독: 구글 캘린더 웹, iPhone 캘린더(webcal 구독 창), Mac 캘린더, 삼성 캘린더(안 되면 "구글 캘린더에 구독하면 삼성 캘린더에도 보여요" 안내 추가)
- 외부 검증기(icalendar.org validator)로 표본 피드 확인. 저장소 테스트는 ical.js 파싱까지
- 운영 `API_PUBLIC_ORIGIN` (없으면 운영 기본 `https://api.whenwemeet.day`)
- 운영 백업 후 마이그레이션 배포
