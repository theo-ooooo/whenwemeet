# 스토어 제출 절차 (#96, 앱 기획 P6)

App Store 와 Google Play 에 "언제볼까 - 같이 쓰는 달력" 을 올리는 순서와 콘솔에 넣을 답. 붙여 넣을 문구는 `docs/운영/스토어-문구.md`, 이미지는 `docs/store/`. 빌드와 서명은 `docs/운영/앱-빌드.md`.

출시 순서(합의): 웹 먼저 공개 → Google Play 비공개 테스트(12명, 14일) 바로 시작 → iOS 는 TestFlight 확인 후 심사 제출.

### 1.8 수출 규정
`ITSAppUsesNonExemptEncryption: false` 가 `app.config.ts` 에 이미 있다. 업로드한 빌드에 "수출 규정 정보 누락" 경고가 뜨지 않는다. 혹시 물으면 "표준 암호화(HTTPS)만 사용, 면제 대상" 으로 답한다.

## 2. iOS 빌드와 TestFlight

```bash
cd apps/mobile
eas build -p ios --profile production       # 빌드 번호는 EAS 가 올린다 (autoIncrement)
eas submit -p ios --latest                  # App Store Connect API 키는 처음에 EAS 가 만들고 보관
```

1. App Store Connect > TestFlight 에 빌드가 "처리 중" → "테스트 준비 완료" (10~30분)
2. 내부 테스트 그룹에 본인 Apple ID 추가 → TestFlight 앱으로 설치
3. `앱-빌드.md` 11장 확인 목록을 실기기에서 돌린다. 특히 카카오톡 로그인, 애플 로그인, 메모 앱에서 `https://whenwemeet.day/join/<코드>` 탭, 내 정보 > 사진 > 사진 찍기(#149)
4. 이상 없으면 1.6 에서 이 빌드를 고르고 "심사에 추가"

카카오 iOS 플랫폼 등록: 카카오 개발자센터 > 내 애플리케이션 > 앱 설정 > 플랫폼 > iOS 에 번들 ID `day.whenwemeet.app`. 이미 했다면 넘어간다 (설계 앱.md 12장 7번). 빠지면 카카오톡 로그인이 "등록되지 않은 번들 ID" 로 실패한다.

## 3. 심사용 계정

| 스토어 | 심사자 로그인 수단 | 준비 |
|--------|------------------|------|
| App Store | Sign in with Apple (심사자 본인 계정) | 없음. 카카오 계정은 선택 |
| Google Play | **카카오만** (Android 앱은 애플 버튼을 숨긴다, #145) | **카카오 테스트 계정 필수** |

카카오 테스트 계정 만들기 (사용자):
1. 심사 전용 카카오 계정을 새로 만든다 (이메일 가입. 전화번호 인증이 필요하면 본인 번호 사용)
2. 카카오 계정 설정에서 2단계 인증을 끈다. 해외(심사자 위치)에서 처음 로그인하면 추가 인증을 요구할 수 있으니, 심사 기간에는 그 계정의 새 기기 로그인 알림을 확인할 수 있게 둔다
3. 언제볼까에 한 번 로그인해서 팀 "심사용" 을 만들고 일정 3~4개, 기념일 1개를 넣어 둔다 (심사자가 빈 화면을 보지 않게)
4. 계정과 비밀번호는 저장소와 문서에 적지 않고 각 콘솔 입력칸에만 넣는다

카카오톡 앱이 없는 심사 기기에서는 카카오 SDK 가 시스템 브라우저로 카카오 계정 로그인을 띄운다. 이메일과 비밀번호로 로그인된다.

### 4.3 콘텐츠 등급 (IARC 질문지)
- 카테고리: "참고, 뉴스 또는 교육" 이 아니라 **"유틸리티, 생산성, 통신 또는 기타"**
- 폭력, 성적 콘텐츠, 언어, 규제 약물, 도박: 전부 아니요
- 사용자 간 상호작용 또는 콘텐츠 교환: **예** (초대받은 팀 멤버끼리 일정 공유)
- 사용자 위치 공유: 아니요 / 디지털 상품 구매: 아니요 / 웹 브라우저 또는 검색 엔진: 아니요
- 예상 결과: 전체이용가(또는 3+) + "사용자 상호작용" 표시

### 4.4 타겟층과 콘텐츠
- 타겟 연령: **16~17세, 18세 이상** (추천). 약관이 만 14세 이상이지만 13~15세를 고르면 아동 관련 추가 질문과 정책 검토가 붙는다. 13세 미만은 고르지 않는다 (가족 정책 대상)
- 아동에게 호소력이 있는가: 아니요

### 4.8 첫 AAB 업로드와 Play 앱 서명

```bash
cd apps/mobile
eas build -p android --profile production   # AAB, EAS 업로드 키로 서명
```

1. EAS 빌드 페이지에서 `.aab` 내려받기
2. **첫 업로드는 Play Console 에서 직접** (Google API 는 처음 업로드를 받지 않는다). 4.7 의 비공개 테스트 새 버전에 올린다. 내부 테스트로 먼저 확인하고 싶으면 내부 테스트 트랙에 먼저 올려도 되지만, 14일 시계는 비공개 테스트부터 돈다
3. Play 앱 서명: 기본값 "Google 이 앱 서명 키 생성 및 관리" 그대로
4. 테스트 및 출시 > 설정 > 앱 무결성 > 앱 서명 에서 두 인증서 확인
   - "앱 서명 키 인증서" (Google 이 다시 서명하는 키) SHA-1, SHA-256
   - "업로드 키 인증서" (EAS 키) SHA-1, SHA-256
5. 카카오 개발자센터 > 플랫폼 > Android > 키 해시에 **앱 서명 키 SHA-1 을 Base64 로 바꾼 값** 추가 (업로드 키 해시는 이미 있어야 함)
   ```bash
   echo "<앱 서명 키 SHA-1, AA:BB:.. 형식>" | tr -d ':' | xxd -r -p | openssl base64
   ```
   빠지면 Play 에서 받은 설치본만 카카오 로그인이 KOE009 로 실패한다
6. Vercel 웹 환경 변수 `ANDROID_CERT_SHA256` = `<업로드 키 SHA-256>,<앱 서명 키 SHA-256>` (쉼표 구분, `AA:BB:..` 형식 그대로) → 웹 재배포 → 확인
   ```bash
   curl -s https://whenwemeet.day/.well-known/assetlinks.json     # 지문 2개
   adb shell pm get-app-links day.whenwemeet.app                    # Play 설치본에서 whenwemeet.day: verified
   ```
7. 이후 업로드는 CLI
   ```bash
   eas build -p android --profile production
   eas submit -p android --latest
   ```
   Play 서비스 계정 JSON 을 `eas credentials -p android` 에 한 번 올린다 (저장소에 두지 않음). `eas.json` 의 submit 은 지금 `track: internal`, `releaseStatus: draft` 다. 비공개 테스트 트랙으로 바로 보내려면 `--track alpha` 를 붙이거나(Alpha 트랙 기준) `eas.json` 을 바꾸는 PR 을 낸다 (모바일 에이전트 작업)

### 5.3 다시 만드는 법
데이터는 목 픽스처(`apps/web/src/mocks/fixtures.ts`, 실행한 날 기준 이번 달)라 실제 사용자 정보가 없다. 픽스처는 고치지 않았다.
1. `cd apps/web && API_MOCK=1 pnpm dev -p 3205`, `/auth/kakao?next=/` 로 목 로그인
2. Playwright(Chromium) 로 연다. 앱 화면처럼 보이게 UA 끝에 `WhenwemeetApp/1.1.0 (ios)` (Play 는 `(android)`) 를 붙이고, 페이지 시작 스크립트로 `window.ReactNativeWebView` 가짜 브리지를 넣어 `pushStatus` 에 `permission: granted` 로 답한다. 그래야 새 일정의 알림 줄이 "앱에서 받을 수 있어요" 안내 없이 고를 수 있는 상태로 나온다
3. `deviceScaleFactor: 3`, `isMobile: true`, `colorScheme: light`, `timezoneId: Asia/Seoul`, 뷰포트는 5.1 표의 CSS 크기. 찍기 전에 포커스를 풀고(`blur`) 마우스를 화면 구석으로 옮겨 hover 흔적을 없앤다. Next 개발 표시는 `next.config.ts` 의 `devIndicators: false` 라 안 나온다
4. 화면별 조작: 3 은 달력에서 `[data-date="<오늘>"]` 칸을 눌러 일 상세(`?day=1`), 5 는 `/g/<팀>/events/new?start=<토 11:00>&end=<토 13:00>` 에서 제목과 메모를 채우고 "알림" 줄 → "1시간 전", "반복" 줄 → "매주"
5. sharp 로 합성. Pretendard 는 `apps/mobile/assets/fonts/` 를 fontconfig(`FONTCONFIG_FILE`) 에 등록해 SVG 텍스트로 그린다. iPhone 은 상태 표시줄(9:41, 신호, 배터리)을 그려 붙인 뒤 Dynamic Island 테두리 안에 넣고, Play 는 v1 과 같은 단순 테두리, 듀오는 Apple 공식 베젤(5.4)을 화면 위에 덮는다. 모두 `flatten` + `removeAlpha`, iPhone 과 듀오는 JPEG 92 (sRGB)

화면 디자인이 크게 바뀌면 다시 찍는다. 스토어 스크린샷은 버전마다 바꿀 수 있다.

### 7.2 심사 메모 추가분 (1.7 메모 끝에 붙임)

```
WHAT'S NEW IN 1.1 - NOTIFICATIONS
- Event reminders: when creating or editing an event, choose "알림" (Reminder), e.g. 1 hour before. All team members get a push notification at that time.
- Team updates: members are notified when another member adds, edits or deletes a shared event, when a new member joins a team, and on anniversaries (09:00 KST).
- Permission: the app never asks on first launch. After the first event is saved, an in-app sheet explains why ("약속 전에, 팀원이 일정을 바꿀 때 알려 드릴까요?" = "Shall we notify you before plans and when team members change events?") and only "알림 받기" (Allow) shows the iOS permission dialog. "나중에" (Later) never asks again; it can be turned on later in profile > 알림 (Notifications).
- Notifications are not used for advertising or marketing. Tapping a notification opens the related event, anniversary list, team calendar or activity feed.
```

"이 버전의 새로운 기능" (한국어): `일정 알림이 생겼어요. 약속 전에, 팀원이 일정을 바꾸거나 새 멤버가 들어오면, 기념일 아침에 알려 드려요.`
