# 운영 배포 (#50)

| 구성 | 위치 | 주소 | 설정 문서 |
|------|------|------|-----------|
| 웹 (Next.js) | Vercel, 함수 리전 `sin1` (싱가포르) | `https://whenwemeet.day` | [vercel.md](./vercel.md) |
| API (NestJS) | Railway, 리전 Southeast Asia (Singapore) | `https://api.whenwemeet.day` | [railway.md](./railway.md) |
| DB (MySQL 8.4) | Railway (API 와 같은 프로젝트, 사설망) | `mysql.railway.internal` | [railway.md](./railway.md) |
| 프로필 사진 | Cloudflare R2 버킷 `whenwemeet` | `https://images.whenwemeet.day` | [cloudflare-r2.md](./cloudflare-r2.md) |
| DNS | Cloudflare (`whenwemeet.day` 존) | - | 아래 "DNS" |
| 카카오 로그인 | 카카오 개발자센터 | - | [카카오-개발자센터.md](./카카오-개발자센터.md) |

웹 서버(Vercel 함수)가 API 를 부르고, API 는 DB 를 부른다. 셋을 싱가포르에 모아 화면 한 번에 여러 번 오가는 API 호출이 같은 지역 안에서 끝나게 했다. 브라우저는 API 주소를 카카오 로그인 왕복 때만 직접 연다.

## 흐름

```
feature → PR → develop (CI build) → release PR develop → main (CI build) → 머지
                                                                      ├─ Railway: main 감시, CI 통과 후 이미지 빌드 → migrate deploy → 기동 → /v1/health 200 이면 트래픽 전환
                                                                      └─ Vercel : main = Production Branch, 빌드 후 whenwemeet.day 에 연결
```

- 두 플랫폼 모두 GitHub 저장소를 직접 연결한다. GitHub Actions 에 배포 토큰을 두지 않는다.
- Railway 는 "Wait for CI" 를 켜 `main` 의 CI(`build`) 가 실패하면 배포를 건너뛴다.
- Vercel 은 `develop`, PR 브랜치도 Preview 로 빌드한다. Preview 는 `API_MOCK=1` (메모리 목) 로 띄워 운영 API 와 DB 를 건드리지 않는다.
- 웹과 API 는 따로 배포된다. API 를 먼저 바꾸고 웹을 나중에 바꿔도 깨지지 않게, API 변경은 하위 호환으로 낸다 (필드 추가는 OK, 삭제/이름 변경은 웹이 먼저 안 쓰게 한 뒤).

## 마이그레이션 정책

- API 컨테이너가 기동할 때 `prisma migrate deploy` 를 먼저 돌리고 성공해야 서버를 띄운다 (`apps/api/Dockerfile` 의 `CMD`).
- 실패하면 새 컨테이너가 죽고 healthcheck 가 통과하지 않아 **이전 배포가 계속 트래픽을 받는다**. Railway 로그에서 원인을 보고 고친 커밋을 다시 올린다.
- 마이그레이션은 앞으로만 간다(롤백 SQL 없음). 그래서 한 릴리스 안에서는 **추가형 변경만** 한다.
  - 컬럼/테이블 추가, nullable 컬럼, 기본값 있는 NOT NULL 은 바로 OK
  - 컬럼 삭제/이름 변경은 두 릴리스로 나눈다: ① 코드가 안 쓰게 배포 → ② 다음 릴리스에서 DROP
- 운영 DB 에 직접 DDL 을 치지 않는다. 모든 변경은 `apps/api/prisma/migrations` 로만.
- 큰 마이그레이션 전에는 Railway MySQL 의 수동 백업을 먼저 뜬다 ([railway.md](./railway.md) "백업").

## 롤백

| 대상 | 방법 |
|------|------|
| API | Railway > API 서비스 > Deployments > 직전 성공 배포의 `⋮` > **Rollback**. 이미지가 그대로 다시 뜬다. 단 DB 스키마는 되돌아가지 않으므로 추가형 마이그레이션 정책을 지켜야 안전 |
| 웹 | Vercel > Deployments > 직전 Production 배포의 `⋯` > **Instant Rollback** (재빌드 없이 즉시) |
| DB | Railway MySQL > Backups 에서 복원 (새 볼륨으로 마운트 후 Deploy). 데이터 유실 구간이 생기므로 마지막 수단 |
| 근본 수정 | 롤백은 응급 처치. 고친 커밋을 develop → main 으로 다시 내보낸다 |

## DNS (Cloudflare, `whenwemeet.day` 존)

| 이름 | 종류 | 값 | 프록시 | 만드는 곳 |
|------|------|----|--------|-----------|
| `@` (`whenwemeet.day`) | A | Vercel 도메인 화면이 알려 주는 값 (보통 `76.76.21.21`) | **끔 (DNS only)** | [vercel.md](./vercel.md) |
| `www` | CNAME | Vercel 도메인 화면이 알려 주는 값 (`cname.vercel-dns.com` 류) | 끔 | [vercel.md](./vercel.md) |
| `api` | CNAME | Railway 커스텀 도메인 화면이 알려 주는 `*.up.railway.app` 값 | **끔 (DNS only)** 권장 | [railway.md](./railway.md) |
| `_railway-verify.api` | TXT | Railway 가 알려 주는 값 | (TXT 라 해당 없음) | [railway.md](./railway.md) |
| `images` | R2 가 자동 생성 | R2 커스텀 도메인 연결 시 자동 | 켬 (R2 가 관리) | [cloudflare-r2.md](./cloudflare-r2.md) |

- 웹과 API 는 각 플랫폼이 Let's Encrypt 인증서를 직접 발급하므로 프록시를 끄는 편이 단순하다. 켜야 한다면 Cloudflare SSL/TLS 모드를 **Full** 로 둔다 (Flexible 은 리다이렉트 무한 루프).
- 기존에 `@` 에 AAAA 나 다른 A 레코드가 있으면 지운다.

## 환경 변수 (이름만, 값은 각 플랫폼 시크릿에만)

### API (Railway, API 서비스)

| 이름 | 필수 | 운영 값 / 출처 |
|------|------|---------------|
| `DATABASE_URL` | O | `${{MySQL.MYSQL_URL}}` (Railway 참조 변수, 사설망 주소) |
| `WEB_ORIGIN` | O | `https://whenwemeet.day` (끝에 `/` 없이) |
| `JWT_SECRET` | O | `openssl rand -base64 48` (32자 이상). 로컬 값 재사용 금지 |
| `JWT_EXPIRES_IN` | - | 기본 `30d` |
| `KAKAO_CLIENT_ID` | O | 카카오 REST API 키 |
| `KAKAO_CLIENT_SECRET` | O | 카카오 Client Secret |
| `KAKAO_REDIRECT_URI` | O | `https://api.whenwemeet.day/v1/auth/kakao/callback` |
| `KAKAO_ADMIN_KEY` | O | 카카오 Admin 키 (탈퇴 시 unlink) |
| `R2_ACCOUNT_ID` | O | Cloudflare 계정 ID |
| `R2_ACCESS_KEY_ID` | O | 운영 버킷 전용 R2 토큰 |
| `R2_SECRET_ACCESS_KEY` | O | 위 토큰의 Secret |
| `R2_BUCKET` | O | `whenwemeet` |
| `R2_PUBLIC_BASE_URL` | O | `https://images.whenwemeet.day` |
| `RAILWAY_DOCKERFILE_PATH` | O | `apps/api/Dockerfile` (Railway 빌드 설정용) |
| `NODE_ENV` | - | 이미지에 `production` 고정. 넣지 않아도 됨 |
| `PORT` | - | Railway 가 자동 주입. 넣지 않음 |

`NODE_ENV=production` 이면 위 "필수" 가 하나라도 비었거나, `JWT_SECRET` 이 32자 미만이거나, `WEB_ORIGIN`/`KAKAO_REDIRECT_URI`/`R2_PUBLIC_BASE_URL` 이 `https://` 가 아니면 **기동 직후 종료**한다 (`apps/api/src/config/env.validation.ts`). 로그에는 빠진 변수 이름만 찍힌다.

## 운영 점검 결과 (코드)

| 항목 | 상태 |
|------|------|
| 쿠키 Secure | 웹 `wwm_session`(httpOnly), 자동 합류 쿠키와 API `wwm_oauth_state`(httpOnly) 는 `NODE_ENV=production` 이면 `Secure`, SameSite=Lax. `wwm_group`(마지막으로 본 팀 번호, 비밀 아님) 만 브라우저 스크립트가 쓰는 일반 쿠키라 Secure 없이 둔다 |
| CORS | `WEB_ORIGIN` 한 곳만 허용. 브라우저는 API 를 fetch 로 부르지 않으므로(웹 서버가 대신 호출) 사실상 방어용 |
| trust proxy | 설정 안 함. API 가 `req.ip`, `req.protocol`, `req.secure` 를 쓰지 않고, 쿠키 Secure 도 `NODE_ENV` 로 정하므로 필요 없음. 접속 IP 기반 기능(레이트 리밋 등)을 넣을 때 `app.set('trust proxy', 1)` 추가 |
| dev-login | 운영에서 404 (이미지가 `NODE_ENV=production` 고정) |
| health | `GET /v1/health` 인증 없음, DB `SELECT 1` 실패 시 503 `DB_UNAVAILABLE`. Railway healthcheck 경로 |

유료 전환 / 비용 증가 조건

- Railway: 처음 가입하면 Trial($5 일회성 크레딧, 30일) 이다. 크레딧이 떨어지거나 30일이 지나면 서비스가 멈추므로, 오픈 전에 **Hobby 로 업그레이드(카드 등록)** 해야 한다. 이후 메모리 사용량이 곧 비용이다 (1GB 늘 때마다 약 $10/월).
- Vercel: 광고, 결제, 유료 기능 등 **수익이 생기면 Hobby 약관 위반**이라 Pro($20/사용자/월) 로 옮긴다. 무료 한도 초과 시 Hobby 는 과금 대신 30일간 기능이 멈춘다.
- R2: 저장 10GB(프로필 사진 약 30만 장) 를 넘으면 GB 당 과금.
- 각 콘솔에서 사용량 알림(Railway Usage Limits, Vercel Spend 알림은 Pro 만) 을 걸어 둔다.
