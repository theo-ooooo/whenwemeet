# 카카오 개발자센터 등록

카카오 로그인에 필요한 앱 등록과 키 발급 절차. 키 값은 `apps/api/.env` 에만 넣고 어떤 문서에도 적지 않는다.
운영 배포 시에는 사이트 도메인과 Redirect URI 를 실제 도메인으로 추가 등록한다 (로컬 값은 그대로 둬도 됨).

[developers.kakao.com](https://developers.kakao.com) > 내 애플리케이션 > 애플리케이션 추가 후 아래를 설정한다. 운영 배포 시에는 운영 도메인을 각 항목에 **추가** 로 등록한다 (로컬 값은 지우지 않는다).

| 순서 | 위치 | 로컬 값 | 들어가는 곳 |
|------|------|---------|------------|
| 1 | 앱 설정 > 플랫폼 > Web > 사이트 도메인 | `http://localhost:3000` | 웹 주소 (`WEB_ORIGIN`) |
| 2 | 제품 설정 > 카카오 로그인 > 활성화 설정 | ON | - |
| 3 | 제품 설정 > 카카오 로그인 > Redirect URI | `http://localhost:4000/v1/auth/kakao/callback` | `apps/api/.env` `KAKAO_REDIRECT_URI` 와 글자 단위로 동일해야 함 |
| 4 | 제품 설정 > 카카오 로그인 > 동의항목 | 닉네임(`profile_nickname`), 프로필 사진(`profile_image`) 을 "필수 동의" 또는 "선택 동의" | - |
| 5 | 제품 설정 > 카카오 로그인 > 보안 > Client Secret | 코드 생성 후 활성화 상태 "사용함" | `apps/api/.env` `KAKAO_CLIENT_SECRET` |
| 6 | 앱 설정 > 앱 키 > REST API 키 | 복사 | `apps/api/.env` `KAKAO_CLIENT_ID` |
| 7 | 앱 설정 > 앱 키 > Admin 키 | 복사 | `apps/api/.env` `KAKAO_ADMIN_KEY` (회원 탈퇴 시 unlink 에 사용) |
| 8 | 앱 설정 > 앱 > 일반 > 앱 ID (숫자) | 복사 | `apps/api/.env` `KAKAO_APP_ID` (앱 카카오 로그인의 `app_id` 대조. 비밀 아님, 없으면 앱 로그인만 503) |

- 키와 Secret 은 `.env` 와 배포 플랫폼 시크릿에만 둔다. 문서, 이슈, 커밋에 쓰지 않는다.
- 플랫폼 Web 에는 포트까지 포함한 origin 을 넣는다 (`http://localhost:3000`).

## 운영 도메인 추가 (#50)

로컬 값은 그대로 두고 아래를 **추가** 한다.

| 위치 | 추가할 값 | 들어가는 곳 |
|------|-----------|------------|
| 앱 설정 > 플랫폼 > Web > 사이트 도메인 | `https://whenwemeet.day` | Railway `WEB_ORIGIN` |
| 제품 설정 > 카카오 로그인 > Redirect URI | `https://api.whenwemeet.day/v1/auth/kakao/callback` | Railway `KAKAO_REDIRECT_URI` (글자 단위로 동일) |

- 키(REST API 키, Client Secret, Admin 키)와 앱 ID(`KAKAO_APP_ID`) 는 로컬과 같은 앱의 값을 Railway 변수에 넣는다. 키는 문서에 쓰지 않는다
- 비즈 앱 전환, 검수가 필요한 동의항목은 쓰지 않는다 (닉네임, 프로필 사진만)
- 앱 설정 > 앱 > 일반의 앱 이름, 아이콘은 카카오 동의 화면에 그대로 보이므로 운영 전에 `언제볼까` 와 로고로 맞춘다

## 카카오톡 공유 (#195)

팀 초대를 카카오톡 피드 카드로 보낸다 (웹 JS SDK, 앱 1.1.1 네이티브 SDK). 템플릿은 코드(`apps/web/src/lib/kakao-share.ts`)에 있고 콘솔의 메시지 템플릿 빌더는 쓰지 않는다 (D-168).

| 위치 | 값 | 들어가는 곳 |
|------|-----|------------|
| 앱 설정 > 앱 키 > JavaScript 키 | 복사 | Vercel Production `NEXT_PUBLIC_KAKAO_JS_KEY` (공개값. 넣은 뒤 재배포). 로컬 확인은 `apps/web/.env.local` |
| 앱 설정 > 플랫폼 > Web > 사이트 도메인 | `https://whenwemeet.day` (로컬 확인은 `http://localhost:3000`) | JS SDK 를 부를 수 있는 도메인. 없으면 `sendDefault` 가 오류 → 버튼이 OS 공유로 떨어진다 |
| 앱 설정 > 플랫폼 > Web (제품 링크 관리 > 웹 도메인) | `https://whenwemeet.day` | 카드, 버튼 링크(`/join/<코드>`)와 이미지(`/og/join/<코드>`) 도메인. 등록 안 된 도메인 링크는 카드에서 동작하지 않는다 |
| 앱 설정 > 플랫폼 > iOS, Android | 번들 ID `day.whenwemeet.app`, 키 해시(EAS 업로드 키, Play 앱 서명 키) | 로그인 때문에 이미 등록. 앱 공유도 같은 값을 쓴다 |
| 제품 설정 > 카카오톡 메시지(공유) | 사용 가능 상태 확인 | - |

- 프리뷰 배포 도메인은 등록하지 않는다. 프리뷰에는 `NEXT_PUBLIC_KAKAO_JS_KEY` 를 넣지 않아 버튼이 OS 공유로 동작한다
- 쿼터: 카카오 API 전체 무료 사용량 하루 30,000건, 월 3,000,000건. 넘으면 유료 전환(공유 메시지 건당 정가 50원, 2027-12-31 까지 10원). 지금 규모에선 문제없다 ([쿼터](https://developers.kakao.com/docs/ko/getting-started/quota))
- 카드 이미지는 카카오가 처음 받은 것을 캐시한다. 팀 이름을 바꿔도 카드가 늦게 바뀌면 [공유 디버거](https://developers.kakao.com/tool/debugger/sharing)에서 주소를 초기화한다
- JS SDK 버전을 올릴 때는 [다운로드](https://developers.kakao.com/docs/ko/javascript/download) 페이지의 버전과 SRI 해시를 함께 `kakao-share.ts` 에 바꾼다. CSP 를 쓰게 되면 `script-src` 에 `t1.kakaocdn.net` 허용
