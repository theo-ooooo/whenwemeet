# 번들 기준선과 knip (#204)

웹 서버 함수 크기, 클라이언트 JS 크기의 기준선과 쓰지 않는 코드 검사(knip) 사용법. 수치가 눈에 띄게 늘면 이 표와 비교해 원인을 찾는다.

## 1. 측정 방법
```bash
cd apps/web
rm -rf .next && API_MOCK=1 pnpm build
# 서버 함수: .next/server/app/**/*.nft.json 의 files 크기 합 (Vercel 함수에 실리는 파일)
# 클라이언트: .next/static/chunks/*.js 크기 합, 파일마다 gzip -9 한 크기 합
```

## 2. 기준선 (2026-11-11, Next 16.4.5, Sentry(#185) 포함)

### 서버 함수 (추적 파일 합계)
| 함수 | #204 전 | #204 후 |
|------|---------|---------|
| 페이지 함수 23개 평균 | 28.7MB | 4.1MB |
| `/g/[groupId]/calendar` | 28.8MB | 4.2MB |
| route handler (`/api/[...path]`, `/auth/*` 등) | 1.7~1.8MB | 1.7~1.8MB |
| 공유 미리보기 이미지 | `/opengraph-image` 등 4개, 각 26.3MB | `/og`, `/og/join/[code]` 2개, 각 26.2MB |
| 글꼴(OTF 2개 3.2MB) + `@vercel/og`(2.9MB) 이 들어간 함수 | 44개 중 27개 | 41개 중 2개 (`/og*` 만) |

- 원인: 루트 `app/opengraph-image.tsx` 같은 메타데이터 파일 규칙은 하위 모든 페이지의 메타데이터 생성에 그 모듈을 끌어들인다. 글꼴, `@vercel/og` 말고도 그 의존 묶음 전체가 페이지 함수에 실려 페이지마다 약 24MB 가 늘었다
- 그래서 OG 이미지는 route handler(`app/og/route.tsx`, `app/og/join/[code]/route.tsx`)로 두고 주소를 metadata 에 직접 단다 ([vercel.md](./vercel.md) 5장). **`opengraph-image.*`, `twitter-image.*` 파일 규칙을 다시 쓰지 않는다**
- 확인: 빌드 후 `grep -l '\.otf' -r .next/server/app --include='*.nft.json'` 결과가 `og/` 아래 두 개뿐이어야 한다

### 클라이언트 JS (`.next/static/chunks`)
| 항목 | 값 |
|------|-----|
| 전체 | 34개, 1,238KB (파일별 gzip 합 407KB) |
| 큰 청크 | 439KB (gzip 139KB), 164KB (45KB), 113KB (39KB) |

- 의존성이 `next`, `react`, `react-dom`, `@sentry/nextjs` 뿐이라 큰 덩어리는 프레임워크와 Sentry 다. #185 전(2026-11-11 오전)은 997KB / gzip 292KB 였다
- 지금은 최적화 대상이 아니다. 늘면 화면별 분석(`next experimental-analyze` 등)을 한다

## 3. knip (쓰지 않는 코드, 의존성)
```bash
pnpm knip            # 저장소 루트. CI 와 같은 검사
pnpm knip --fix      # export 키워드 제거 등 자동 수정 (결과는 꼭 diff 로 확인)
```
- 설정은 루트 `knip.json`. 워크스페이스 3개(`apps/web`, `apps/api`, `apps/mobile`)의 진입점은 knip 플러그인(Next app 디렉터리, Nest CLI, Expo, vitest, jest)이 찾는다. 테스트 파일도 진입점이라 테스트에서만 쓰는 export 는 "쓰는 것" 으로 친다
- **CI 실패**: 쓰지 않는 파일, 쓰지 않는/목록에 없는 의존성, 풀리지 않는 import
- **경고만**: 쓰지 않는 export, 타입, enum 멤버, 중복 export. 2주 운영해 오탐이 없으면(2026-11-25 이후) `knip.json` `rules` 에서 `warn` 을 지워 실패로 올린다
- 같은 파일 안에서만 쓰는 export 는 무시한다(`ignoreExportsUsedInFile`). 상수를 테스트 편의로 export 해 두는 것은 괜찮다
- 오탐 무시 목록: `apps/web` 의 `@tailwindcss/turbopack`(`next.config.ts turbopack.rules` 의 문자열 로더), `apps/api` 의 `@prisma/client`(생성 클라이언트가 쓴다)
- CI 에서는 `prisma generate` 뒤에 돈다. 생성 코드가 없으면 그 import 가 풀리지 않는 것으로 잡힌다
