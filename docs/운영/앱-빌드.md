# 앱 빌드와 배포 (#95)

`apps/mobile` (Expo SDK 58) 을 EAS 로 빌드해 기기에 설치하고, TestFlight 와 Google Play 내부 테스트로 내는 절차. 설계는 `docs/설계/앱.md`, 계정 준비 순서는 그 문서 12장.

명령은 모두 **`apps/mobile` 에서** 실행한다. EAS CLI 는 전역 설치 대신 `npx eas-cli@latest <명령>` 으로 써도 된다 (아래 `eas` 는 그 줄임).

## 0. 미리 있어야 하는 것

| 항목 | 비고 |
|------|------|
| Expo 계정 | https://expo.dev 가입. 무료 플랜으로 충분 |
| Apple Developer Program (개인) | iPhone 설치(내부 배포)부터 필요. App ID 는 EAS 가 만들어 준다 |
| Google Play 개발자 계정 (개인) | Play 내부 테스트부터 필요. APK 직접 설치(preview)는 계정 없이 된다 |
| 카카오 네이티브 앱 키 | 카카오 개발자센터 > 내 애플리케이션 > 앱 키 |

## 1. 로그인

```bash
cd apps/mobile
npm i -g eas-cli        # 또는 npx eas-cli@latest
eas login
eas whoami
```

## 2. 프로젝트 연결 (`eas init`, 처음 1회)

```bash
eas init
```

`app.config.ts` 가 동적 설정이라 EAS 가 파일을 고치지 못하고 프로젝트 ID 를 출력한다. 그 값을 `app.config.ts` 의 `EAS_PROJECT_ID` 에 넣고 커밋한다 (공개값, PR 로).

```ts
const EAS_PROJECT_ID: string | undefined = "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx";
```

이 값이 있어야 `extra.eas.projectId` 와 EAS Update 주소(`updates.url`)가 채워진다.

## 3. 환경 변수 (EAS)

카카오 네이티브 앱 키는 앱 바이너리에 들어가는 공개값이라 `plaintext` 로 둔다. 값은 문서와 저장소에 적지 않고 명령으로만 넣는다.

```bash
eas env:set --name KAKAO_NATIVE_APP_KEY --value <네이티브 앱 키> \
  --environment development --environment preview --environment production \
  --visibility plaintext
eas env:list production
```

`EXPO_PUBLIC_WEB_ORIGIN`, `EXPO_PUBLIC_API_ORIGIN` 은 넣지 않으면 운영 주소(`https://whenwemeet.day`, `https://api.whenwemeet.day`)다. 스테이징을 띄울 때만 해당 환경에 추가한다.

**넣지 않는 것**: 카카오 Client Secret, Admin 키, Apple `.p8`(`APPLE_PRIVATE_KEY`), `JWT_SECRET`. 이 값들은 API(Railway) 시크릿에만 둔다.

로컬에서 `expo start`, `expo run:*` 을 쓸 때는 `apps/mobile/.env` (`.env.example` 복사, 커밋 안 됨).

## 4. 자격 증명 (서명)

```bash
eas credentials -p ios       # 처음 빌드 때 자동으로 물어보므로 건너뛰어도 된다
eas credentials -p android
```

- iOS: Apple 계정으로 로그인하면 EAS 가 Distribution 인증서, 프로비저닝 프로필, App ID `day.whenwemeet.app` 을 만든다. App ID 의 Capability 는 `app.config.ts` 에서 Sign in with Apple, Associated Domains 가 켜진다
- Android: "Generate new keystore" 를 고른다. 이 키가 **업로드 키**다. 키스토어는 EAS 에 보관되고, 저장소에 `.jks` 를 두지 않는다

## 5. 첫 빌드를 폰에 설치

### iPhone (internal distribution)

```bash
eas device:create                          # 출력된 링크/QR 을 iPhone 으로 열어 프로필 설치 → UDID 등록
eas build -p ios --profile development     # 개발용 (Metro 접속, 실기기 확인 항목은 이걸로)
eas build -p ios --profile preview         # 운영 웹을 띄우는 배포용 내부 빌드
```

- 빌드가 끝나면 나오는 링크/QR 을 iPhone 카메라로 열어 설치
- iOS 16 이상은 **설정 > 개인정보 보호 및 보안 > 개발자 모드** 를 켜야 internal 빌드가 열린다
- 기기를 새로 등록하면 그 다음 빌드부터 설치된다 (프로필 재생성)

development 빌드를 설치한 뒤:

```bash
pnpm --filter @whenwemeet/mobile start      # 같은 Wi-Fi 의 기기에서 앱이 Metro 에 붙는다
```

### Android (APK)

```bash
eas build -p android --profile preview      # APK. 링크를 폰에서 열어 설치 ("알 수 없는 앱 설치" 허용)
eas build -p android --profile development  # 개발용 APK
```

## 6. 카카오 플랫폼 등록 (첫 빌드 직후)

카카오 개발자센터 > 내 애플리케이션 > 앱 설정 > 플랫폼.

| 플랫폼 | 값 |
|--------|----|
| iOS | 번들 ID `day.whenwemeet.app` |
| Android | 패키지명 `day.whenwemeet.app`, 키 해시 아래 3개 |

키 해시는 서명 인증서 SHA-1 의 **Base64** 다 (16진수 그대로 넣으면 KOE009).

```bash
# 1) EAS 업로드 키: eas credentials -p android → Keystore 정보의 SHA1 Fingerprint (AA:BB:.. 형식)
echo "<SHA1 지문>" | tr -d ':' | xxd -r -p | openssl base64

# 2) Play 앱 서명 키: Play Console > 테스트 및 출시 > 설정 > 앱 무결성 > 앱 서명 > "앱 서명 키 인증서" SHA-1
#    (Play 에 첫 AAB 를 올린 뒤에 생긴다. 같은 명령으로 변환)

# 3) 로컬 디버그 키 (npx expo run:android 로 직접 빌드할 때만)
keytool -exportcert -alias androiddebugkey -keystore ~/.android/debug.keystore -storepass android | openssl sha1 -binary | openssl base64
```

Play 앱 서명 키 해시가 빠지면 **Play 에서 받은 설치본만** 카카오 로그인이 KOE009 로 실패한다.

## 7. 유니버설 링크와 앱 링크 확인값 (웹 환경 변수)

웹(Vercel)의 `.well-known` 두 라우트가 아래 값을 읽는다 (설계 5장, P4).

| 웹 환경 변수 | 값 |
|-------------|----|
| `APPLE_TEAM_ID` | Apple Developer > Membership 의 Team ID |
| `ANDROID_CERT_SHA256` | EAS 업로드 키 SHA-256, Play 앱 서명 키 SHA-256 (쉼표 구분, `AA:BB:..` 형식 그대로) |

확인:

```bash
curl -sI https://whenwemeet.day/.well-known/apple-app-site-association | grep -i content-type   # application/json
curl -s  https://whenwemeet.day/.well-known/assetlinks.json
# Android 기기에서 검증 상태
adb shell pm get-app-links day.whenwemeet.app     # whenwemeet.day: verified
```

iOS 는 AASA 를 설치 시점에 Apple CDN 에서 받는다. 웹에 값을 넣은 뒤 앱을 다시 설치해야 반영된다.

## 8. TestFlight (iOS)

```bash
eas build -p ios --profile production
eas submit -p ios --latest          # App Store Connect 앱이 없으면 만들지 묻는다. 이름 "언제볼까 - 같이 쓰는 달력"
```

- App Store Connect > TestFlight 에서 내부 테스터(최대 100명, 심사 없음)를 추가하면 TestFlight 앱으로 설치된다
- 외부 테스터는 베타 심사 1회가 필요하다
- 수출 규정 질문은 `ITSAppUsesNonExemptEncryption: false` 로 생략된다
- `eas submit` 에 쓰는 App Store Connect API 키(.p8)는 EAS 가 보관한다. 저장소와 문서에 두지 않는다

## 9. Google Play 내부 테스트 (Android)

```bash
eas build -p android --profile production    # AAB
```

1. Play Console 에서 앱 생성 (패키지명은 첫 업로드로 `day.whenwemeet.app` 에 고정된다)
2. **첫 AAB 는 Play Console 에서 직접 올린다** (테스트 및 출시 > 내부 테스트 > 새 버전 만들기). Google API 는 첫 업로드를 받지 않는다. Play 앱 서명은 기본값(Google 관리) 그대로
3. 그 뒤 6장의 Play 앱 서명 키 SHA-1 을 카카오에, SHA-256 을 웹 `ANDROID_CERT_SHA256` 에 추가
4. 이후 업로드는 `eas submit -p android --latest` (Play 서비스 계정 JSON 을 `eas credentials -p android` 에 한 번 올린다. 저장소에 두지 않는다). `eas.json` 의 submit 은 내부 테스트 트랙, draft 상태로 올린다
5. 개인 계정은 프로덕션 신청 전에 **비공개 테스트 12명 이상 14일** 이 필요하다 (기획 4.4). 내부 테스트로 확인이 끝나면 바로 비공개 테스트 트랙을 시작한다

## 10. 업데이트

| 바뀐 것 | 방법 |
|--------|------|
| 웹 화면 | 웹 배포만 (앱은 그대로) |
| 셸 JS (`src/`) | `eas update --channel production --message "<내용>"`. 같은 `version` 의 빌드에만 간다 (`runtimeVersion: appVersion`) |
| 네이티브 모듈, 권한, `app.config.ts` 의 네이티브 설정, 아이콘 | `version` 을 올리고 스토어 빌드 + 심사 |

### 1.3.0 (휴대폰 캘린더 #549, D-294)

`expo-calendar` 네이티브 모듈과 캘린더 권한이 새로 들어가 **스토어 빌드가 필요하다** (`eas update` 로 1.2.x 에 가지 않음, `runtimeVersion: appVersion` 이 1.3.0 으로 바뀜). 설계 `docs/설계/앱.md` 4.9. 웹은 UA 에 `DeviceCalendar/1` 이 있는 앱에만 설정 줄을 보이고 스냅샷을 보낸다(웹 먼저 배포해도 옛 앱에는 아무 변화 없음).

| 항목 | 값 |
|------|----|
| 버전 | `app.config.ts` `VERSION` 과 `package.json` `1.3.0` (빌드 번호는 EAS autoIncrement) |
| iOS 권한 문구 | `NSCalendarsFullAccessUsageDescription`(17+), `NSCalendarsUsageDescription`(16 이하) 같은 값 "언제볼까 일정을 휴대폰 캘린더에 보여 주려고 캘린더에 접근해요". 미리 알림 문구는 넣지 않는다 |
| Android 권한 | `READ_CALENDAR`, `WRITE_CALENDAR` (`expo-calendar` 플러그인) |
| Apple Developer | 새 capability, App Group, 익스텐션 없음 (권한 문구만). 프로비저닝 그대로 |
| 순서 | iOS 먼저 제출, Android 는 Play 프로덕션 승인 뒤 |

```bash
cd apps/mobile
npx expo-doctor                                   # 18개 패키지 버전 차이 경고는 1.2.0 때부터 있던 것
eas build -p ios --profile production             # 1.3.0, 빌드 번호 자동 증가
eas submit -p ios --latest                        # App Store Connect 로 올림 → TestFlight 내부 테스트로 확인 → 심사 제출
# Android (Play 프로덕션 승인 뒤)
eas build -p android --profile production
eas submit -p android --latest
```

- 개인정보: 캘린더 일정은 **기기 안에서만** 쓰고 서버로 보내지 않는다(새 수집 항목 없음, App Store 영양 성분표, Play 데이터 보안 그대로). 처리방침 1장에 "휴대폰 캘린더에 표시" 단락을 넣었다(웹 배포로 반영)
- Play Console: 캘린더 권한은 민감 권한 선언 대상이 아니다(`READ_CALENDAR` 는 위험 권한이지만 별도 양식 없음). 데이터 보안의 "캘린더 일정" 은 이미 신고돼 있고, 기기 캘린더로 쓰는 것은 수집이 아니다
- 심사 메모(iOS): `1.3 can add a "언제볼까" calendar to the iPhone Calendar app with the user's team schedules (My info > 휴대폰 캘린더 > toggle). Calendar access is used only to create that calendar and write our events; other calendars are never read or uploaded. Turning it off deletes the calendar.`
- "이 버전의 새로운 기능": `휴대폰 캘린더에서도 언제볼까 일정을 볼 수 있어요. 내 정보 > 휴대폰 캘린더에서 켜 주세요.`
- 실기기 확인(development 빌드 → TestFlight): 켜기 → 권한 창 문구 → 캘린더 앱에 "언제볼까"(코랄) 생김 → 일정 수와 종일/여러 날/반복 회차 날짜가 언제볼까와 같은지(특히 종일이 하루 길어지지 않는지) → 웹에서 일정 추가, 고치기, 지우기 뒤 3초쯤 뒤 반영 → 휴대폰에서 일정을 지우면 다음 맞추기에서 돌아오는지 → 팀 빼기 → 끄기 시 캘린더가 사라지는지 → 기기 설정에서 권한 끄기 후 화면 문구 → 로그아웃 시 캘린더 삭제 → 해외 시간대(설정 > 일반 > 날짜 및 시간)에서도 종일 날짜 그대로. Android 는 삼성 캘린더와 구글 캘린더 앱 둘 다
