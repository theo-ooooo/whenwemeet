# 일정 가져오기 기획 (ICS 파일, #279)

- 이슈: #279 (#194 1부를 뗀 것. 바쁨 정보 연동 2부는 #194 에 남는다)
- 정할 것 Q1~Q7 은 이슈의 추천안으로 확정 (주인 승인)

## 1. 목표와 대상
- 구글, 애플, 네이버 캘린더나 TimeTree 를 쓰다 넘어오는 사람이 지난 일정과 반복 일정을 다시 입력하지 않고 한 번에 옮긴다
- 순간: 처음 팀을 만들었을 때, 다른 캘린더에서 옮기기로 마음먹었을 때. 가입 장벽(다시 입력하는 부담)을 낮추는 게 목적

## 2. 핵심 흐름
1. 다른 캘린더 사용자로서, 내보낸 `.ics` 파일을 올려 몇 개가 들어가는지 먼저 보고 싶다 (미리보기, 아무것도 저장하지 않음)
2. 팀 사용자로서, 넣을 팀과 참여자(모두 / 나만), 기간(오늘 이후 / 지난 1년부터)을 고르고 한 번에 넣고 싶다
3. TimeTree 사용자로서, 옮기는 방법을 앱 안에서 안내받고 싶다 (공식 경로가 없다는 것과 그다음 할 일)

## 3. MVP 기능 목록
| 기능 | 필수/선택 | 비고 |
|------|----------|------|
| 팀 설정(개인 달력 포함) "일정 가져오기" 줄 → 단독 화면 `/g/[groupId]/import` | 필수 | 3단계: 파일 고르기 → 미리보기 → 완료 |
| `.ics` 1개 업로드, 서버는 파싱만 하고 파일을 버림 | 필수 | 2MB, VEVENT 3,000개, 넣는 일정(펼친 회차 포함) 1,000개 |
| VEVENT 만. 반복은 우리 규칙(매주, 격주, 매월, 매년)으로 옮길 수 있으면 반복으로, 아니면 회차를 펼쳐 한 번짜리로 | 필수 | 펼침은 오늘부터 1년 안 회차만 |
| EXDATE → 그 회차 취소, RECURRENCE-ID → 그 회차 예외 (앞뒤 30일 밖이면 원본에서 취소하고 따로 넣음) | 필수 | |
| 같은 파일을 다시 올려도 들어간 일정은 건너뜀 (UID 기준, 지운 일정도) | 필수 | 내용이 바뀌어도 덮어쓰지 않음 (Q5) |
| 참여자: 팀은 "모두"(기본), [나만] 선택. 개인 달력은 나 | 필수 | Q4. 미리보기에 "팀원 모두의 빈 시간에 바쁨으로 잡혀요" |
| 기간: 오늘 이후(기본), 지난 1년부터 | 필수 | 그보다 오래된 것은 건너뜀 |
| 일정마다 새 소식, 푸시를 남기지 않고 한 번에 한 줄 + 푸시 한 건 | 필수 | "민지님이 일정 42개를 가져왔어요" |
| 알림은 모두 없음 (VALARM 무시) | 필수 | |
| 지원 페이지 "TimeTree 에서 옮기기", 개인정보처리방침 한 줄 | 필수 | 비공식 도구 이름은 지원 페이지에만 (Q7) |

## 4. MVP 제외
- 주기적 동기화 (한 번 옮기기만. 동기화로 오해받지 않게)
- VTODO, VJOURNAL, VALARM, ATTENDEE, 첨부
- 가져오기 통째로 되돌리기 (Q6. 기록 테이블만 남겨 나중에 붙일 수 있게)
- 서버가 다른 서비스에 로그인해 가져오기 (TimeTree 포함. 자격 증명 보관, 약관, 장애 책임)
- 바쁨 정보 연동 (#194 2부)

## 5. 제약
- 개인정보: 파일은 저장하지 않는다. 원본 UID 는 SHA-256 해시만 저장. 처리방침에 한 줄
- TimeTree: 공개 API 는 2023-12-22 종료, 공식 내보내기 없음. 언제볼까는 TimeTree 계정 정보를 받지 않는다
- 비용: 파싱은 요청당 순간 CPU (2MB, 반복 펼치기 걸음 상한)

## 6. 성공 기준
- 가져오기를 쓴 사람의 2주 뒤 잔존이 쓰지 않은 신규 가입자보다 높다
- 가져오기 실패(VALIDATION_FAILED file) 비율 5% 미만
- 가져오기로 인한 푸시 민원 0 (일정마다 푸시가 가지 않는다)

- 없음 (Q1~Q7 추천안 확정)
