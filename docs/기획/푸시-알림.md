## 1. 목표와 대상

**누가**: iOS, Android 앱 사용자. 웹은 대상이 아니다 (웹 푸시는 iOS 사파리 제약이 크고, 앱이 있으니 앱으로 유도한다).

**어떤 순간에**: 지금은 앱을 열어야 새 소식 배지로 바뀐 걸 안다. 약속 1시간 전, 상대가 일정을 바꿨을 때, 기념일 당일, 초대한 사람이 들어왔을 때 앱을 열지 않아도 알게 한다.

**지금 상태**: 푸시 없음. 앱은 Expo 셸(SDK 58) 이라 `expo-notifications` 와 Expo 푸시 서비스(APNs, FCM 을 한 API 로)를 붙일 수 있다 (앱.md 4.6).

## 2. 핵심 흐름

| # | 유저 스토리 | 완료 기준 |
|---|------------|-----------|
| P1 | 연인으로서, 저녁 약속을 등록할 때 "1시간 전" 을 고르면 둘 다 1시간 전에 알림을 받고 싶다 | 18:00 일정 + 1시간 전 → 17:00 에 팀원 모두의 폰에 제목 "저녁 약속", 본문 "1시간 뒤 오후 6:00" |
| P2 | 팀원으로서, 상대가 일정을 바꾸면 바로 알고 싶다 | 상대가 수정 → 수 초 안에 "민지님이 '저녁 약속' 을 수정했어요". 알림을 누르면 그 일정 상세 |
| P3 | 알림이 많다고 느끼는 사람으로서, 종류별로, 팀별로 끄고 싶다 | 내 정보 > 알림 에서 종류 4개 각각 끄기, 팀 설정에서 그 팀 알림 끄기 |

## 3. 규칙

### 3-1 알림 종류 (확정, Q4)

| 종류 | 언제 | 누구에게 | 문구 예 | 누르면 |
|------|------|---------|--------|-------|
| 일정 알림 | 일정에 고른 시각 | 팀원 모두 (등록자 포함) | "저녁 약속" / "1시간 뒤 오후 6:00" | 일정 상세 |
| 팀원 변경 | 다른 멤버가 일정을 추가, 수정, 삭제한 즉시 | 나머지 멤버 (변경한 사람 제외) | "민지님이 일정을 추가했어요" / "저녁 약속, 11월 12일 (수) 오후 6:00" | 일정 상세 (삭제면 새 소식) |
| 기념일 당일 | 그날 오전 9시 KST | 팀원 모두 | "오늘은 처음 만난 날 300일이에요" | 기념일 화면 |
| 새 멤버 합류 | 초대 링크로 합류한 즉시 | 기존 멤버 | "지훈님이 '우리 가족' 에 들어왔어요" | 팀 달력 |

- 팀 이름을 함께 보여 팀이 여럿인 사람이 구분하게 한다 (iOS 는 부제, Android 는 제목 앞)
- **메모는 알림에 넣지 않는다** (잠금 화면 노출). 제목과 시각만
- 개인 달력(PERSONAL) 은 나 혼자라 팀원 변경과 합류 알림이 없다. 일정 알림과 기념일은 온다

### 3-2 일정 알림 시각 (확정, Q3)
일정 작성/수정에서 하나를 고른다. 일정에 저장되어 팀원 모두에게 같은 시각에 간다.

| 일정 | 선택지 | 기본 |
|------|-------|------|
| 시간 일정 | 없음 / 정시 / 10분 전 / 1시간 전 / 1일 전 | 없음 |
| 종일 일정 | 없음 / 당일 오전 9시 / 전날 오전 9시 | 없음 |

- 기본이 "없음" 인 이유: 팀원 모두에게 가는 알림이라, 등록자가 고르지 않았는데 남의 폰이 울리면 안 된다
- 알림 시각이 이미 지난 상태로 저장하면 보내지 않는다 (예: 30분 뒤 일정에 1시간 전)
- 일정 시각이나 알림 선택을 바꾸면 새 시각으로 다시 잡는다. 이미 보낸 알림은 다시 보내지 않는다 (시각이 바뀌면 다시 보낸다)
- 반복 일정 (#187): 회차마다 같은 알림. "이 일정만" 으로 바꾼 회차는 그 회차 값

### 3-3 팀원 변경 알림
- 새 소식(EventLog) 1건 = 알림 1건. 반복 일정은 3-6(#187) 처럼 동작 하나에 1건
- 같은 사람이 같은 일정을 **2분 안에 여러 번 수정** 하면 마지막 1건만 보낸다 (오타 고치기로 알림이 쌓이지 않게)
- 추가 직후 2분 안에 삭제하면 둘 다 보내지 않는다

### 3-4 받을 조건과 설정 (P3)
알림은 아래를 모두 만족할 때만 간다.
1. 그 사람이 앱에 로그인한 기기가 있고, OS 알림 권한을 허용했다
2. 내 정보 > 알림 의 해당 종류가 켜져 있다 (4개 토글, 모두 기본 켬)
3. 그 팀의 알림이 켜져 있다 (팀 설정 "이 팀 알림 받기", 기본 켬)

- 한 사람이 기기 여러 대(폰, 태블릿) 면 모두에게 보낸다
- 로그아웃하면 그 기기로 보내지 않는다. 탈퇴하면 기기 정보를 지운다
- 앱을 지웠거나 권한을 끈 기기는 발송 실패 응답을 받으면 지운다
- 방해 금지 시간은 두지 않는다. OS 의 집중 모드, 방해 금지를 따른다

### 3-5 권한 요청 시점
- 앱 첫 실행에서 묻지 않는다 (무엇에 쓰는지 모르면 거부가 많다)
- **처음 일정을 저장한 직후** 또는 **알림 시각을 처음 고를 때** 앱 안 안내 시트 한 번: "약속 전에, 팀원이 일정을 바꿀 때 알려 드릴까요?" [알림 받기] [나중에] → [알림 받기] 를 누를 때만 OS 권한 창
- "나중에" 를 누르면 다시 묻지 않는다. 내 정보 > 알림 에서 언제든 켤 수 있다 (OS 에서 거부했으면 설정 앱으로 안내)
- 웹에서는 알림 시각 칸이 보이지만, 아래에 "알림은 앱에서 받을 수 있어요" 한 줄

### 3-6 정확도
- 일정 알림과 기념일 알림은 정한 시각에서 **1분 안** 에 보낸다
- 서버가 멈췄다 돌아오면 **10분 안에 지난 알림** 만 늦게라도 보내고, 더 오래된 건 버린다 (지난 약속 알림이 한꺼번에 오지 않게)
- 같은 알림은 한 기기에 한 번만 (서버 재시작, 중복 실행에도)

## 6. 제약
- **앱 새 버전 필요**: `expo-notifications` 는 네이티브 모듈이라 웹 배포로 안 바뀐다. iOS, Android 스토어 재제출 (1.1). 이전 앱 버전은 알림 없이 지금처럼 동작
- 사용자 준비물: Apple Push Notification 키 (.p8, Apple Developer > Keys, 기존 로그인 키와 별도 또는 같은 키에 APNs 추가), Android 는 Firebase 프로젝트와 FCM v1 서비스 계정 키. 둘 다 EAS 자격 증명에 등록 (값은 파일로만)
- 개인정보: 기기 푸시 토큰과 기기 종류를 새로 저장한다 → 개인정보처리방침 "수집 항목" 과 "위탁(Expo, Apple, Google)" 에 추가, 탈퇴 시 즉시 삭제. 광고성 정보가 아니라 정보통신망법 광고 수신 동의는 필요 없다
- 앱 심사: 알림 권한 안내 문구가 기능과 맞아야 한다 (3-5). 마케팅 알림을 보내지 않는다
- 운영 비용: Expo 푸시 서비스 무료. 발송 예약은 API 서버 안에서 처리 (Railway 에 별도 서비스를 늘리지 않는 쪽을 설계에서 먼저 검토)

## 7. 성공 기준
1. 앱 활성 사용자 중 알림 권한 허용 50% 이상 (기기 등록 수 / 앱 로그인 사용자)
2. 일정 알림 지연 p95 1분 이내 (예정 시각 대비 Expo 발송 시각 로그)
3. 출시 4주 뒤 주간 재방문(앱 열기) 이 출시 전 대비 증가
