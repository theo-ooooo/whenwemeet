# 팀 공유 할 일 목록 기획

- 이슈: #276
- 상태: 승인 (2026-11-12, 이슈의 "정할 것" 추천안 그대로 주인 승인)
- 작성: 2026-11-12
- 설계: `docs/설계/할일-목록.md`

## 1. 목표와 대상

**누가**: 장보기, 여행 준비물, "다음에 같이 할 것" 을 같이 챙기는 연인, 가족, 친구 팀. 혼자 쓰는 사람(개인 팀)의 체크리스트.

**어떤 순간에**: 날짜가 없는 일을 적어 둘 곳이 필요할 때. 지금은 아무 날짜에 종일 일정으로 넣거나(달력이 지저분해지고 빈 시간 "종일 포함" 토글에 섞인다, D-12) 카톡에 적는다.

**왜 이 앱에서**: 이미 팀이 같이 여는 앱이다. 달력 옆에 같은 팀의 할 일이 있으면 따로 앱을 깔지 않는다.

## 2. 핵심 흐름

| # | 유저 스토리 | 완료 기준 |
|---|------------|-----------|
| T1 | 팀원으로서, "장보기" 목록을 만들고 항목을 연달아 적고 싶다 | 목록 만들기 → 상세에서 입력줄에 쓰고 엔터, 입력칸이 비고 포커스가 남아 바로 다음 항목 |
| T2 | 팀원으로서, 마트에서 산 것을 체크하고 상대가 무엇을 체크했는지 보고 싶다 | 체크하면 취소선 + 아래 "완료 N개" 로, 다른 멤버가 연 화면에도 다시 불러오면 "민지님이 완료" |
| T3 | 앱을 연 사람으로서, 남은 할 일을 홈에서 한눈에 보고 싶다 | 폰 홈 "할 일" 구역에 목록마다 "남은 N개", 넓은 화면은 사이드바 "할 일" 메뉴 |

## 3. MVP 기능 목록

| 기능 | 필수/선택 | 비고 |
|------|----------|------|
| 목록 만들기, 이름 바꾸기, 삭제 | 필수 | 팀당 여러 개, 최대 20개. 이름 1~30자. 삭제는 확인 "장보기와 항목 12개를 지울까요?" |
| 항목 추가, 글 수정, 완료 체크와 해제, 삭제 | 필수 | 목록당 최대 300개, 글 1~100자. 삭제는 확인 없이 + 5초 되돌리기 (기념일과 같은 D-26) |
| 완료 항목 한꺼번에 지우기 | 필수 | 확인 "완료한 3개를 지울까요?" |
| 누가 추가했는지, 누가 완료했는지 | 필수 | 항목 줄 오른쪽 추가한 사람 색 점, 완료 항목 아래 "민지님이 완료" |
| 홈 "할 일" 구역, 사이드바 메뉴, 목록 화면, 목록 상세 | 필수 | 폰 아래 독은 4개 그대로 (디자인규칙 4-1) |
| 개인 팀에서도 같은 기능 | 필수 | 서버 분기 없음 (D-132 와 같은 원칙) |
| 빈 목록 제안 칩 "장보기", "여행 준비물", "같이 할 일" | 선택 | 누르면 그 이름으로 목록 생성 |

## 4. MVP 제외

| 제외 | 이유 |
|------|------|
| 기한, 담당자, 알림, 반복 할 일 | 날짜가 생기면 일정과 겹친다. 수요를 본 뒤 |
| 손으로 순서 바꾸기 | 추가 순서 고정으로 충분. 끌어 옮기기는 폰 웹뷰에서 비용이 크다 |
| 항목을 일정으로 바꾸기 | 일정 경로(빈 시간, 알림, 반복)와 엮인다 |
| 실시간 동기화 | 화면에 들어올 때, 앱이 다시 앞으로 올 때 다시 불러오기로 충분 |
| 새 소식, 푸시 | 장보기 한 줄마다 기록과 알림이 쌓이면 소음. #191 확장 규칙이 정해진 뒤 따로 |
| 체크 없는 메모장 | 범위 밖 |

## 5. 제약

- 개인정보: 새 수집 항목은 사용자가 직접 입력한 할 일 글뿐. 개인정보처리방침 1장 "직접 입력한" 문장에 "할 일 목록" 을 더한다. 스토어 라벨의 "사용자 콘텐츠" 는 일정 때문에 이미 선언됨
- 탈퇴: 만든 사람, 완료한 사람은 "탈퇴한 멤버" 로 남는다 (D-03). 개인 팀은 팀과 함께 삭제
- 비용: 작은 행 2종, 서버 비용 영향 없음
- 앱: 웹 화면만. 앱 심사, 네이티브 빌드 없음

## 6. 성공 기준

1. 배포 2주 안에 할 일 목록을 하나 이상 만든 팀 비율 20% 이상
2. 목록 상세에서 항목 추가 → 다음 항목 입력까지 탭 0번 (엔터만)
3. 할 일 기능 관련 Critical, High 버그 0건
