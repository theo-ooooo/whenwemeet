# 이메일 로그인 기획

- 이슈: #245
- 상태: 기획 승인 대기
- 작성: 2026-11-11
- 관련: 앱 심사 계정(스토어-제출.md 3장), 계정 연결 #198 (이번 범위 아님)

## 1. 목표와 대상

**누가**: 카카오톡을 안 쓰거나 카카오 계정을 연결하고 싶지 않은 사람, Android 에서 Apple 로그인이 없는 사람, 스토어 심사자.

**왜**: 지금 로그인은 카카오와 Apple 뿐이라 Android 사용자는 카카오 계정이 꼭 있어야 한다. Google Play 심사도 심사자가 쓸 카카오 계정을 요구한다. 비밀번호 없이 이메일만으로 들어오는 길을 하나 더 둔다.

## 2. 핵심 흐름

| # | 유저 스토리 | 완료 기준 |
|---|------------|-----------|
| E1 | 웹 사용자로서, 이메일만 넣고 메일의 링크를 누르면 바로 가입하고 들어가고 싶다 | 이메일 입력 → "메일을 보냈어요" → 메일의 [언제볼까 시작하기] 링크 → (처음이면 닉네임 입력) → 달력 |
| E2 | 앱 사용자로서, 메일 앱을 오가도 앱에서 로그인되고 싶다 | 앱에서 이메일 입력 → 메일의 6자리 코드를 앱 화면에 입력 → 로그인 |
| E3 | 심사자로서, 메일함 없이 안내받은 계정으로 들어가고 싶다 | 심사 전용 이메일 + 고정 코드로 로그인, 샘플 데이터가 있는 "심사용" 팀이 보인다 |

## 3. 규칙

### 3-1 로그인 방식 (확정, 사용자 결정)
- **비밀번호는 없다.** 이메일로 받은 **링크** 또는 **6자리 코드**가 곧 로그인이다. 가입과 로그인을 나누지 않는다(처음 오는 이메일이면 가입)
- 메일 한 통에 링크와 코드를 같이 넣는다. 링크를 누르면 그 브라우저에서 로그인되고, 코드는 입력한 화면(앱, 다른 기기)에서 로그인된다
  - 이유: 앱에서 메일 앱의 링크를 누르면 앱이 아니라 Safari/Chrome 에서 열려, 앱은 로그인되지 않은 채 남는다
- 링크와 코드는 **15분** 유효, **한 번만** 쓸 수 있다. 하나를 쓰면 같은 메일의 나머지도 무효
- 코드는 5번 틀리면 그 메일은 무효. 다시 받아야 한다
- 새로 받으면 이전에 보낸 링크와 코드는 무효

### 3-2 발송 (확정, Resend)
- 보내는 주소 `언제볼까 <noreply@whenwemeet.day>`. 제목 "[언제볼까] 로그인 링크와 코드"
- 본문: 큰 버튼 [언제볼까 시작하기], 코드 6자리, "15분 안에 사용해 주세요", "요청하지 않았다면 이 메일을 무시하세요"
- 다시 보내기: 같은 이메일은 **60초에 한 번, 1시간에 5번**까지. IP 당 1시간에 20번
- 받는 사람이 없는 주소, 수신 거부 등으로 실패해도 화면은 같은 "메일을 보냈어요"(가입 여부를 알려 주지 않는다)

### 3-3 처음 가입
- 링크나 코드로 처음 들어오면 **닉네임 입력** 화면 한 번(2~20자, 기본값 없음). 프로필 사진은 나중에 내 정보에서
- 가입하면 지금과 똑같이 개인 달력이 생긴다
- 초대 링크로 들어온 사람은 닉네임을 정한 뒤 그 팀에 합류(지금의 카카오 흐름과 같음)

### 3-4 화면 위치
- 로그인 화면(웹, 앱 모두): 카카오 → Apple(iOS, 웹) → **"이메일로 계속하기"** 순서. 이메일 버튼은 보조 모양(테두리)
- 이메일 입력 화면 → "메일을 보냈어요" 화면(코드 6칸 입력 + 다시 보내기 + 다른 이메일로)
- 초대 합류 화면의 로그인 버튼 묶음에도 같은 버튼

### 3-5 계정
- 이메일 계정은 카카오, Apple 계정과 **별개**다. 같은 사람이 카카오와 이메일로 각각 들어오면 계정이 둘이 된다(계정 연결은 #198)
- 이메일은 소문자로 맞춰 저장한다. 이메일은 바꿀 수 없다(바꾸려면 탈퇴 후 새로 가입)
- 탈퇴하면 이메일과 발송 기록을 바로 지운다

### 3-6 심사 계정
- 서버 설정(환경 변수)에 **심사 전용 이메일 1개와 고정 코드**를 둔다. 이 이메일로 요청하면 메일을 보내지 않고, 고정 코드로만 로그인된다
- 이 계정에 "심사용" 팀과 샘플 일정, 기념일을 넣어 둔다
- 설정이 비어 있으면 이 기능은 꺼진다. 값은 저장소, 문서에 쓰지 않고 Railway 와 각 스토어 콘솔 입력칸에만

## 5. MVP 제외

| 제외 | 이유 |
|------|------|
| 비밀번호 로그인 | 사용자 결정(매직 링크). 비밀번호 찾기까지 필요 없음 |
| 이메일 변경 | 드묾. 탈퇴 후 재가입으로 |
| 카카오/Apple 과 같은 계정으로 합치기 | #198 계정 연결 |
| 앱이 링크를 직접 여는 유니버설 링크 | 코드 입력으로 충분. 필요하면 나중에 |

## 6. 제약
- **개인정보**: 이메일을 새로 수집한다 → 개인정보처리방침 수집 항목, 위탁(Resend), App Store 개인정보 라벨(이메일 주소: 앱 기능, 계정 관리), Play 데이터 보안(이메일 주소) 갱신
- **사용자 준비물**: Resend 가입, `whenwemeet.day` 도메인 인증(DNS 레코드 추가: Cloudflare), API 키를 Railway 변수로
- **보안**: 링크/코드는 해시로만 저장. 응답에 가입 여부를 드러내지 않음. 횟수 제한
- **앱**: 웹 화면만 바뀐다. 앱 새 빌드 없이 적용(로그인 화면은 웹)

## 7. 성공 기준
1. Google Play 심사를 이메일 심사 계정으로 통과
2. 출시 4주 뒤 신규 가입 중 이메일 비율과 메일 → 로그인 완료율(링크/코드 사용 / 발송) 측정 가능
3. 메일 도착 시간 p95 1분 이내(Resend 로그)
