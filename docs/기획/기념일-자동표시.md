# 기념일 자동 표시 기획

- 이슈: #105 (구현 #106 API, #107 웹)
- 상태: 기획 승인 대기
- 작성: 2026-11-10
- 선행: 디자인 개편 #99 (밀도 + 색 A). 구현은 그 뒤 새 토큰으로

## 1. 목표와 대상

**누가**: 처음 만난 날, 결혼기념일 같은 "세는 날" 을 등록한 연인, 가족. 생일처럼 매년 돌아오는 날을 등록한 모든 팀.

**어떤 순간에**: "우리 300일이 언제지?" 를 계산기나 다른 앱으로 세는 순간. 기념일 하나만 등록하면 100일, 200일, 1주년이 달력에 알아서 뜨게 한다.

**지금 상태 (develop 75378d0)**: 기념일 화면에 D-day / D+N 과 "다음 100일까지 30일 이내" 힌트 한 줄뿐이다. 달력 칸에는 기념일이 전혀 안 보이고, 생일은 등록 연도 하루만 해당한다. 힌트(`hundredHint`)는 시작일을 0일로 세어 100일이 하루 늦게 나온다.

## 2. 핵심 흐름

| # | 유저 스토리 | 완료 기준 |
|---|------------|-----------|
| A1 | 연인으로서, 처음 만난 날만 등록하면 100일, 200일, 1주년이 달력에 저절로 보이길 원한다 | 등록 직후 달력 해당 날짜 칸에 "100일", 기념일 화면에 "다음 100일 D-n" |
| A2 | 팀원으로서, 생일을 한 번 등록하면 매년 그날 달력에 보이길 원한다 | 종류 "매년 반복" 으로 등록하면 올해와 내년 칸에 이름이 보이고 100일 단위는 안 생긴다 |
| A3 | 달력을 여는 사람으로서, 곧 다가오는 기념일을 따로 찾지 않고 보고 싶다 | 30일 안의 항목이 다가오는 일정과 D-day 타일에 "300일 D-12" 로 보인다 |

## 3. 규칙

### 3-1 기념일 종류 (확정, Q1)
등록, 수정 시트에서 하나를 고른다. 기본은 "함께한 날 세기".

| 종류 | 값 | 예 | 달력에 생기는 항목 |
|------|----|----|------------------|
| 함께한 날 세기 | `COUNT_UP` | 처음 만난 날, 결혼기념일 | 원래 날짜, N일(아래 단위), N주년 |
| 매년 반복 | `YEARLY` | 생일, 기일 | 원래 날짜와 이후 매년 같은 월일 |
| 그날만 | `ONCE` | 시험일, 여행 출발 | 원래 날짜 하나 (지금 동작) |

사용자가 승인한 "기념일 자동 표시 켜기/끄기" 는 `COUNT_UP` 과 `ONCE` 의 차이와 같다. 생일에 필요한 "매년" 은 켜기/끄기로 표현되지 않아 종류를 셋으로 둔다.

### 3-2 날짜 세기
- 시작일이 1일이다. **N일 = 시작일 + (N - 1)일**. 100일 = 시작일 + 99일
- N일 단위: 100, 200, ..., 1000 (100 간격), 이후 2000, 3000, ... (1000 간격). 상한 30000일 (약 82년)
- N주년: 시작일과 같은 월일, 연도 + N. 상한 100주년
- 매년(`YEARLY`): 시작일 이후 매년 같은 월일. 시작일 이전 연도에는 만들지 않는다
- 2월 29일: 평년에는 2월 28일로 (N주년, 매년 공통). 윤년에는 2월 29일 그대로. N일 세기는 순수 날짜 차이라 영향 없음
- 같은 날 항목이 둘이면(예: N주년과 N일이 겹침) 둘 다 만든다
- 시간대: 모든 계산은 KST 달력 날짜(`YYYY-MM-DD`) 끼리. "오늘" 은 KST 오늘. 브라우저 시간대를 쓰지 않는다 (`lib/date.ts` 의 `Date.UTC` 방식)

### 3-3 얼마나 앞까지 계산하나
미리 목록을 만들어 두지 않고 **필요한 범위만** 계산한다. N일은 범위의 날짜 차이로, N주년과 매년은 범위의 연도로 바로 구하므로 시작일이 아무리 오래돼도 반복 계산이 없다.

| 쓰는 곳 | 범위 |
|---------|------|
| 달력 | 보이는 6주 그리드 42일 (과거 달로 가면 과거 항목도 보임) |
| 다가오는 일정 | 오늘 ~ 오늘 + 30일 |
| D-day 타일, 기념일 화면 "다음" | 오늘 이후 가장 가까운 1개. `COUNT_UP` 과 `YEARLY` 는 1년 안에 반드시 있다 |

### 3-4 대표 라벨 (기념일 화면 행, D-day 타일)
| 종류 | 시작일 전 | 시작일 당일 | 이후 |
|------|----------|------------|------|
| `COUNT_UP` | D-n | 1일 | {N}일 (오늘이 몇 번째 날인지, 예 "679일") |
| `YEARLY` | D-n | D-day | 다음 돌아오는 날까지 D-n, 당일 D-day |
| `ONCE` | D-n | D-day | D+n (지금 그대로) |

`COUNT_UP` 이 D+N 대신 "N일" 을 쓰는 이유: D+N 은 시작일을 0으로 세어 100일 당일에 "D+99" 가 나와 규칙과 어긋난다 (확정, Q2).

### 3-5 예시 (오늘 = 2026-11-10, 단위 테스트 케이스로 그대로 쓴다)
| 기념일 | 결과 |
|--------|------|
| 2025-01-01 처음 만난 날 (`COUNT_UP`) | 100일 2025-04-10, 200일 2025-07-19, 300일 2025-10-27, 1주년 2026-01-01, 1000일 2027-09-27, 2000일 2030-06-23. 대표 라벨 "679일", 다음 "700일 2026-12-01 D-21" (그다음 2주년 2027-01-01 D-52) |
| 2026-08-03 (`COUNT_UP`) | 오늘이 100일. 칸, 상세, 다가오는 일정, 타일 모두 "100일 오늘" |
| 2026-12-24 (`COUNT_UP`, 미래) | 대표 라벨 "D-44". 100일 2027-04-02 도 미리 달력에 보임 |
| 2024-02-29 (`COUNT_UP`) | 100일 2024-06-07, 1주년 2025-02-28 (평년), 4주년 2028-02-29 (윤년) |
| 1996-02-29 생일 (`YEARLY`) | 2026-02-28, 2027-02-28, 2028-02-29 |
| 2000-05-05 생일 (`YEARLY`) | 매년 5월 5일. 100일 단위 없음. 대표 라벨 "D-176" (2027-05-05) |
| 2026-11-20 시험 (`ONCE`) | 그날 하나. "D-10", 지나면 "D+n" |

### 3-6 표시 개수 제한
- **달력 칸에는 기념일 줄 1개**. 그날 항목이 여럿이면 우선순위로 하나: N주년 > N일 > 매년/원래 날짜, 같으면 먼저 등록한 기념일(id 오름차순). 나머지는 날짜 상세에서 전부
- 공휴일과 겹치면 칸 글자는 기념일, 공휴일은 빨간 숫자로만. 칸 `aria-label` 에는 공휴일과 기념일 전부
- 다가오는 일정에는 기념일 항목 최대 2개 (일정 목록을 밀어내지 않게)

## 4. 화면 동작

#99 개편 후의 화면 기준이다. 강조는 면 없이 `--hl-time` 글자색, 하트 선 아이콘, 점으로 (#99 디자인토큰 "강조 방식").

| 위치 | 동작 |
|------|------|
| 달력 칸 (phone, fold 막대형) | 날짜 숫자 아래 한 줄 10px `--hl-time`: N일/N주년은 "300일" "1주년", 매년과 원래 날짜는 이름(말줄임). 일정 제목 줄 위에 오고, 칸 높이가 모자라면 일정 제목 줄을 숨긴다 (막대는 유지) |
| 달력 칸 (pc, fold 칩형) | 첫 칩 자리에 하트 아이콘 + 라벨(면 없음, `--hl-time`). 칩 3개 제한에 포함, 넘치면 "+N개 더" |
| 날짜 상세 (phone 시트, fold/pc 팝오버, #99 5장) | 일정 위에 그날 기념일 항목 전부. 한 줄: 하트 + "처음 만난 날 300일" + 오른쪽 "오늘" / "D-3" / 지난날은 "D+5". 탭 → 기념일 화면 |
| 다가오는 일정 (#99 개요 칸, 폰 달력 아래) | 30일 안의 기념일 항목을 날짜순으로 섞는다 (최대 2개). "300일 처음 만난 날" + "12월 15일 (화)" + "D-35" |
| D-day 타일 / 개요 정보 줄 | 오늘 포함 가장 가까운 다음 항목 1개 "처음 만난 날 300일 D-35". 다음 항목이 없으면(지난 `ONCE` 뿐) 지금처럼 가장 가까운 기념일의 D+n |
| 기념일 화면 행 | 이름, 날짜, 대표 라벨(3-4). 아래 작은 글씨 "다음 {라벨} {M월 D일} D-n" (`ONCE` 이후는 없음). 정렬은 다음 항목 날짜순, 다음이 없는 것은 맨 아래 |
| 추가/수정 시트 | 이름, 날짜, **종류**(세그먼트 3개: 함께한 날 세기 / 매년 반복 / 그날만). 아래 한 줄 설명 "100일, 200일, 1주년이 달력에 자동으로 보여요" 등 종류별 |
| 빈 상태 문구 | "기념일을 등록하면 100일, 1주년이 달력에 자동으로 보여요. 첫 기념일을 추가해 보세요" |

## 5. API와 스키마 (제안, 설계 승인 시 확정)

- 계산은 **웹 순수 함수** (`apps/web/src/lib/anniversary.ts`). 서버는 종류만 저장한다. D-17(기념일 D-day 는 클라이언트) 의 연장
  - 이유: 범위 계산이 화면마다 다르고(42일, 30일, 다음 1개), 서버 계산은 응답을 날짜 범위 쿼리로 바꿔야 한다. 알림이 없어 서버가 날짜를 알아야 할 곳도 없다
  - 테스트: 3-5 예시 표를 웹 단위 테스트(vitest 도입)로. 나중에 푸시 알림으로 서버 계산이 필요해지면 같은 표를 API 테스트로 옮긴다
- 스키마: `enum AnniversaryKind { COUNT_UP YEARLY ONCE }`, `Anniversary.kind AnniversaryKind @default(COUNT_UP)`. 추가형 마이그레이션, 기존 행은 `COUNT_UP` (미결 Q3)
- API: POST `{ name, date, kind? }` (생략 시 `COUNT_UP`), PATCH `{ name?, date?, kind? }`, 응답 `Anniversary` 에 `kind`. 잘못된 값은 400 VALIDATION_FAILED. 새 오류 코드 없음
- 앱(WebView)은 웹을 그대로 띄우므로 별도 작업 없음
